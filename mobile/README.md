# Kin mobile (iOS)

A Capacitor shell that runs **the Hub's own console**. There is no second UI to
keep in step: `mobile/` adds a native iOS project around the console in
`../ui`, and at runtime the app loads the console from the Hub.

That last part is the design decision worth knowing. The console signs in with a
cookie, and a cookie is only first-party when the page came from the origin that
set it. Loading the Hub's URL directly makes the webview that origin, so login,
`/api` calls, and the SSE/long-poll sync all behave exactly as they do in a
browser. A bundled copy of the console still ships inside the app as a starting
point, but the Hub's copy is what runs. (The Electron desktop shell works the
same way.)

## Build it

Set the origin your Hub is reachable at and build. The origin is baked in at
sync time, so the app is per-deployment: rebuild to point it somewhere else.

```bash
cd mobile
KIN_HUB_URL=https://kin.example.com npm run build:ios          # simulator
KIN_HUB_URL=https://kin.example.com npm run build:ios:device   # device (needs a team)
```

`scripts/build-ios.sh` builds the console first, syncs the native project, and
then runs `xcodebuild`. For the device build you need a signing team: open the
project once and set it under *Signing & Capabilities*.

```bash
npm run open     # Xcode, to set signing or run from the IDE
npm run sync     # re-copy web assets + plugins after a console change
```

For a Hub on the LAN over plain http (`kin serve --lan`), pass
`KIN_HUB_URL=http://192.168.1.20:7777`; the config enables cleartext for http
origins so iOS does not block it.

## Notes

- **First build may fail fetching the Swift package.** Xcode resolves
  `capacitor-swift-pm` over git; on a machine where git cannot reach GitHub
  directly, the error names a cache directory that does not exist.
  `scripts/build-ios.sh` seeds that mirror with a plain `git clone --mirror`
  before building, which is what gets past it.
- `ios/App/App/public/` and `ios/App/App/capacitor.config.json` are generated by
  `npm run sync` and are not committed. The latter holds the baked Hub origin.
- The app icon and splash are Capacitor's defaults; replacing them is a separate
  chore.
- Backgrounding the app kills the event stream. On resume the console notices,
  reconnects, and catches up from its cursor — that is the same path a dropped
  network takes, so there is no mobile-specific sync code here.
