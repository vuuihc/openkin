## 现在 → 目标

**Mac（默认窗口 1100×760）**
现在：左边一列是对话列表（带"搜索会话…"），右边一页又是同一批对话（带"搜索对话"）；左栏底部还挂着一块文字导航。
目标：左缘是**区域栏**（对话 / 例行任务 / 设置，⌘1–⌘3，带待批准与未读例程角标）；旁边是唯一的对话列表，层级是**设备 → 项目 → 对话**；再往右是主区。右边是一个对话；没有打开对话时，右边是新建页。右侧面板打开或窗口窄于 1280 时，区域栏收成 64px 图标栏，对话列表让位（标题栏留一个"显示列表"），对话区永远不低于 420px。（2026-11-17，S1/S1b）

**手机（390 宽）**
现在：一页对话列表（"搜索对话"，只有项目 → 对话两层）；点左上角 K，又出来一份同样的列表（"搜索会话…"）。
目标：对话列表保持**设备 → 项目 → 对话**三级；对话列表、例行任务、Agent 运维、设置四个同级入口共用底部导航，可在内容空白区左右滑动切换。每个入口回到自己那一片上次所在的位置——列表带搜索、状态与归档范围，例行任务带选中的机器（`?device=`），设置带打开的 tab（`?tab=`）；Agent 运维的目标落点是 `/settings?tab=operations`。归档是列表内的筛选，不是第五个入口。「新建对话」是列表头里与标题并排的次级按钮，不再是浮在列表上的实心圆。没有 K 抽屉，没有 dock。对话、新建和导入会话都是推入的整页；项目不是页面，项目标题和任务头的项目名都把列表收窄到这一个项目（`?project=<id>`）；返回只有一条路：页头返回、系统返回和左缘右滑都弹回上一层，推入的详情最终回到对话列表（带它上次的搜索 / 状态 / 归档范围），冷启动深链在路由挂载前补上列表父级。导入在 Agent 运维；详情保护不变。（2026-11-16，S2b；2026-11-17，G2）

## 列表层级

唯一的对话列表按三层排：

```
设备（本机 / 另一台机器）
  项目（工作目录）
    对话
```

- 设备名一直显示，单设备也不收起（2026-10-30 改；原规则"只有一台设备时收起"作废，`showMachineLabels` 随之改掉）。
- 左栏现在已经是这个结构；手机列表现在也是这个三层结构（`DeviceSection`，见下表「手机对话列表」行）。
- 归档页和搜索结果是同一份列表的另一种范围，层级相同。
- 例行任务的运行就是一条任务行，不是第二份列表：`routine_id` 非空的行在尾部带「例行」标记并加入行的无障碍名称；`?routine=<id>` 把列表收窄到这一个例行的运行（服务端 `routine_id` 加已加载页的本地收窄，和 `?status=` 同一套规则），此时导入的 agent 会话整组隐藏、不提供手动排序、空结果显示「没有符合筛选的对话」，筛选条上留一枚可清除的「例行运行」chip。
- 手机整页与 Mac 左栏共用同一个列表组件（`SessionList`）：数据、搜索、过滤、排序、折叠、行操作一致，宽度只决定容器和溢出的触发方式（左栏悬停按钮 / 手机滑动与长按；行操作与长按入口归 KIN-MANAGE-001）。项目标题把这份列表收窄到该项目（`?project=<id>`，同一层、不改历史），折叠是它前面的箭头；任务头的项目名落在同一份收窄列表（`?project=<id>`，筛选条上留一枚写着项目名的可清除 chip，清除即回到全量列表、不新增历史条目）。项目行自己还提供一句话摘要和工作目录两个编辑入口（`ProjectSummaryEditor` / `ProjectRootsEditor`）：摘要的粗指针在 `⋯` 表里、细指针在悬停按钮里，工作目录两个指针都有入口（粗指针是 `⋯` 表里的一行、细指针是悬停按钮，打开的是同一个编辑器：粗指针为底部表、细指针为对话框）；保存后列表原地重画，从不跳 `/projects/:id`。项目不是第四个区域（KIN-CONTRACT-001，2026-11-22）：项目层级由这份列表的设备 → 项目 → 对话画出，`/projects` 不再渲染集合，而是重定向到 `/sessions`——书签、通知、⌘K 都落在同一份列表；`/projects/:id` 旧封面 URL 以 `replace` 落到按项目收窄的对话列表（`/sessions?project=<id>`），书签与旧返回层都落到同一份列表。区域表只有三个区域（`ui/src/lib/areas.ts`），每个导航面都读它。
- 项目封面已退役（KIN-CONTRACT-001，2026-11-24）：项目没有自己的页面，最近活动、摘要与工作说明都在列表里这个项目那一行；列表不复制第二份对话列表（2026-11-11，KIN-PROJECT-001 签字的规则沿用）。摘要编辑 One-Pager 的 `Current Focus`，例行任务在 `/routines`；项目记录、摘要、工作说明各自失败、各自保留上次结果（2026-11-11 交付）。
- 导入的 agent 会话不是项目：每台机器末尾单独一组「导入的会话（N）」，默认收起，行与原生对话同形（无彩色 rail、状态点或可用性徽标）；新导入只改计数，不自动展开。行在列表上方打开一张 sheet（agent 与状态、最近三轮、一个 composer），不离开列表；发送即把源会话接到新任务并落到 `/tasks/<id>`，列表留在下面一层（R-agent-preview，2026-11-23）。`/agent-sessions/:id` 旧整页 URL 现在以 `replace` 落到 `/sessions?agent=<id>`：列表不动，该会话的 sheet 开在列表上方，关闭即回到同一份列表并去掉参数（R-agent-retire 5a，2026-11-24；详情页文件已由 5b 删除——#676 先删掉它的两个套件，`ui/src/App.tsx:276` 现在只剩这条重定向，没有任何路由再渲染它）。

## 例行任务（2026-11-09）

例行任务属于机器，不属于 Hub：cwd、agent、凭据和调度都在那台机器上。Hub 只负责鉴权和转发，自己不拥有 routines。

| 面 | 归谁 | 内容 |
|---|---|---|
| 例行任务 `/routines` | 页面上选中的机器（Node） | 顶部选机器；列表、run-now、编辑、删除、已读都发给那台机器。首次打开落在第一台在线的非本机机器，选择会记住 |
| 侧栏「例行任务」角标 | 与 `/routines` 同一台机器 | 未读数跟着页面会打开的那台机器走；机器列表还没到不猜，读失败时保留已存选择 |
| 新建对话 → 存为例行任务 | 同一台机器 | 机器和目录跟着会话的选择走；选远程机器时也允许 |
| 项目的例行任务 | 拥有该项目 cwd 的机器（Node） | 封面退役后列表不列 routine：例行任务只在 `/routines`，按 cwd 匹配机器，`?device=<id>` 带出拥有者。选机器、目录、权限、模型、会话方式与创建都在 `/routines` 内完成。没有其他机器声明该目录时落在本机（单机桌面，或按路径在本机建的项目） |
| 运行详情 `/tasks/:id?device=<device>` | 跑出这次运行的机器（Node） | 从「最近运行」点开的一条只读详情：任务行和 transcript 都向那台机器要。它和本地任务是同一张任务详情页，`?device=` 说明 run 在哪台机器；旧的 `/machines/:device/tasks/:id` 以 `replace` 到达这里。批准、回复、停跑仍在机器自己的 console 上，Hub 不转发这些动作 |

## 一条用户路径（一条故事一条）

- **手机上接着问**：打开 → 找到昨天的对话 → 继续 → 回答弹出的批准。
- **Mac 上接着问**：打开 → 搜到上周的对话 → 继续 → 改模型和权限 → 看 diff；读整条回答时只有一条 ≤44 px header、正文和一个 composer，用量在 composer footer、改动文件在 header 的文件入口，平板的次要动作走既有会话动作表（2026-11-21，KIN-QUALITY-001）。手机上的同一条 header 只有一行：返回 · 标题（超长截断）· 文件 · 「⋯」；运行中与断线不占 header 一行（composer 的停止按钮、正文活动行与 shell 的重连条各自说明），项目 · 分支在那条 header 的「⋯」会话动作表里（同上，D16）。
- **新建一段对话**：任一端 → 新建 → 写提示词、选 agent / 模型 / 权限（卡内）→ 选设备与项目（卡上一条）→ 开始（2026-11-11，KIN-START-001）。
- **找项目或例行任务**：找到项目或例行任务并操作它。

引发这次整理的问题分别落在"Mac 上接着问"（Mac 没变化、还是手机控件）、"手机/Mac 上接着问"（两个列表）、"新建一段对话"（模型选择器）。
