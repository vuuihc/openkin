## 现在 → 目标

**Mac（默认窗口 1100×760）**
现在：左边一列是对话列表（带"搜索会话…"），右边一页又是同一批对话（带"搜索对话"）；左栏底部还挂着一块文字导航。
目标：左边一列是唯一的列表，层级是**设备 → 项目 → 对话**；左栏是一整块——列表在上，导入、归档、设置等收进底部的一行图标，不另开第二块导航面板。右边是一个对话；没有打开对话时，右边是新建页。

**手机（390 宽）**
现在：一页对话列表（"搜索对话"，只有项目 → 对话两层）；点左上角 K，又出来一份同样的列表（"搜索会话…"）。
目标：一页对话列表，层级是**设备 → 项目 → 对话**；点 K 只有入口（导入、Agent 运维、设置）。

## 列表层级

唯一的对话列表按三层排：

```
设备（本机 / 另一台机器）
  项目（工作目录）
    对话
```

- 设备名一直显示，单设备也不收起（2026-10-30 改；原规则"只有一台设备时收起"作废，`showMachineLabels` 随之改掉）。
- 左栏现在已经是这个结构；手机列表现在只有"项目 → 对话"两层，缺设备层。
- 归档页和搜索结果是同一份列表的另一种范围，层级相同。
- 手机整页与 Mac 左栏共用同一个列表组件（`SessionList`）：数据、搜索、过滤、排序、折叠、行操作一致，宽度只决定容器和溢出的触发方式（左栏悬停按钮 / 手机滑动与长按）。项目标题是项目封面（`/projects/:id`）的入口，折叠是它前面的箭头；`/projects` 索引页已删，手机 dock 不再有「项目」（2026-11-10，R0b-2d）。
- 项目封面没有「对话」tab：概览的最近活动只放最近一段对话的入口，更早的对话回列表按项目找；封面不复制第二份对话列表（2026-11-11，KIN-PROJECT-001 签字）。摘要编辑 One-Pager 的 `Current Focus`，热力图固定两周，例行任务只读并链到 `/routines`；项目记录、摘要、pulse、活动、例行任务各自失败、各自保留上次结果（2026-11-11 交付）。
- 导入的 agent 会话不是项目：每台机器末尾单独一组「导入的会话（N）」，默认收起，行与原生对话同形（无彩色 rail、状态点或可用性徽标）；新导入只改计数，不自动展开。详情页的头部也只保留标题与来源行，来源 ID 放进时间戳那一行（R0b-2c，2026-11-10）。

## 通知（KIN-NOTIFY-001，已签 2026-11-02）

通知不是第三个列表。**待批准属于它所在的那条对话**：对话列表的行尾带计数，原生通知只负责把人带到那段对话，并让被点名的卡片获得焦点（R0b-2，2026-11-10）。

| 面 | 归谁 | 内容 |
|---|---|---|
| 系统设置（macOS / iOS） | 这台设备 | 通知权限与开关；控制台不再有「设置 → 通知」面，iPhone 首次授权保留「设置 → 通用」的一行入口（2026-11-11，R0b-3） |
| 系统通知中心 | macOS / iOS | 标题是对话标题，正文说清批准、提问、跑完、失败、额度或例行报告；点开落到那一条 |

- 原生是 Mac / iPhone 的唯一通道；Bark / ntfy / Web Push 在这一条删除，升级时清理旧配置，不保留回退开关。浏览器控制台和 Android 不再收到 Kin 通知；如果以后要，另开故事。控制台只负责送达与落点：不提供设备列表、测试推送或按事件开关；唯一的控件是 iPhone 未授权时「设置 → 通用」的一行入口（iOS 不请求过一次就不会出现在系统通知设置里），已授权的手机每次启动自动重登记。
- 通知的触发条件、文案语义沿用；落点随 R0b-2 从收件箱改到对话（`/tasks/<id>?focus=<item>`）。
- 发送成功不等于用户看到；通知丢了，对话行上的计数仍然在。

## 例行任务（2026-11-09）

例行任务属于机器，不属于 Hub：cwd、agent、凭据和调度都在那台机器上。Hub 只负责鉴权和转发，自己不拥有 routines。

| 面 | 归谁 | 内容 |
|---|---|---|
| 例行任务 `/routines` | 页面上选中的机器（Node） | 顶部选机器；列表、run-now、编辑、删除、已读都发给那台机器。首次打开落在第一台在线的非本机机器，选择会记住 |
| 侧栏「例行任务」角标 | 与 `/routines` 同一台机器 | 未读数跟着页面会打开的那台机器走；机器列表还没到不猜，读失败时保留已存选择 |
| 新建对话 → 存为例行任务 | 同一台机器 | 机器和目录跟着会话的选择走；选远程机器时也允许 |
| 项目页的例行任务 | Hub（遗留） | 项目是 Hub 侧按 cwd 建立的记录，节点不认识它；这块仍是本机，待后续按 cwd 找机器上的 routine 或收掉 |
| 例行任务的会话 | 任务所属项目 | `/routines` 只保留运行记录（时间、结果、耗时），不内嵌或复制会话。会话默认在同一条里面持续；每条任务可选「每次执行在对应项目新建会话」（2026-11-11，KIN-ROUTINE-001 签字） |

## 设置与环境（KIN-SETTINGS-002，2026-11-09）

设置不是一张页面，是「环境」的几块：运行默认值归控制台，桌面壳自己的版本归托盘。谁拥有什么，以面为单位：

| 面 | 归谁 | 内容 |
|---|---|---|
| 控制台设置 `/settings` | Hub | Agent、模型、权限等运行默认值（KIN-SETTINGS-001 的面）；远程 / 通知两个 tab 已于 2026-11-11（R0b-3）删除，relay / APNs 仍是 daemon API；通知只保留 iPhone 首次授权的一行 |
| 菜单栏托盘（Mac） | 桌面壳 | 常驻版本行「Kin X」；检查更新、下载（进度）、安装（open dmg + 确认退出）、删除已下载的安装包；只连 github.com 官方 Releases，不做后台轮询 |
| 手机 | 无此面 | PWA 由 Hub 重新部署时自然更新；手机上没有桌面壳的升级问题 |

- Agent 目录最多 10 个产品（同一产品的 native / ACP / CLI 只算一个）；发现新 agent 不自动接入，必须由用户确认；接入不导入历史会话，会话只在用户手动导入时进来（2026-11-11，KIN-AGENTS-001 签字）。交付：目录按浏览器保存，发现区只列可托管且已安装的产品，Mac 表格对齐帧的 9 列（2026-11-11 交付）。
- 桌面壳的更新是壳的事：Hub 不认识壳，控制台 SPA 里永远不出现升级入口。
- app 未签名，升级的终点是挂载 dmg + 拖装覆盖；静默自升级不做（见该故事 D1，已定）。

## 一条用户路径（一条故事一条）

- **手机上接着问**：打开 → 找到昨天的对话 → 继续 → 回答弹出的批准。
- **Mac 上接着问**：打开 → 搜到上周的对话 → 继续 → 改模型和权限 → 看 diff。
- **新建一段对话**：任一端 → 新建 → 写提示词、选 agent / 模型 / 权限（卡内）→ 选设备与项目（卡下一条）→ 开始（2026-11-11，KIN-START-001）。
- **找项目或例行任务**：找到项目或例行任务并操作它。

引发这次整理的问题分别落在"Mac 上接着问"（Mac 没变化、还是手机控件）、"手机/Mac 上接着问"（两个列表）、"新建一段对话"（模型选择器）。
