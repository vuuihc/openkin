## 现在 → 目标

**Mac（默认窗口 1100×760）**
现在：左边一列是对话列表（带"搜索会话…"），右边一页又是同一批对话（带"搜索对话"）；左栏底部还挂着一块文字导航。
目标：左边一列是唯一的列表，层级是**设备 → 项目 → 对话**；左栏是一整块——列表在上，导入、归档、设置等收进底部的一行图标，不另开第二块导航面板。右边是一个对话；没有打开对话时，右边是新建页。

**手机（390 宽）**
现在：一页对话列表（"搜索对话"，只有项目 → 对话两层）；点左上角 K，又出来一份同样的列表（"搜索会话…"）。
目标：一页对话列表，层级是**设备 → 项目 → 对话**；点 K 只有入口（导入、产物库、Agent 运维、设置）。

## 列表层级

唯一的对话列表按三层排：

```
设备（本机 / 另一台机器）
  项目（工作目录）

```

- 设备名一直显示，单设备也不收起（2026-10-30 改；原规则"只有一台设备时收起"作废，`showMachineLabels` 随之改掉）。
- 左栏现在已经是这个结构；手机列表现在只有"项目 → 对话"两层，缺设备层。
- 归档页和搜索结果是同一份列表的另一种范围，层级相同。

## 通知（KIN-NOTIFY-001，已签 2026-11-02）

通知不是第三个列表。**收件箱仍是唯一列出"等你处理"的地方**；原生通知只负责把人带到那一条，点开后落在收件箱的那张卡片或那段对话。

| 面 | 归谁 | 内容 |
|---|---|---|
| 设置 → 通知 | 这台设备 | Mac 显示"这台 Mac"，iPhone 显示"这台 iPhone"：系统权限、启用/关闭、发送测试、打开系统设置。第一块是这台设备，不再有浏览器推送 / Bark / ntfy 区块 |
| 设置 → 通知（浏览器控制台） | 浏览器 | 不显示启用或测试，只说明通知在 Mac / iPhone 原生应用里 |
| 系统通知中心 | macOS / iOS | 标题是对话标题，正文说清批准、提问、跑完、失败、额度或例行报告；点开落到那一条 |

- 原生是 Mac / iPhone 的唯一通道；Bark / ntfy / Web Push 在这一条删除，升级时清理旧配置，不保留回退开关。浏览器控制台和 Android 不再收到 Kin 通知；如果以后要，另开故事。
- 通知的触发条件、文案语义和收件箱路由沿用今天的行为；这一条只改送达通道和落点。
- 发送成功不等于用户看到；通知丢了，收件箱仍然有那一条。
- 例行报告/禁用告警的落点：在 Node 上跑出的例行任务，点通知落到那台机器的运行详情 `/machines/:device/tasks/:id`；电路熔断禁用告警落到 `/routines?device=<id>`（ADR 0030）。例行任务仍在机器上，Hub 只把告警扇出到它自己登记的手机。

## 例行任务（2026-11-09）

例行任务属于机器，不属于 Hub：cwd、agent、凭据和调度都在那台机器上。Hub 只负责鉴权和转发，自己不拥有 routines。

| 面 | 归谁 | 内容 |
|---|---|---|
| 例行任务 `/routines` | 页面上选中的机器（Node） | 顶部选机器；列表、run-now、编辑、删除、已读都发给那台机器。首次打开落在第一台在线的非本机机器，选择会记住 |
| 侧栏「例行任务」角标 | 与 `/routines` 同一台机器 | 未读数跟着页面会打开的那台机器走；机器列表还没到不猜，读失败时保留已存选择 |
| 新建对话 → 存为例行任务 | 同一台机器 | 机器和目录跟着会话的选择走；选远程机器时也允许 |
| 项目页的例行任务 | 拥有该项目 cwd 的机器（Node） | 项目是 Hub 侧按 cwd 建立的记录；页面拿 cwd 匹配机器声明的目录，列表、计数和创建都发给那台机器，并按 cwd 归属 routine。没有其他机器声明该目录时落在本机（单机桌面，或按路径在本机建的项目） |
| 运行详情 `/machines/:device/tasks/:id` | 跑出这次运行的机器（Node） | 从「最近运行」点开的一条只读详情：任务行和 transcript 都向那台机器要。批准、回复、停跑仍在机器自己的 console 上，Hub 不转发这些动作 |
| 例行报告通知落点 | 跑出这次运行的机器（Node） | 点例行报告通知落到 `/machines/:device/tasks/:id`；电路熔断禁用告警落到 `/routines?device=<id>` 并预选那台机器（ADR 0030） |

## 设置与环境（KIN-SETTINGS-002，2026-11-09）

设置不是一张页面，是「环境」的几块：运行默认值归控制台，桌面壳自己的版本归托盘。谁拥有什么，以面为单位：

| 面 | 归谁 | 内容 |
|---|---|---|
| 控制台设置 `/settings` | Hub | Agent、模型、权限等运行默认值（KIN-SETTINGS-001 的面） |
| 菜单栏托盘（Mac） | 桌面壳 | 常驻版本行「Kin X」；检查更新、下载（进度）、安装（open dmg + 确认退出）、删除已下载的安装包；只连 github.com 官方 Releases，不做后台轮询 |
| 手机 | 无此面 | PWA 由 Hub 重新部署时自然更新；手机上没有桌面壳的升级问题 |

- 桌面壳的更新是壳的事：Hub 不认识壳，控制台 SPA 里永远不出现升级入口。
- app 未签名，升级的终点是挂载 dmg + 拖装覆盖；静默自升级不做（见该故事 D1，已定）。

## 一条用户路径（一条故事一条）

- **手机上接着问**：打开 → 找到昨天的对话 → 继续 → 回答弹出的批准。
- **Mac 上接着问**：打开 → 搜到上周的对话 → 继续 → 改模型和权限 → 看 diff。
- **新建一段对话**：任一端 → 新建 → 选 agent、模型、权限 → 发送。
- **找产物**：找到产物、项目或例行任务并操作它。

引发这次整理的问题分别落在"Mac 上接着问"（Mac 没变化、还是手机控件）、"手机/Mac 上接着问"（两个列表）、"新建一段对话"（模型选择器）。
