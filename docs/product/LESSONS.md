# 教训台账（LESSONS）

规则不是开会想出来的，是从"又被修了一次"的地方长出来的。做法抄自 Magpie 的
`LESSONS.md`（本地参考副本 `~/Workspace/works/magpie/LESSONS.md`）：每条先记事实和证据，
同一模式累计到第三次才升级成通用规则。

## 什么时候写

- 每次交付自审、review、dogfood、用户反馈里发现的缺陷。
- 只写"本来可以拦住但没拦住"的，不写一次性的手滑。

## 格式

```
## YYYY-MM-DD · <一句话规则>
seen: <第几次出现>

发生了什么：
为什么没拦住：
规则：
证据：<commit>
```

## 怎么升级

- `seen` 到 3 → 写进 `TASTE.md` 的编号规则或 `AGENTS.md` 的硬规定，并补一个能复现的测试。
- 没满三次的 → 写进相关故事的 `Do not`，不升级。

## 2026-10-30 · 点击在 jsdom 里到不了按钮
seen: 1

发生了什么：`SwipeReveal` 在 `pointerdown` 就 capture 指针，tap 的 `click` 被重定向到包装层，
行打不开，pin / archive / delete 全都不响。DOM 结构对，组件测试全绿。

为什么没拦住：jsdom 不重定向点击，只有真浏览器会。测试测的是"元素在"，不是"点得到"。

规则：任何"手指点一下"的行为，除了组件测试，必须在真浏览器里点一次；故事的验收表里写一条
`/browse` 检查，写清点什么、看到什么。

证据：`f3c43ba9`

## 2026-10-30 · 快捷键属于最靠近它的那个面
seen: 4

发生了什么：① `ChatStream` 把 ⌘F 绑在 window 上，抢在 Monaco 前面（`c0f1fa57`）；
② 文件面板盖住对话后，对话仍然占着 ⌘F，焦点跑进看不见的输入框（`239a2dab`）；
③ 菜单、第二层、文件面板盖住对话时，对话仍响应 j/k/a/d（`d9026cd5`）；
④ 页面同时挂着多条缓存的对话，⌘F 按"文档里第一个 pane"判断归属，被隐藏的那条抢走键
（`d9026cd5`）。

为什么没拦住：两处都只测了"能打开"，没测"盖住时不该打开"；④还把"存在"当成了"当前"。

规则：覆盖层出现时，被盖住的面的快捷键、焦点、滚动全部让位；快捷键归属看光标在哪一层，
不看文档里谁先出现；测试同时断言该开的开、该关的关，而不是只测前者。

证据：`c0f1fa57`、`239a2dab`、`d9026cd5`

## 2026-10-30 · 给用户看的错误只能是提供方自己的话
seen: 1

发生了什么：提供方网关挂了，任务里存下 300 字节 Cloudflare HTML 错误页。这段文本写进对话、
推到手机、分享给别人的页面，却什么也没说明。

为什么没拦住：只看状态码和 hint，没有断言错误文本本身的内容。

规则：写进对话、推送、分享的文本必须是提供方可读的消息；HTML 页面一律丢弃，只取 `<title>`
兜底；测试用真实 HTML 错误页做输入。

证据：`fff2c11d`

## 2026-10-31 · 一次性焦点标记要在落点消费
seen: 1

发生了什么：从会话返回列表时，为了把焦点放回原来那一行，页面在每次列表更新时重放标记。
标记被聚焦后没有清掉，之后任何一次打字或实时更新都会把光标从搜索框抢回那一行
（KIN-CONTINUE-001 五轮复审）。

为什么没拦住：测试只证明"返回后焦点在那一行"，没测"落点之后不再抢"。

规则：一次性的焦点/滚动标记，聚焦成功当场消费；测试必须包含"落点之后再触发一次更新，焦点不动"。

证据：`d9026cd5`

## 2026-10-31 · 弹出层的焦点要等它真的挂载
seen: 1

发生了什么：运行设置、权限菜单、小选择器三处都在打开那一帧的 effect 里找选项并聚焦，
但浮层是测量之后才 portal 出来的，effect 跑时 DOM 里还没有选项，焦点留在触发按钮上
（KIN-CONTINUE-001 四、五轮复审）。

为什么没拦住：三处各写了一遍同样的 effect，测试都在"打开后"断言，没覆盖挂载时序。

规则：portal 浮层的焦点 effect 以"测量到的 anchor 存在"为 key，不以 `open` 为 key；
三处各有回归测试。

证据：`d9026cd5`（`SheetSelect.dom.test.tsx`、`PermissionModePicker.dom.test.tsx`、
`RunConfigSheet.dom.test.tsx`）

## 2026-10-31 · 测试只证明元素在，不证明行为发生
seen: 2

发生了什么：① 手机小选择器的测试只断言 `ion-action-sheet` 宿主存在，而 Ionic 关着也挂宿主，
点击完全没反应测试也是绿的（`d9026cd5`）；② 返回行、覆盖层快捷键也出现同类浅断言，
复审逐个打回（`d9026cd5`）。

为什么没拦住：把"渲染出来了"当成了"发生了"。

规则：交互测试断言状态变化（`aria-expanded`、焦点位置、选项出现），不断言宿主或容器存在；
送审前先用 mutant 证明测试会红。

证据：`d9026cd5`

## 2026-11-04 · 验收探针只能把本次受邀回合自己的输出算作证据
seen: 1

发生了什么：W4 的 step 4 用探针 prompt 的回显就能满足 live text 断言，按片段做的过滤又被拆开的回显
绕过，第四轮复审才发现（`f2fe9bfd`）。W4b 的 step 5 连续四轮各被找出一个新的伪通过口：审批列表读不
出来也记 skip，没有 tool 证据的回合也记 skip，上一回合的 tool_use 也能顶替，空基线让整份日志都像本回合
（`f4eb8774`、`891a7beb`、`0d01b702`、`f21c297c`）。五次复审、mutant 从 15 加到 28 才收敛。

为什么没拦住：判 pass/skip 时只看"有没有出现某个信号"，没有先问"这个信号是不是这次邀请产生的"；
基线不可读、为空、身份重复时又选了 skip 而不是失败。

规则：验收探针判一步通过前，先把探针自己的输入（prompt 回显）、历史回合和上一次基线从证据里剔除；
只接受基线之后、属于本次受邀回合的输出；基线不可读、为空或身份重复时失败，不跳过；每个伪通过口
配一个负向用例和一个 mutant。

证据：`f2fe9bfd`、`f4eb8774`、`891a7beb`、`0d01b702`、`f21c297c`（2026-11-02）

## 2026-11-04 · 改到 iOS 壳层就在合并前编译一次 Release
seen: 1

发生了什么：`cf556915` 新增的 `KinPushState` / `KinNativePushPlugin`（397 行 Swift）把
`Result<String, String>` 当 `Result.Failure` 用；Swift 要求 Failure 满足 `Error`，这个 target 根本
编译不过。第二天 `92027ed7` 才包出 `KinPushError`，并注明用 Release archive 加导出 IPA 验证；
main 上的 iOS 壳层有半天多不能编译。

为什么没拦住：同一次提交的 Go 测试、Vitest、`tsc` 都不编译 Swift；`scripts/check.sh` 和 CI 也没有
iOS 构建这一步，绿色 gate 只证明了别的平台。

规则：改动 `mobile/ios/`（或任何原生壳层）时，合并前至少跑一次该平台的 Release 编译/归档；JS、Go
与单元测试不能替代平台构建；提交正文写出实际跑过的构建命令与产物。

证据：`92027ed7`（2026-11-04，修复 `cf556915`，2026-11-03）

seen: 1

发生了什么：W4 新增 `probe/kin-probe-w4` 后，`scripts/check.sh` 的 probe job 仍只跑
`probe/kin-probe`；`4893e668` 把变更检测放宽到任意 `probe/*`，但执行清单还是写死的两个模块。

check.sh 的 probe 阶段只覆盖两个旧模块，新模块的 gofmt/vet/race 是手工跑的。

为什么没拦住：nested Go module 不在根 `go test ./...` 里；改 `changed_probe_files` 只决定"要不要跑"，
不决定"跑哪些"。gate 绿了，但新模块一次都没跑。

规则：新增 nested module、独立 probe 目录或新 workspace 包时，在同一个提交里把它加进
`scripts/check.sh` 的执行清单（不是只改变更检测的 glob），并让 gate 的输出能看出它跑过。

证据：`4893e668`、`213a5683`（2026-11-02）

## 评审复盘与协议

KIN-CONTINUE-001 审了五轮才过。事实：77 个文件、+5025/−1335（源码 +2836、测试 +2099），
后端只有约 40 行——耗时不在后端，也不在"删列表"。五轮各自发现的是新问题，不是同一个改五遍：
① 行为缺口（切走留白、覆盖层抢快捷键、过期当拒绝）；② 判定错误（关着的 Ionic 宿主被当成覆盖层、
引擎自动拒绝被说成"在这里决定"）；③ 契约漂移（Mac 归档地址、冷启动恢复、第二层 Tab/返回、渠道文案）；
④ 焦点竞态（返回行标记不消费、⌘F 按第一个 pane 判断）；⑤ 只验 delta，1.4 分钟结束。

它慢在四个可改的地方：

1. **按全量 diff 通读，没有按风险面清单逐项过。** 5k 行一次通读只能覆盖一部分，剩下的下一轮才撞见。
2. **修完一小批就重审全量。** 不是"一次修完，再只验 delta"。
3. **测试太浅，复审在替测试干活。** 手机面板测试证明"宿主在"，不证明"打开了"。
4. **送审时树是动的。** 未暂存、`web/dist` 过期，复审要花精力分辨"审的是什么"。

### 协议（下一条故事照做，目标 2–3 轮）

1. **送审前**：按下面的风险面清单自查一遍；每条新行为跑一个 mutant，证明测试会红；
   全量 stage；重建 `web/dist`；告诉复审者"工作树只读，只出报告不改代码"。
2. **第 1 轮**：全量 diff + 相关调用点，一次性列出全部发现，按 blocker/major/nit 分级。
3. **一次修完**（含 nit）→ **第 2 轮只验 delta** 和对应不变量，不再重读全量。
4. 第 2 轮若冒出"改前就存在"的 major，先补风险面清单，不算流程失败。

### 风险面清单（按故事取用）

键盘归属（⌘F/Esc/方向键/j/k/a/d）· 焦点（挂载时序、返回行、弹层内）· 历史（push/back/关闭/深链）·
两种宽度一致性 · 空/慢/错/断线 · i18n 双语言 · 生成物（`web/dist/index.html` 与 chunk）·
无障碍名字与状态（`aria-expanded`、`aria-checked`）。

### 复审指令模板

> 审查这份 diff 与相关调用点。按风险面清单逐项过：<清单>。一次性列出全部发现，按
> blocker/major/nit 分级，不改代码；指出哪些测试会在行为回退时变红。工作树只读。
