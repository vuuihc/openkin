# 教训台账（LESSONS）

规则不是开会想出来的，是从"又被修了一次"的地方长出来的。做法抄自 Magpie 的
`LESSONS.md`（本地参考副本 `~/Workspace/works/magpie/LESSONS.md`）：每条先记事实和证据，
同一模式累计到第三次才升级成通用规则。

## 什么时候写

- 每次交付自审、review、dogfood、用户反馈里发现的缺陷。
- 只写"本来可以拦住但没拦住"的，不写一次性的手滑。

## 格式

```
## YYYY-MM-DD · <一句话规则>
seen: <第几次出现>

发生了什么：
为什么没拦住：
规则：
证据：<commit>
```

## 怎么升级

- `seen` 到 3 → 写进 `TASTE.md` 的编号规则或 `AGENTS.md` 的硬规定，并补一个能复现的测试。
- 没满三次的 → 写进相关故事的 `Do not`，不升级。

## 2026-10-30 · 点击在 jsdom 里到不了按钮
seen: 1

发生了什么：`SwipeReveal` 在 `pointerdown` 就 capture 指针，tap 的 `click` 被重定向到包装层，
行打不开，pin / archive / delete 全都不响。DOM 结构对，组件测试全绿。

为什么没拦住：jsdom 不重定向点击，只有真浏览器会。测试测的是"元素在"，不是"点得到"。

规则：任何"手指点一下"的行为，除了组件测试，必须在真浏览器里点一次；故事的验收表里写一条
`/browse` 检查，写清点什么、看到什么。

证据：`f3c43ba9`

## 2026-10-30 · 快捷键属于最靠近它的那个面
seen: 4

发生了什么：① `ChatStream` 把 ⌘F 绑在 window 上，抢在 Monaco 前面（`c0f1fa57`）；
② 文件面板盖住对话后，对话仍然占着 ⌘F，焦点跑进看不见的输入框（`239a2dab`）；
③ 菜单、第二层、文件面板盖住对话时，对话仍响应 j/k/a/d（`d9026cd5`）；
④ 页面同时挂着多条缓存的对话，⌘F 按"文档里第一个 pane"判断归属，被隐藏的那条抢走键
（`d9026cd5`）。

为什么没拦住：两处都只测了"能打开"，没测"盖住时不该打开"；④还把"存在"当成了"当前"。

规则：覆盖层出现时，被盖住的面的快捷键、焦点、滚动全部让位；快捷键归属看光标在哪一层，
不看文档里谁先出现；测试同时断言该开的开、该关的关，而不是只测前者。

证据：`c0f1fa57`、`239a2dab`、`d9026cd5`

## 2026-10-30 · 给用户看的错误只能是提供方自己的话

## 2026-10-31 · 一次性焦点标记要在落点消费

## 2026-10-31 · 测试只证明元素在，不证明行为发生
seen: 2

发生了什么：① 手机小选择器的测试只断言 `ion-action-sheet` 宿主存在，而 Ionic 关着也挂宿主，

## 2026-11-04 · 验收探针只能把本次受邀回合自己的输出算作证据
seen: 1

发生了什么：W4 的 step 4 用探针 prompt 的回显就能满足 live text 断言，按片段做的过滤又被拆开的回显
绕过，第四轮复审才发现（`f2fe9bfd`）。W4b 的 step 5 连续四轮各被找出一个新的伪通过口：审批列表读不
出来也记 skip，没有 tool 证据的回合也记 skip，上一回合的 tool_use 也能顶替，空基线让整份日志都像本回合
（`f4eb8774`、`891a7beb`、`0d01b702`、`f21c297c`）。五次复审、mutant 从 15 加到 28 才收敛。

为什么没拦住：判 pass/skip 时只看"有没有出现某个信号"，没有先问"这个信号是不是这次邀请产生的"；
基线不可读、为空、身份重复时又选了 skip 而不是失败。

规则：验收探针判一步通过前，先把探针自己的输入（prompt 回显）、历史回合和上一次基线从证据里剔除；
只接受基线之后、属于本次受邀回合的输出；基线不可读、为空或身份重复时失败，不跳过；每个伪通过口
配一个负向用例和一个 mutant。

证据：`f2fe9bfd`、`f4eb8774`、`891a7beb`、`0d01b702`、`f21c297c`（2026-11-02）

## 2026-11-04 · 改到 iOS 壳层就在合并前编译一次 Release
seen: 1

发生了什么：`cf556915` 新增的 `KinPushState` / `KinNativePushPlugin`（397 行 Swift）把
`Result<String, String>` 当 `Result.Failure` 用；Swift 要求 Failure 满足 `Error`，这个 target 根本
编译不过。第二天 `92027ed7` 才包出 `KinPushError`，并注明用 Release archive 加导出 IPA 验证；
main 上的 iOS 壳层有半天多不能编译。

为什么没拦住：同一次提交的 Go 测试、Vitest、`tsc` 都不编译 Swift；`scripts/check.sh` 和 CI 也没有
iOS 构建这一步，绿色 gate 只证明了别的平台。

规则：改动 `mobile/ios/`（或任何原生壳层）时，合并前至少跑一次该平台的 Release 编译/归档；JS、Go
与单元测试不能替代平台构建；提交正文写出实际跑过的构建命令与产物。

证据：`92027ed7`（2026-11-04，修复 `cf556915`，2026-11-03）

## 2026-11-05 · 新增凭证表要在同一个提交里进导出排除清单
seen: 2

发生了什么：导出按“排除清单”工作，清单外的表整表写成 JSONL。`auth_sessions`、`user_identities`、
`bootstrap_tokens`（2026-10-22，`f4366b82`）、`invite_tokens`（2026-10-26，`bd7f010c`）、
`login_tokens`（2026-11-03，`a9a2fabe`）陆续落库，却都没进 `excludedExportTables`；备份因此带着
可重放的会话 hash、密码 hash 和未花掉的一次性 token。2026-11-04 新增 `login_codes`（`5a00281d`）
时又漏了一次，14 分钟后才由 `f446fcae` 把六张表一起补上并加红测。旧测试只断言当时已知的
`device_credentials` 和 `push_devices`，新长出来的凭证表从未进入断言，清单漏项时一直是绿的。
2026-11-05 再次出现：restore 只清快照表，目标库自己的 login/device/pairing 凭证未被清掉；旧测试只断言源库的 `auth_sessions` 没被带过来（`726eb318`）。

为什么没拦住：导出是“默认导出、按表排除”，排除清单是一条需要人记得更新的旁路；测试又只覆盖
一个已知凭证表，新表加入时既不报错也不变红。凭证表是随账号、邀请、登录链接逐步长出来的，每次
改动都像局部功能，没人回头看导出。这和第 9 条 gate 模块清单是同一个形状：新增的东西不登记，
旁路仍然全绿。

规则：任何新表只要存 token、hash、secret 或一次性凭证，在同一个提交里加入
`excludedExportTables`，并让导出测试遍历所有这类表（或按表清单断言），不只断言某一个例子；
评审导出改动时先问“这张表被备份带走后能不能直接认证或兑换”。

证据：`f446fcae`（2026-11-04，修复 `f4366b82`、`bd7f010c`、`a9a2fabe`、`5a00281d` 引入的泄漏）

## 2026-11-05 · 绑定密钥只存服务端，不让它经过浏览器或提供方往返
seen: 1

发生了什么：G9 的设备绑定把 `device_key` 拼在提供方授权 URL 上，指望提供方在回调里原样带回；回调 URL 于是带着“证明这台设备发起流程”的值穿过系统浏览器。任何看到回跳地址的人都能在 app 兑换前拿它去兑换，绑定形同虚设。`726eb318` 把 key 记进服务端 pending 流程，成功回调只带一次性 code，错误回调才带 key 用于归属。

为什么没拦住：代码注释把“提供方会回显”当成了“流程由这台设备发起”，测试覆盖了完整往返、设备绑定和重放拒绝，却没有断言“回调 URL 里没有绑定值”；功能测试证明绑定能用，没证明绑定值不可见。

规则：绑定值在发起时写进服务端 pending 状态，只出现在 start URL；成功回调只带一次性 code；测试要断言回调 URL 不含绑定值，并用一个带别人 key 的回调证明兑换失败。

证据：`726eb318`（2026-11-05，修复 `5a00281d`，2026-11-04）

## 2026-11-05 · 改原生壳层配置后，在模拟器里冷启动走一次真实路径
seen: 1

发生了什么：G8 把运行时 Hub URL 写进 `capacitor.config.ts`，却把 `allowNavigation: ["*"]` 放在顶层；Capacitor 只读 `server.allowNavigation`，顶层这个键被静默忽略，运行时 Hub 根本加载不出来。`834cef3f` 把导航策略收进 `KinHubConfigPlugin.shouldOverrideLoad`，只允许已保存的 Hub 源、构建期源和内置 console，并补上 http 确认与 `NSAllowsLocalNetworking`。

为什么没拦住：顶层 `allowNavigation` 是合法 TypeScript，`tsc`、构建和单测都不会报错；测试测的是 `setHubUrl` 被调用，不是 webview 真的导航到了那个源。把“配置写下了”当成“框架读到了”。

规则：改 `mobile/capacitor.config.ts`、原生插件或任何壳层配置后，必须在模拟器里冷启动，输入或深链一个运行时 Hub URL，确认 webview 真的导航过去、返回键和外部链接也按预期走；编译和 `tsc` 通过不算验证。

证据：`834cef3f`（2026-11-05，修复 `5a00281d`，2026-11-04）

## 2026-11-05 · 异步回调按发起流程归属，不属于本流程的回调不能结束它
seen: 1

发生了什么：手机登录用一个全局 pending 流程轮询 `kin://auth-callback`。旧逻辑把任何回调都当成“某个流程结束了”，于是第二个并发登录的错误回调清掉了仍在等自己浏览器的那个流程，界面只剩一个不会再回来的等待。`a2a61343` 改成按 `device_key` 归属：别人的错误回调消费掉但本流程继续轮询，无归属的成功只由唯一 pending 流程认领。

为什么没拦住：测试一次只跑一个流程，没覆盖“两个流程同时在等”的时序；代码注释还把“任何回调都结束一个流程”写成了刻意设计，评审时看起来像是合理的清理。

规则：异步回调必须带发起时生成的流程 id，只结束 id 相同的流程；不属于本流程的回调可以消费但不能清当前状态；测试至少覆盖两个并发流程，其中一个失败不影响另一个。

证据：`a2a61343`（2026-11-05，修复 `5a00281d`，2026-11-04）

## 2026-11-07 · 连接断了不等于工作结束
seen: 1

发生了什么：Node 与 Hub 的 WebSocket 抖动一次，在途 turn 被三条路径同时杀死：Hub 立刻让被顶替连接上的每个 turn 失败，Node 因 dispatch context 来自 socket 而取消 agent，断线后写入的帧被直接丢弃。在手机 → Hub → Mac 这种经常抖动的链路上，用户看到 “device ... disconnected mid-turn”，而 agent 还在跑，已经写出的半段 transcript 也接不上（`2d9d7ec4`）。16 天前 `ac342468` 把 turn 绑在派发它的连接上，这个结局就写死了。

为什么没拦住：既有测试只覆盖“连接正常时 turn 能跑完”，没有一条在 turn 进行中拔掉 socket；`connections.go` 的注释还把“turn 的生命周期来自连接”写成刻意设计，评审时读起来自洽。三条杀死路径任何一条单独存在都足以丢一次运行，但没有一条被断言过。

规则：断线只把在途工作标成 orphan，给一个有界的重连宽限（60s）；重连第一帧 `turn.resume` 列出本机还持有的 turn，认领的迁到新连接，没列出的立刻失败，宽限到期仍未认领的才结束。断线期间的帧进有界 outbox，重连后先 resume、再重放、再排空；重复的 start ack 是幂等 no-op；outbox 溢出时用真实原因结束受影响的 turn，不无声丢弃。必须有一个真拔 websocket、进程仍活着的端到端测试，断言任务仍成功且 transcript 连续。

证据：`2d9d7ec4`（2026-11-07，修复 `ac342468`，2026-10-22）

## 2026-11-07 · 长任务的 ctx 必须由守护进程持有
seen: 1

发生了什么：`internal/server/node.go` 的 `OnFrame: func(ctx context.Context, frame worker.Frame)` 用同名参数遮住了外层的守护进程 ctx，`executor.Handle(ctx, frame)` 实际拿到的是连接 ctx；控制通道一断，agent 就被 cancel，turn 跟着结束（`2d9d7ec4`）。同一个提交把 e2e harness 从 `OnFrame: executor.Handle` 改成包一层、显式传守护进程 ctx：方法值会把连接 ctx 原样递进执行器，与出 bug 的生产接线恰好一致，修复后又会自己取消 agent，让“拔 socket”的测试红在 harness 上。

为什么没拦住：两个 ctx 类型相同，同名遮蔽完全合法，编译器没有信号；`go vet` 的 shadow 分析默认不在检查集里；测试替身用方法值装配，复制了生产里那个错误的接线，而不是走生产的组合根，于是它既抓不到 bug，也验证不了修复。

规则：长任务的取消信号只从守护进程的 ctx 来，用显式名字（`daemonCtx`/`runCtx`）传，回调参数不叫 `ctx`；e2e 测试必须调用生产组合根里的同一段闭包，不用方法值另抄一份等价装配；用“连接断开、进程还在”的测试证明 agent 没被取消。

证据：`2d9d7ec4`（2026-11-07）

## 2026-11-07 · 浮层按实测视口摆放，390px 下逐个验证
seen: 1

发生了什么：dogfooding 记下三处控制台缺口，其中两处是浮层几何：同一个输入框工具栏里的 Agent、模型、权限模式选择器展开方向不一致，窄屏下面板贴边或被裁；消息上的分享入口气泡向左展开，超出视口后右侧内容看不全也点不到（`a9662bde`，issue #1、#3）。到 HEAD 为止两处都还没修。

为什么没拦住：jsdom 不做布局，现有 DOM 测试只断言面板出现、焦点落位，仓库里没有一条按 390px 视口断言几何的用例；同一工具栏的浮层还分属两套测量实现——`SearchSelect` 在 640px 以下换成 `Sheet`，`PermissionModePicker` 始终弹一个 288px 的 `useAnchoredPanel` 浮层，两套各自设翻转阈值、宽度上限和最大高度，宽屏下看不出差别。

规则：同一区域的浮层只允许一套 placement：按实测视口空间决定向上或向下，左右夹到视口内，最大高度取可用空间；窄屏该换 Sheet 就统一换，不让同一工具栏一半 Sheet 一半浮层。新增浮层复用现有测量逻辑；交付前在 390px 宽的真浏览器里逐个打开，确认内容完整可见、可点、可关闭且无横向滚动。

证据：`a9662bde`（2026-11-07）

## 评审复盘与协议

KIN-CONTINUE-001 审了五轮才过。事实：77 个文件、+5025/−1335（源码 +2836、测试 +2099），
后端只有约 40 行——耗时不在后端，也不在"删列表"。五轮各自发现的是新问题，不是同一个改五遍：
① 行为缺口（切走留白、覆盖层抢快捷键、过期当拒绝）；② 判定错误（关着的 Ionic 宿主被当成覆盖层、
引擎自动拒绝被说成"在这里决定"）；③ 契约漂移（Mac 归档地址、冷启动恢复、第二层 Tab/返回、渠道文案）；
④ 焦点竞态（返回行标记不消费、⌘F 按第一个 pane 判断）；⑤ 只验 delta，1.4 分钟结束。

它慢在四个可改的地方：

1. **按全量 diff 通读，没有按风险面清单逐项过。** 5k 行一次通读只能覆盖一部分，剩下的下一轮才撞见。
2. **修完一小批就重审全量。** 不是"一次修完，再只验 delta"。
3. **测试太浅，复审在替测试干活。** 手机面板测试证明"宿主在"，不证明"打开了"。
4. **送审时树是动的。** 未暂存、`web/dist` 过期，复审要花精力分辨"审的是什么"。

### 协议（下一条故事照做，目标 2–3 轮）

1. **送审前**：按下面的风险面清单自查一遍；每条新行为跑一个 mutant，证明测试会红；
   全量 stage；重建 `web/dist`；告诉复审者"工作树只读，只出报告不改代码"。
2. **第 1 轮**：全量 diff + 相关调用点，一次性列出全部发现，按 blocker/major/nit 分级。
3. **一次修完**（含 nit）→ **第 2 轮只验 delta** 和对应不变量，不再重读全量。
4. 第 2 轮若冒出"改前就存在"的 major，先补风险面清单，不算流程失败。

### 风险面清单（按故事取用）

键盘归属（⌘F/Esc/方向键/j/k/a/d）· 焦点（挂载时序、返回行、弹层内）· 历史（push/back/关闭/深链）·
两种宽度一致性 · 空/慢/错/断线 · i18n 双语言 · 生成物（`web/dist/index.html` 与 chunk）·
无障碍名字与状态（`aria-expanded`、`aria-checked`）。
