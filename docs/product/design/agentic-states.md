# Agent 状态规格（草案）

状态：**草案，未签字。** 只回答“agent 在工作时，界面上该出现什么状态语言”，
不回答协议、事件字段、隐藏推理怎么存。
配套：[`../TASTE.md`](../TASTE.md) 第 10 条（四个状态、两种语言）、[`../IA.md`](../IA.md)。

## 为什么单独一份

TASTE 第 10 条要求每个列表、面板、表单都有空、加载、错误、断线四态。那是
**界面状态**的底线，不是 **agent 状态**的语言。一个对话里同时有：思考、流式
输出、工具调用、等待批准、等待回答、排队、重试、断线。这些不是同一种东西，
但现在没有一个地方写清楚它们分别该长什么样、谁优先、什么时候可以折叠。

这份规格借用 Astryx 的分类法（`docs/design/agentic-states.md`，MIT）：状态按
**谁驱动变化**分三类，agent 驱动的单独一类，并且**先复用已有语言**，不新造。

| 类别 | 谁驱动 | Kin 已有的词 |
|---|---|---|
| 用户状态 | 人 | rest / hover / press / focus / 选中 |
| 系统状态 | 界面自己 | 空 / 加载 / 错误 / 断线 / 禁用 |
| **Agent 状态** | agent | 已建：思考 / 流式 / 工具 / 等待。待定：同步 / 检查 / 渲染——见 OQ6–OQ8，还不是现有的词 |

## 现在的词汇（2026-11-08 盘点）

| 现有实现 | 状态 | 位置 |
|---|---|---|
| 思考行 | 等第一个 token | `ChatStream.tsx` `role="status"` 行 |
| 流式文本 | 增量未完成 | `ChatStream` 消息体 |
| 工具步骤 | running / done / error | `ToolStepRow.tsx` |
| 进度卡 | running / done / failed / partial_failed | `summarizeProgressStatus()` |
| 排队消息 | 等下一轮 | `ChatStream.queuedSeqs` |
| 待批准 | 阻塞等人 | `ApprovalCard.tsx`、`FloatingApproval.tsx` |
| 待回答 | 阻塞等人 | `UserQuestionCard.tsx` |
| 断线 | 连接没了 | AppShell 断线态 |

这张表就是现状。它没有回答的是下面 8 个问题——**这些是设计决策，不是实现细节**。

## 开放问题

**OQ1 — 思考和普通处理要不要分开？**
“等第一个 token”和“工具在跑”现在是两种画法，但都没有名字。分开的依据是什么：
是耗时、是可中断性，还是“人能不能预期还要多久”？定了要改：思考行与进度卡。

**OQ2 — 可见解释和隐藏推理的边界。**
Kin 不能、也不该展示模型的隐藏推理。但“agent 自己写的一段说明”是产品内容，
可以展示。问题不在能不能，在**画法**：它和普通输出要有区别吗？有区别会不会
暗示“我们看到了推理过程”？定了要改：消息体的排版规则。

**OQ3 — 流式文本怎么算“还没完”。**
光标、渐隐、还是什么都不做？前提是**不能干扰已经可读的部分**，也不能让
屏幕阅读器每来一个 token 就播报一次。定了要改：`ChatStream` 的增量渲染和
`aria-live` 策略。

**OQ4 — 工具执行展示多少、什么时候折叠。**
现在 `ToolStepRow` 全量列出。一个问题：人真正需要的是“它在干什么”，还是
“它动过哪些文件”？折叠的默认值应该按**能否撤销**分，还是按**是否需要人介入**分？

**OQ5 — 等待人回答要压过一切。**
待批准和待回答现在有两种卡片。它们和“正在跑”的区别不是颜色，是**谁被阻塞**：
agent 停了，人在等。这条优先级要在任何折叠、任何多对话并排里都成立。

**OQ6 — 同步中 / 已同步。**
手机 → Hub → Mac 这条链路上，“命令发出去了”和“Mac 收到了”是两件事。现在
界面用一个 loading 盖住。它们要不要分开？分开了会不会让人以为要等两次？

**OQ7 — 检查。**
agent 读文件、看 diff、跑测试，算不算一种独立状态，还是“工具执行”的子集？
判断标准：人需不需要**当场**看到它在看什么。

**OQ8 — 生成界面的挂载。**
产物（`ArtifactsPage`）从生成到可打开之间有一段。这段是“加载”还是“生成中”？
两者的区别是：前者可以等，后者可能失败并需要重新生成。

## 决策记录

无。以上 8 条都未定。定了的写在这里，并同步改 TASTE 或 IA。

## 边界

这份文档不定义：事件协议、`TaskEvent.kind` 的取值、隐藏推理的存储、具体颜色
和动效、i18n 文案。它只定义**状态该不该存在、彼此什么关系**。
