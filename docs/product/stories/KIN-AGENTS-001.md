# KIN-AGENTS-001 · 机器上的 agent

状态：covered
优先级：P1
旅程：J6
归属面：`IA.md`「设置与环境」的 agent 运维面（`/agents`）
面：Mac、手机

## 谁、什么时候、为什么

当我想知道这台机器上到底有哪些 agent 能用、哪个没登录、这个月花在哪，我想在一个页面上看到全部 agent 的状态和用量，并把缺的装上、把坏的修好，以便新建对话时不再撞上「这个 agent 不可用」，也不用去翻日志。

## 现在

`/agents` 把用量和 agent 管理揉在一页：上半是 7/30/90 天的花费、token、缓存命中与每日花费，下半是 agent 表（状态、版本、登录、花费、token、任务数、效率、额度、操作）。手机用卡片和动作面板。没有页面测试；「重检」「全量 smoke」只给一句 toast，失败时不说清是哪一台；额度的「等待中」与登录状态在表里是两套颜色。

目录现在有 74 个产品条目（`internal/adapter/detect/skills_catalog.go`，含编辑器与 CLI），远超一个人能读完的规模，也没有「接入前确认」这一步。2026-11-11 签字时定下三条：目录收敛到 10 个产品以内；接入一个被发现的 agent 必须由你确认；接入不导入它的历史会话，会话只在手动导入时进来。

截图：`09-agents-1280.png`、`22-agents-390.png`。

## 范围

- 做：打开 agent 运维 → 看用量区间 → 找一个 agent → 重检 / smoke / 装或更新 / 设为默认 / 复制安装命令 → 看清它的额度和登录状态 → 发现一个未接入的 agent 时先确认再接入 → 离开再回来。
- 做：目录保持在一屏可读完的规模——最多 10 个产品；同一产品的 native / ACP / 通用 CLI 只算一个（已有的 `agentFamilies` 合并规则）。满 10 个时不能悄悄再加，必须先移除或合并一个。
- 做：接入只增加一个可用 agent，不导入它的历史会话；会话导入始终是用户手动点的动作，没有自动导入。
- 不做：改 provider 的密钥与端点（`KIN-SETTINGS-001`）；新建对话的 agent / 模型 / 权限选择（`KIN-START-001`）；删除或卸载 agent；跨机器的调度与安装推送；自动发现即自动接入；自动导入任何 agent 的历史会话。

## 每一步的预期

### 1. 定义 / 打开：这里的 agent 现在什么样

| 项 | 预期 |
|---|---|
| 起点 | Mac 左栏底部或手机 K 面板的「Agent 运维」 |
| 动作 | 打开 `/agents` |
| 立刻看到 | 页面标题与说明；用量区间（7 / 30 / 90 天）默认 7 天；下面先出 agent 列表的骨架；目录标题旁写「已接入 N / 10」 |
| 慢 / 空 / 失败 / 断线 | 加载中出骨架；没有用量时写「这段时间没有用量」而不是空白表；没有 agent 时写「还没有可用的 agent」并给安装入口；断线时标「离线，显示上次结果」 |
| 键盘与焦点 | Mac：Tab 到区间切换与「重检」；手机：标题让位给内容，区间是分段控件 |
| 离开再回来 | 区间与排序保持上次选择 |

### 2. 定位：用量花在哪

| 项 | 预期 |
|---|---|
| 起点 | `/agents`，用量卡片可见 |
| 动作 | 切换 7 / 30 / 90 天 |
| 立刻看到 | 花费、token、缓存命中率、任务数随区间更新；每日花费图跟着重画 |
| 慢 / 空 / 失败 / 断线 | 切换中保留旧数字并标「更新中」，不闪成骨架；失败时回到旧区间并说明 |
| 键盘与焦点 | Mac：三段可用 ←/→ 切换；手机：分段控件至少 44px 高 |
| 离开再回来 | 停在所选区间 |

### 3. 准备 / 确认：找到那一个 agent

| 项 | 预期 |
|---|---|
| 起点 | agent 列表 |
| 动作 | 看每个 agent 的状态、版本、登录、额度与操作 |
| 立刻看到 | 每行能一眼分出「可用 / 未登录 / 未安装 / 需要更新」；额度等待中显示进度与原因；默认 agent 有标记 |
| 慢 / 空 / 失败 / 断线 | 重检进行中该行显示「检查中」；某个 agent 状态读不到时写「状态未知」，不猜成可用；断线时禁用重检 |
| 键盘与焦点 | Mac：表头可点排序，当前列有 aria-sort；手机：一行一张卡，操作收进动作面板 |
| 离开再回来 | 排序保持；展开的动作面板不保持 |

### 4. 确认：接入一个新 agent 要你点头

| 项 | 预期 |
|---|---|
| 起点 | `/agents` 目录下方出现「发现 1 个未接入的 agent」；或目录已满 10 个 |
| 动作 | 点「查看」→ 读说明（会新增一个可用 agent；不会导入它的历史会话）→ 点「接入」或「取消」 |
| 立刻看到 | Mac 是确认对话框，手机是底部面板；接入后该 agent 进入目录并标「检查中」，完成后显示可用 / 未登录；取消后仍是「未接入」，目录不变 |
| 慢 / 空 / 失败 / 断线 | 接入失败说明原因并保留「未接入」与重试；已满 10 个时「接入」禁用并写「先移除或合并一个」；离线时禁用 |
| 键盘与焦点 | 焦点进入确认框，Tab 只在框内循环，Esc 取消；手机面板下滑取消 |
| 离开再回来 | 未确认的发现仍在；已接入的保留 |

### 5. 执行：把它修好或装上

| 项 | 预期 |
|---|---|
| 起点 | 一个未登录 / 未安装 / 需要更新的 agent |
| 动作 | 重检、smoke、装或更新、设为默认、复制安装命令 |
| 立刻看到 | 动作进行中就地把那一行标成「检查中 / 安装中」，完成后状态与时间更新；「设为默认」成功后标记移到这一行 |
| 慢 / 空 / 失败 / 断线 | 动作失败时说明是哪个 agent、哪一步失败，并保留重试；smoke 全部跑完给出「N 通过 / M 失败 / K 跳过」并指出失败的 agent；断线时动作禁用并说明 |
| 键盘与焦点 | Mac：动作在行尾菜单里，Esc 关闭并还焦点；手机：动作面板里每个动作至少 44px，选完自动关闭 |
| 离开再回来 | 已完成的动作结果保留；进行中的动作离开后不假装完成 |

### 6. 监控：额度与登录会变

| 项 | 预期 |
|---|---|
| 起点 | agent 列表，某个 agent 正在等额度或登录过期 |
| 动作 | 重检，或隔一段时间回来 |
| 立刻看到 | 额度等待显示已等时长与恢复时间（有的话）；登录过期显示「需要重新登录」与命令；恢复后变回可用 |
| 慢 / 空 / 失败 / 断线 | 额度接口读不到时只隐藏额度列，不影响其余列；断线时保留上次额度并标时间 |
| 键盘与焦点 | 等待中的行不抢焦点；状态变化不用 live region 反复播报 |
| 离开再回来 | 下次打开重新读一次，不沿用旧状态 |

### 7. 收尾：从这里离开

| 项 | 预期 |
|---|---|
| 起点 | `/agents`，任意状态 |
| 动作 | 返回列表或去新建对话 |
| 立刻看到 | 列表与新建页用的是刚更新的 agent 状态 |
| 慢 / 空 / 失败 / 断线 | 没有可用 agent 时新建页仍给出说明与去 `/agents` 的入口 |
| 键盘与焦点 | Mac：返回后焦点在左栏对应入口；手机：返回回到 K 面板关闭后的列表 |
| 离开再回来 | 区间、排序与上次结果保留 |

## 各面差异

| 面 | 这一面怎么呈现 | 为什么不同 |
|---|---|---|
| Mac | 用量卡片一行四张，下面是 agent 表：状态、版本、登录、花费、token、任务、效率、额度、操作；接入确认是对话框 | 窗口宽，横向比较是这一页的主要动作；对话框不离开目录 |
| 手机 | 用量卡片两列，agent 收成卡片：名字、状态、关键数字，操作进底部动作面板；接入确认用同一套内容的底部面板 | 一屏只能放一件事；表格在 390 宽不可读 |

必须画到的状态：默认、加载、空（没有 agent / 没有用量）、未登录、未安装、需要更新、额度等待中、重检中、失败、断线、发现未接入、已满 10 个、接入确认中与接入失败。

## Do not

- 不改 provider 的密钥、端点与运行默认值（`KIN-SETTINGS-001`）。
- 不做 agent 的删除或卸载；不新增 agent 来源。
- 不自动接入被发现的 agent；没有用户确认就不改变目录（2026-11-11 签字）。
- 不自动导入任何 agent 的历史会话；导入只在用户手动点「导入」时发生（2026-11-11 签字）。
- 不让目录超过 10 个产品；满时先移除或合并一个，不静默挤进第 11 个（2026-11-11 签字）。
- 不为这一页新增后端接口；用现有的 agents / usage / limits 接口。
- 不把用量做成第二个设置页；区间切换只影响这一页。
- 不用颜色单独表达状态（每个状态都有文字）。

## 已知限制

- 帧中的「需要更新」没有数据来源：daemon 只报版本，不报最新版本，所以行状态是「可用 / 需要登录 / 未安装 / 已识别·验证中 / 不可用」，不猜「需要更新」。
- 帧中的「复制登录命令」没有数据来源：管理接口不提供登录命令；动作面板改为「让默认 agent 去登录」，用 `auth_detail` 预填一段任务。
- 已接入目录按浏览器保存（localStorage），不随账号走：换浏览器会按「可托管产品」重新播种。这是不新增后端接口的代价。
- 额度等待时长是「这个控制台第一次看到它等待」起算，不是服务商的真实等待起点（`period_start` 是当天零点）。
- 发现区只列可托管、已安装、未接入的产品：本机 10 个名额通常盖住全部已安装产品，所以发现区多在移除一个产品后或安装超过 10 个可托管产品时出现。
- 帧 01/04 的 Cursor 示例以「Cursor 是可托管产品」为前提；本机 PATH 里的 Cursor 若没有 headless 适配（`permission_modes` 缺失），只是 sighting，不能接入。`/api/agents` 合并了 74 条探测目录，把这些都当可接入会让上限与发现区没有意义。
