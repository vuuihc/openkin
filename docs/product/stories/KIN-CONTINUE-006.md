# KIN-CONTINUE-006 · 手机开屏：先用自己的控制台打开，新版本在后台整套换

## 谁、什么时候、为什么

当我在地铁里掏出手机、网络刚抖过一下，想接着问昨天那段对话，我想 App 用自己带着的那份控制台立刻打开——列表、底栏、上次的位置都在——以便不用盯着转圈，也不用杀掉重开。Hub 的新版本在后台整套换好；换不动就继续用旧的，并告诉我一句。

这是 2026-11-20 手机开屏卡死的结构半边（另半边 A 是有界重试，归 `R-boot-guard`）：那天 App 停在开屏转轮上，被迫强杀两次。本条只写合同与帧，状态保持 `draft`。

## 现在

- 开屏是 `ui/index.html:82` 的 `.kin-boot` 转轮，只有 React 第一次渲染才把它替换掉；那次渲染在 `ui/src/main.tsx:179`，而它在有界账户探测（`:166`）的回调里。探测没回来之前，屏幕上只有转轮；网络抖一下就是那天的样子。
- 今天手机常态加载的是 Hub 的 URL（`mobile/capacitor.config.ts:3-12` 的第一方 cookie 理由）；随包的 `webDir: "../web/dist"`（`:50`）只在没连过 Hub 或 Hub 连不上时兜底（`:22-23`）。所以「用自己的控制台打开」今天不是常态。
- 已经有一个换版路径：`ui/src/main.tsx:104` 的 `watchConsoleVersion()` 在 `visibilitychange` / `pageshow` 时读 `/` 的入口 chunk，不同就整页 reload（`ui/src/lib/consoleVersion.ts:114`），每个文档最多一次；它在 `ui/src/main.tsx:194` 首帧之后才挂上。它只比入口名，不看整套、不看兼容、不保留旧版；本条的后台换版必须与它收敛成一个判断，不能并存两个更新器。
- `/assets/*` 发 `public, max-age=31536000, immutable`（`internal/server/server.go:1603`），`index.html` 与 manifest 是 `no-cache`（`:1604-1605`）；`/api/version` 未鉴权，返回 Hub 版本（`internal/api/api.go:332`、`:908`）。
- 2026-11-20 23:42 实测：1.9 MB 入口 chunk 走 LAN 49 ms 完整返回；第一次隧道尝试 20 秒只收到 74 KB 就停住；随后三次 2.9–5.3 秒。图标、manifest 这类小文件每次都正常。
- `docs/product/IA.md:98` 的设置与环境表还写着手机「无此面」；本 PR 把那一行改成本条的面。

## 范围

- 前提：本条的实现前提是随包控制台能读到上次的列表数据（跨源直连或原生桥接二选一），该选择等 Ethan；在此之前本故事只保留合同与帧，不写代码。
- 做：
  1. 开屏基线：冷启动先渲染随包的那份完整控制台——列表壳、页头、底栏、上次的范围与位置——首帧不等账户探测、不等 Hub。它就是控制台本身，不是第二个界面或第二张启动页。
  2. 后台整套取回：首帧之后向已保存的 Hub 取回当前控制台整套（入口、按需分块、样式、图标、manifest）及其声明的版本与最低 Hub API；只用静态文件与现有 `/api/version`。
  3. 整套校验：版本（只有更新才换）、兼容（控制台要求的最低 Hub API ≤ Hub 实际）、字节完整（清单里每个文件都在、长度与摘要对上）。三项都过才算一套。
  4. 原子换入：整套通过才一次换入，发生在下一次开屏或一次受控重新加载；不出现半张新界面、空白帧或第二张启动页；换入后回到同一段对话与同一位置。
  5. 保留上一份完整版本：只留一份，作为切换中断或下次换不动时的回退；不无限增长。
  6. 失败与不兼容都说一句可行动的话：取不回、超时、500、半套、断线 → 继续用当前版本；两侧不兼容 → 保持当前控制台打开，给一个主行动（更新 App 或更新 Hub），不转圈。
- 不做：
  - 有界重试的超时与退避本身 → `R-boot-guard`；本条只要求失败后仍可用且说一句。
  - 队列 UI / 待处理面 → P13。
  - 原生重写 → DECISIONS 2026-11-20 23:47（不做原生）。
  - 桌面壳的升级与开屏 → `KIN-SETTINGS-002` / P10–P11。
  - PWA（浏览器直接打开 Hub）的更新语义 → 不变，仍由 Hub 重新部署自然更新。
  - 新接口、数据库 / 迁移、新依赖、`ui/package.json` 改动、增量 diff 与多版本预取。

## 每一步的预期

### 1. 定义：打开 App，先有自己的控制台

| 项 | 预期 |
|---|---|
| 起点 | 手机上冷启动 App（上一次已连过 Hub），或系统回收后从后台回来；网络刚抖过 |
| 动作 | 点开 App，不点别处 |
| 立刻看到 | 随包控制台的列表壳立刻出现（设备 / 项目 / 行按上次的范围），底部四个入口在；顶部一行灰字「本地版本 · 正在核对更新」，没有转轮挡住内容 |
| 慢 / 空 / 失败 / 断线 | 账户还没答、Hub 慢、完全没网时：有缓存就显示上次的列表与位置，没有就显示空态 +「离线 · 正在用本地版本」；不白屏、不无限转轮；首次安装且没连过 Hub 时仍落在连接页（基线是控制台，不是已登录会话） |
| 键盘与焦点 | 首帧焦点在主区标题，不自动弹键盘、不自动聚焦底栏；外接键盘 Tab 从内容开始 |
| 离开再回来 | 列表范围（搜索 / 状态 / 归档）、滚动位置、选中的设备按现有记忆恢复；切后台再回来不重新走开屏 |

### 2. 定位：知道这一版从哪来

| 项 | 预期 |
|---|---|
| 起点 | 基线已渲染，顶部那行状态在 |
| 动作 | 看一眼状态行；想细看就点开它（可选，不是必须） |
| 立刻看到 | 状态行写「本地版本 <版本> · 正在核对」；点开是一个只读小面板：当前版本、来源（本地 / Hub）、上次核对时间、Hub 版本与兼容结果 |
| 慢 / 空 / 失败 / 断线 | 核对没回来时面板写「还在核对」；读不到 Hub 版本时写「连不上 Hub，继续用本地版本」，不猜版本号、不显示 0 |
| 键盘与焦点 | 状态行是按钮，Enter / Space 打开面板；Esc 关闭后焦点回状态行 |
| 离开再回来 | 关闭面板不改变任何状态；核对完成后状态行就地更新，不弹 toast |

### 3. 准备：后台整套取回

| 项 | 预期 |
|---|---|
| 起点 | 基线已渲染，已保存 Hub 地址 |
| 动作 | 不点任何东西（App 在首帧之后自己开始） |
| 立刻看到 | 状态行从「正在核对」变成「正在取回 <版本>（x%）」；进度只在那一行，不遮挡内容、不占布局、不弹窗 |
| 慢 / 空 / 失败 / 断线 | 停住（观测到的那次是 20 秒没有新字节；有界阈值归 `R-boot-guard`）就放弃这次，状态行回「仍用本地版本 · 稍后再试」；Hub 500 同一句；完全没网就不发请求，写「离线 · 本地版本」；只取到一半时已取的文件不参与换入 |
| 键盘与焦点 | 进度不是控件，不进 Tab 序、不抢焦点；读屏只在状态行变化时礼貌播报一次 |
| 离开再回来 | 切后台暂停、回来继续或重来；不因为切后台就换入半套 |

### 4. 确认：版本、兼容、字节三项都过

| 项 | 预期 |
|---|---|
| 起点 | 整套文件已取回，尚未换入 |
| 动作 | 无（App 自己校验） |
| 立刻看到 | 状态行短暂显示「校验 <版本>」；通过后写「新版本已就绪，下次打开生效」，不通过就写原因的一行（缺文件 / 摘要不符 / 版本更旧 / API 不兼容） |
| 慢 / 空 / 失败 / 断线 | 版本：只有比当前新才换，相同或更旧不换；兼容：控制台要求的最低 Hub API 高于 Hub 实际 → 判不兼容，永不换；字节：文件缺失、长度或摘要不符、index 与入口对不上 → 判半套，永不换；任一项没有结论都按「不换」处理 |
| 键盘与焦点 | 不新增焦点目标；状态行文字变化不移动焦点 |
| 离开再回来 | 校验结果只对这次取回的整套有效；下次开屏重新比版本与兼容（不重下字节），Hub 已回滚就继续用当前版本 |

### 5. 执行：整套换入，原处继续

| 项 | 预期 |
|---|---|
| 起点 | 一套通过校验、且比当前新的控制台 |
| 动作 | 下一次开屏；状态行里的「现在换」是可选操作，不是必须 |
| 立刻看到 | 当前屏不闪白、不出现第二张启动页；换入后仍在同一段对话、同一滚动位置，输入框草稿还在；状态行变成「已用 <版本>」 |
| 慢 / 空 / 失败 / 断线 | 只有新 index 与它声明的全部文件都就位才切；切换中进程被杀 → 下次开屏仍打开上一份完整版本，不落在半套上 |
| 键盘与焦点 | 若换入触发一次重新加载，焦点回到同一控件、同一滚动位置，不丢到页首；返回路径不因换版改变 |
| 离开再回来 | 回到原来那段对话；上一份完整版本保留，作为下一次失败的回退 |

### 6. 监控：慢、断线、500、半套都不挡前台

| 项 | 预期 |
|---|---|
| 起点 | 后台正在取回 / 校验，或刚刚失败 |
| 动作 | 继续用控制台：翻列表、开对话、发消息 |
| 立刻看到 | 所有前台操作不受影响；发消息不排在整套下载后面，后台不抢前台请求 |
| 慢 / 空 / 失败 / 断线 | 停住 → 「更新没取完，仍用本地版本」+ 可重试；Hub 500 → 同一句；没网 → 「离线 · 本地版本」，网络回来可再试；半套 → 永不换入；每种只说一次，不重复弹 |
| 键盘与焦点 | 失败提示不是模态、不抢焦点；要重试时状态行是按钮，Enter 触发 |
| 离开再回来 | 失败结论保留到下次核对；重试不改变当前控制台与位置 |

### 7. 修改与收尾：不兼容时给一个下一步，留住上一份

| 项 | 预期 |
|---|---|
| 起点 | App 与 Hub 的版本无法一起工作（App 太旧或 Hub 太旧） |
| 动作 | 看状态行，或打开面板 |
| 立刻看到 | 当前控制台仍然打开并且能用；面板里只有一个主行动：App 太旧 →「这台 Hub 需要更新的 App」+ 更新 App；Hub 太旧 →「这台 Hub 需要更新」+ 去设置 / 复制地址；不同时给两个同等显眼的按钮 |
| 慢 / 空 / 失败 / 断线 | 判断不了兼容性（Hub 不答、版本读不到）不算不兼容：继续用当前版本并写「无法确认」，不锁死 |
| 键盘与焦点 | 主行动可获得焦点，Esc 关闭面板回状态行；不自动跳设置 |
| 离开再回来 | 结论保留到下次核对；更新 App / Hub 后下一次开屏自动恢复；上一份完整版本仍在，可回退 |

## Do not

- 不许把随包控制台做成第二个控制台或第二份状态：同一份构建产物、同一套列表 / 搜索 / 导航 / 记忆，不许出现「本地版列表」和「Hub 版列表」。
- 不许在开屏路径上等网络、等账户探测、等更新检查。
- 不许保留两个更新器：`watchConsoleVersion` 的 resume 检查与本条的后台换版必须收敛成一个判断，不许各自 reload。
- 不许换入半套、未校验、更旧或不兼容的版本；不许在换入时出现空白帧或第二张启动页。
- 不许新增接口、数据库 / 迁移、依赖或 `ui/package.json` 改动；整套的清单与摘要随构建产物走。
- 不许在手机上加「检查更新」按钮或升级设置页；界面只有一行状态与失败时的一句说明。
- 不许改 PWA 的更新语义，不许动 `KIN-SETTINGS-002` 的桌面壳升级。
- 不许写真实主机名、LAN 地址、设备 id 或账号名到故事 / 帧 / 测试。

## 决定

- D1 开屏基线：**已定**（CEO 2026-11-20 23:47）。推荐：开屏先跑随包控制台，首帧不等网络。代价：App 要保证随包那一份始终能单独启动，而且它只能有一个身份，不能长出第二套状态。
- D2 原子换入与保留上一份：**已定**（同上）。推荐：整套校验通过才换，保留一份完整旧版。代价：换入只发生在开屏 / 受控重载，不是无感热替换；每次换版要一份清单与摘要。
- D3 整套的存放与校验**（阻塞：等 Ethan 定跨源能力，2026-11-21）**：App 私有目录按版本存放已验证的整套，清单与摘要随构建产物；下次开屏从本地加载，只重新比版本与兼容。代价：本地多占一份控制台；清单格式变更要兼容旧包。另一条路是拿系统 WebView 缓存当存储——实现少，但系统会淘汰，无法保证「上一份完整版本还在」，不推荐。随包控制台在 capacitor://localhost，Hub 无 CORS 头（rg Access-Control-Allow-Origin internal/ 零命中），加 CORS 属安全边界变更须 ADR + 人批；本故事因此不能在任何一端先写实现。
- D4 基线控制台的登录**（阻塞：等 Ethan 定跨源能力，2026-11-21）**：沿用现有设备令牌（`ui/src/api/client.ts:287` 的 Bearer），让随包控制台在 App 自己的 origin 上也能调 Hub；cookie 仍只用于 Hub origin。代价：令牌要可撤销、不能变成第二个密码；首次安装没连过 Hub 时仍落在连接页。另一条路是原生层代理所有 API / SSE——登录最自然，但流式通道与新请求路径都要维护，第一版不推荐。随包控制台在 capacitor://localhost，Hub 无 CORS 头（rg Access-Control-Allow-Origin internal/ 零命中），加 CORS 属安全边界变更须 ADR + 人批；本故事因此不能在任何一端先写实现。
