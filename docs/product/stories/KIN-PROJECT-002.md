# KIN-PROJECT-002 · 项目的工作目录：看清这几个目录为什么在一起，并能增删

状态：approved
优先级：P0
旅程：J4
归属面：`IA.md`「项目」行（对话列表里的项目标题 → `/projects/:id` 封面上的工作目录块）
面：Mac、手机

## 谁、什么时候、为什么

当我有一个由几个目录一起组成的项目（一个仓库、旁边一层配置、另一个仓库），我想在项目封面上看清这几个目录分别是哪些、哪个是默认、它们为什么属于同一个项目，并且能自己增删和改默认，以便新对话落在我想要的目录里，不用为了改一个目录去叫 API 或手工改数据库。

## 现在

`Project` 已经有 `roots`（`project_roots` 表），`PATCH /api/projects/:id` 已经接受完整的 `{"roots": [...]}` 并由 `SetProjectRoots` 整体替换（`internal/api/projects.go:297-340`、`internal/store/projects.go:303`）。但封面只显示 `roots[0]`（`ProjectDetailPage.tsx:831`）：多 root 项目和单 root 项目看起来一样，没有默认标记，也没有增删入口，只有 API 和数据库知道还有别的目录。新建对话的落点已经尊重 root（`projectNewChatTarget`：一个 root 直接带 cwd，多个 root 去新建页选目录，KIN-PROJECT-001 D4），但用户在封面上看不到这条规则，也无从调整顺序。

## 范围

- 做：在 `/projects/:id` 封面上加一个工作目录块（inline，不开 tab、不加路由）→ 看清全部目录、顺序与默认 → 打开编辑 sheet 增加或移除目录、把某个设为默认（移到第一位）→ 保存 → 封面立即显示新列表 → 离开再回来仍是保存后的列表。
- 不做：项目说明 / instructions（未来 `KIN-PROJECT-003`，尚未写；PRINCIPLE §5.5 要求先证明 prompt 不能表达）；项目改名、置顶、归档（`KIN-MANAGE-001`）；项目上的例行任务调度（`KIN-ROUTINE-001`）；自动发现 `.gitmodules` 子模块（需要 daemon 侧读文件，未来故事）；跨设备同步项目记录（暂无故事，本版不做）；对已保存 root 的文件系统检查（当前没有这个端点，所以不写「目录不存在」）。

## 每一步的预期

### 1. 定义 / 打开：这个项目由哪几个目录组成

| 项 | 预期 |
|---|---|
| 起点 | 项目封面（从对话列表的项目标题或 `/projects` 集合进入） |
| 动作 | 读页头下方的工作目录块，不点任何东西 |
| 立刻看到 | 全部 root 按保存顺序列出；第一个带「默认」标记；每行是这个目录的路径（过长时中间省略，悬停或聚焦看全）；块标题是「工作目录」，并写一句「新对话默认落在第一个目录」 |
| 慢 / 空 / 失败 / 断线 | 项目记录加载中：块与页头共用一副骨架，不先画「没有目录」；没有 root：写「这个项目还没有目录」并给「添加目录」；项目读取失败：整页已有失败态，块不单独猜；离线：显示上次缓存的列表并标「上次结果」，编辑入口禁用并说明 |
| 键盘与焦点 | Mac：Tab 从页头到工作目录块的「编辑」，再到其余封面控件；手机：块内没有隐藏的长按操作；读屏把块读成标题为「工作目录」的 region |
| 离开再回来 | 回到封面时块内容是上次保存的列表，不闪空、不重新排序 |

### 2. 定位：几个目录里哪个是哪个

| 项 | 预期 |
|---|---|
| 起点 | 封面，工作目录块有多行 |
| 动作 | 比较顺序与默认标记，读每一行的路径 |
| 立刻看到 | 顺序可见，第一行带「默认」徽标；路径过长时在中间省略，悬停或聚焦可看全；同一目录不重复出现 |
| 慢 / 空 / 失败 / 断线 | 只有一个目录时仍显示「默认」，不出现排序说明；390px 下长路径换行，不把页面撑横；断线时行照常可读，只是不能编辑 |
| 键盘与焦点 | Mac：只读块里不放开行内控件，Tab 不逐行停留；「设为默认」「移除」都在编辑 sheet 里 |
| 离开再回来 | 顺序与默认不变 |

### 3. 准备：增加一个目录

| 项 | 预期 |
|---|---|
| 起点 | 工作目录块 →「编辑」 |
| 动作 | 在 sheet 里点「添加目录」，用新建对话同一套机器 / 目录选择器选一个目录 |
| 立刻看到 | 选中的目录作为新行追加到末尾，不抢默认；sheet 底部「保存」可用；保存前封面不变 |
| 慢 / 空 / 失败 / 断线 | 选择器目录加载中写「正在读取目录…」；读不到给原因与重试，不清空已选；选到重复目录时就地说「这个目录已经在列表里」，不追加第二行；离线时「添加目录」禁用并说明 |
| 键盘与焦点 | 打开选择器后焦点在搜索框；Esc 关选择器并回到「添加目录」；选择器不撑高 sheet |
| 离开再回来 | sheet 有未保存修改时，关闭前先确认；取消后回到打开前的列表 |

### 4. 确认：移除一个目录意味着什么

| 项 | 预期 |
|---|---|
| 起点 | 编辑 sheet，列表里至少两个目录 |
| 动作 | 点某一行的「移除」 |
| 立刻看到 | 行内确认条写明后果：这个目录下的对话不再出现在这个项目下（它们仍在会话列表里），没有任何对话被删除；确认后行从草稿消失，若移除的是默认，则新的第一行接任默认 |
| 慢 / 空 / 失败 / 断线 | 移除最后一个目录时说明新对话将无处可落（「新建对话」会禁用），仍允许保存；离线时移除禁用；取消确认则行原样留在草稿里 |
| 键盘与焦点 | 确认条出现时焦点在「取消」上，Esc 取消并回到该行的「移除」；不做全屏二次弹窗 |
| 离开再回来 | 未保存的移除在关闭 sheet 前确认；已保存的移除下次打开不再出现 |

### 5. 执行 / 监控：保存整份列表

| 项 | 预期 |
|---|---|
| 起点 | 编辑 sheet，草稿与已保存不同 |
| 动作 | 点「保存」 |
| 立刻看到 | 按钮变「保存中」并禁用；成功后 sheet 关闭，封面块立即显示新顺序与默认；失败时 sheet 不关，草稿保留，错误条给原因与「重试」 |
| 慢 / 空 / 失败 / 断线 | 慢：超过阈值写「仍在保存…」；失败：保留草稿与焦点，不静默回滚；离线或 403：说明原因并禁用保存，不把半份列表发出去；项目已不存在：说明并给回列表 |
| 键盘与焦点 | ⌘/Ctrl+Enter 保存；保存失败后焦点回「保存」；成功后焦点回封面上的「编辑」 |
| 离开再回来 | 保存成功后封面不再显示草稿；再打开 sheet 是服务器上的列表 |

### 6. 修改：再次编辑

| 项 | 预期 |
|---|---|
| 起点 | 封面，工作目录块 |
| 动作 | 再点「编辑」，改默认或再增删 |
| 立刻看到 | sheet 打开时是当前保存的列表，不是上次留下的草稿；封面滚动位置不动 |
| 慢 / 空 / 失败 / 断线 | 打开时若项目记录已在别处被改，先用服务器返回的最新列表；保存与第 5 步同一套失败态 |
| 键盘与焦点 | 打开后焦点在 sheet 标题或第一行的「设为默认」；Esc 关 sheet 并把焦点还给「编辑」 |
| 离开再回来 | 没有草稿残留；关闭再打开不会把上次取消的改动带回来 |

### 7. 收尾：离开封面

| 项 | 预期 |
|---|---|
| 起点 | 封面，列表已保存 |
| 动作 | 返回列表或切到另一个项目 |
| 立刻看到 | 列表保持原来的搜索、过滤与折叠；工作目录块不因为离开而重置 |
| 慢 / 空 / 失败 / 断线 | 断线时仍能返回；编辑 sheet 还开着时，先确认丢弃草稿 |
| 键盘与焦点 | Esc 先关 sheet；sheet 关闭后再按 Esc 才离页；焦点回列表原来的项目标题 |
| 离开再回来 | 再打开同一项目，块显示保存后的列表，不出现第二次骨架 |

## 各面差异

| 面 | 这一面怎么呈现 | 为什么不同 |
|---|---|---|
| Mac | 工作目录块在页头与概览之间、占满主区；一条路径一行；「编辑」在块标题右端；编辑是贴合块的浮层，列表与「添加目录」同屏 | 窗口宽，几条路径可以同时读完；浮层不遮住封面上下文 |
| 手机 | 工作目录块在页头下方，路径换行；「编辑」是块内 44px 的行尾按钮；编辑是底部 sheet，保存按钮在 sheet 底部、不被键盘遮住 | 一屏只能放一件事；底部 sheet 拇指可达，长路径必须换行而不是横向滚动 |

## 设计

设计稿：`KIN-PROJECT-002.figma/frames/`（SVG 源帧，Figma 可导入）和 `KIN-PROJECT-002.review.html`（Figma 帧为主体，每屏六段用户流程）。

必须画到的状态：加载项目、没有目录、一个目录、多个目录、保存中、保存失败（原因 + 重试，保留草稿）、离线 / 只读（说明原因）、关闭 sheet 时的未保存修改。

## Do not

- 不开新 tab、不加新路由；工作目录块在现有封面上 inline（KIN-PROJECT-001 D2 保持不变）。
- 不改 schema、不加新 API：复用 `PATCH /api/projects/:id` 的 `roots`，保存时发送完整有序列表。
- 不承诺「目录不存在 / 不可读」：当前没有对已保存 root 的文件系统检查端点，不写这种状态。
- 不删除任何对话，也不在文案里暗示删除；移除目录只改变项目下的归属显示。
- 不为目录另造选择器；复用新建对话的机器 / 目录选择器。
- 不在只读块里做拖拽排序；顺序通过「设为默认」（移到第一位）与增删表达。
- 不做项目说明 / instructions、`.gitmodules` 自动发现、跨设备同步。

## 证据

- 之前：封面只显示 `roots[0]`，没有默认标记与编辑入口（`ProjectDetailPage.tsx:831`）；`PATCH /projects/:id` 已接受 `roots`（`internal/api/projects.go:297-340`）。截图：`rsi/state/shots/project-roots-face/before-1100-cover.png`、`before-390-cover.png`。
- 之后：
  - 单元 `ui/src/lib/projectRoots.test.ts`：归一化去空去重（首次出现保留位置）、设为默认移到首位且相对顺序不变、移除唯一 root 得空列表、追加重复目录就地报告。
  - 组件 `ui/src/pages/ProjectDetailPage.dom.test.tsx`：全部 root 按保存顺序显示且只有第一个带「默认」；保存发送完整有序列表；失败保留草稿与重试且焦点回「保存」；移除先读后果（不删对话）再确认；重开编辑是服务器列表而非已取消草稿；离线显示列表并禁用编辑并说明；追加目录与重复就地提示；移除最后一个目录说明新对话无处可落。
  - 回归 `ui/src/lib/projectChats.test.ts`：保存后的第一个 root 决定新对话落点。
  - 视觉：`rsi/state/shots/project-roots-face/` 的 `after-1100-cover.png`、`after-1100-editor.png`、`after-390-cover.png`、`after-390-editor.png`、`after-390-remove-confirm.png`；390 无横滚，点按区 ≥44px。
  - `./scripts/check.sh`：18 项全绿（含 stories、ui-inventory、ui-lint-guard）。
- 未闭合的一项（真浏览器）：封面读全部目录、添加、设为默认、移除并读确认、保存都可用，但保存后 daemon 按 `ORDER BY path` 读回（`internal/store/projects.go:157`），刚保存的顺序被重排，「默认」无法跨读取保留（`after-390-save-order-reset.png` 即此现象）。要让「保存顺序 = 默认」成立，daemon 需按插入顺序读（如 `ORDER BY rowid`）或存储 position；该文件不在本 lane 的声明路径内，未改。因此故事停在 `approved`，未置 `covered`。
