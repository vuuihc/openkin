# KIN-SETTINGS-002 · 桌面壳一键升级

状态：approved
优先级：P1
旅程：J1、J6
归属面：`IA.md`「设置与环境」（新增面：菜单栏托盘）
面：Mac
（手机没有这个面，理由见「各面差异」）

## 谁、什么时候、为什么

当我在第二台 Mac 上装了 Kin 桌面壳用了一阵子之后，我想点一下菜单栏的"检查更新"就知道有没有新版本、有的话一键装上，以便不用去 GitHub 手动找 dmg、拖文件夹、猜自己跑的是哪个版本。同一时刻 Hub 侧发布 tag（`v*`）时，我应该被打扰一次（可选通知）而不是永远不知道。

## 现在

今天的升级路径完全靠人：打开 https://github.com/vuuihc/openkin/releases 找到最新 tag、肉眼比对架构（arm64/x64）、下载 119MB dmg、双击拖进 /Applications 覆盖、重新打开。没有"当前版本"的可见入口（`desktop/package.json` 钉死 `0.0.0-dev`，dmg 里也是它），没有更新提醒，用户甚至无法回答"我跑的是不是最新"。release 流水线（`release.yml`）也只发 CLI 四架构二进制，不发 dmg。

## 范围

- 做：release 流水线在 mac 上构建 dmg（arm64）并挂到 GitHub Release；桌面壳托盘菜单"检查更新"（查 GitHub Releases API → 有新版 → 下载到本地 → 提示打开 dmg 安装）；托盘菜单显示当前版本号；版本号与 git tag 对齐（`desktop/package.json` 由 CI 注入 tag 版本）。
- 不做：手机端（PWA 由 Hub 重新部署自然更新，`openkin-auto-deploy-hub` 已覆盖）；Windows/Linux 的桌面壳（现有 electron-builder 只配了 mac target，别的故事）；自动后台静默升级（未签名 app 无法自替换，见 Do not）；升级 daemon 里的 `kin` CLI（node 二进制跟随 launchd 脚本走，不在桌面壳内）；通知中心推送"有新版"（先做手动检查，推送等使用数据）。

## 每一步的预期

### 1. 定义：知道自己在跑什么版本

| 项 | 预期 |
|---|---|
| 起点 | 菜单栏托盘，任意时刻 |
| 动作 | 点开托盘菜单 |
| 立刻看到 | 菜单顶部新增一行"Kin <版本号>"（如 `Kin 0.3.2`），灰字、不可点 |
| 慢 / 空 / 失败 / 断线 | 版本号来自打包时的常量，无网络依赖，不存在慢/失败；极端情况下（dev 模式）显示 `dev` |
| 键盘与焦点 | 托盘菜单是系统菜单，方向键导航；新行不改变既有顺序，只插在分隔符后 |
| 离开再回来 | 版本号是静态的，重开一致 |

### 2. 定位：查有没有新版本

| 项 | 预期 |
|---|---|
| 起点 | 托盘菜单 |
| 动作 | 点"检查更新…" |
| 立刻看到 | 菜单项立刻变为"正在检查…"（disabled）；结果回来后恢复为"检查更新…"并弹一个系统通知或菜单行提示：`已是最新（0.3.2）` 或 `发现 0.4.0 · 点击下载` |
| 慢 / 空 / 失败 / 断线 | GitHub API 请求超时（10s）→ 菜单恢复 + 通知"检查失败：无法连接 GitHub"；Release 无 dmg 资产（CI 出错）→ "这个版本没有 Mac 安装包，去 GitHub 看"；`0.0.0-dev` 本地构建 → "开发构建不检查更新" |
| 键盘与焦点 | 同托盘菜单系统行为 |
| 离开再回来 | 检查进行中关菜单，结果仍以通知送达；重开菜单看到恢复后的"检查更新…" |

### 3. 准备 + 确认：下载新版本

| 项 | 预期 |
|---|---|
| 起点 | "发现 0.4.0"的提示 |
| 动作 | 点通知（或菜单项"下载 0.4.0…"） |
| 立刻看到 | 菜单显示"下载中… XX%"（GitHub 资产直链，进度按字节计） |
| 慢 / 空 / 失败 / 断线 | 下载中断 → 菜单恢复"下载 0.4.0…"可重点；磁盘满/无权限 → 通知"下载失败：无法写入临时目录"；已有同名文件 → 覆盖（临时目录里上次的半成品不是资产） |
| 键盘与焦点 | 同托盘菜单 |
| 离开再回来 | 下载在后台继续；重开菜单看到当前进度 |

### 4. 执行 + 收尾：装上并重启

| 项 | 预期 |
|---|---|
| 起点 | 下载完成 |
| 动作 | 通知弹出"0.4.0 已下载 · 点击安装"；用户点它 |
| 立刻看到 | `open` 那个 dmg（Finder 挂载、显示 Kin.app 图标），同时当前 app 弹确认"要退出以安装吗？退出并打开 / 稍后" |
| 慢 / 空 / 失败 / 断线 | `open` 失败（dmg 损坏）→ 通知"安装包打不开，请手动下载"；用户点"稍后" → 什么都不发生，dmg 留在临时目录，菜单出现"打开已下载的 0.4.0"直到安装或点击清理 |
| 键盘与焦点 | 确认对话框是系统弹窗，Tab 在两个按钮间移动，Esc = 稍后 |
| 离开再回来 | 选"稍后"后菜单保留"打开已下载的 0.4.0"；重启电脑后临时目录被系统清理，该项自动消失，回到"检查更新…" |

### 5. 监控 / 修改

| 项 | 预期 |
|---|---|
| 起点 | 无 |
| 动作 | 无 |
| 立刻看到 | 没有这一段，因为安装即替换（用户拖动覆盖），无安装后的进度可监控；下次点开"检查更新…"读到新版本号即为验证 |
| 慢 / 空 / 失败 / 断线 | — |
| 键盘与焦点 | — |
| 离开再回来 | — |

## 各面差异

| 面 | 这一面怎么呈现 | 为什么不同 |
|---|---|---|
| Mac | 托盘菜单：版本行 + "检查更新…" + 下载进度 + 系统通知 | 桌面壳只在 Mac；托盘是它的常驻面 |
| 手机 | 没有。PWA 由 Hub 重新部署时自动更新，无需手动升级（`openkin-auto-deploy-hub` 记录的常设指令） | 手机没有这个面 |

## 设计

设计稿：`KIN-SETTINGS-002.figma/frames/`（SVG 源帧）和 `KIN-SETTINGS-002.review.html`。

必须画到的状态：默认（含版本行）、检查中、已是最新、发现新版、下载中、下载完成、检查失败、开发构建、已下载待安装。

## Do not

- 不做自动静默升级：app 未签名（`identity: null`），macOS 不允许运行中的 app 自替换已挂载镜像；假装能静默升级是骗用户。拖装是当前签名状态下的诚实上限。
- 不把升级通道指向任何非 GitHub 官方域（不引入自建更新服务器）。
- 不在控制台 SPA（daemon 服务的网页）里出现升级入口——桌面壳的更新是壳的事，Hub 不认识壳。
- 不改 daemon/CLI 的升级路径（`install-node-service.sh` 是 node 的通道）。
- 不弹"有新版"的主动通知（第一版只做拉取式检查；推送等真实使用数据再议）。

## 证据

- 之前：`desktop/dist-electron/Kin-0.0.0-dev-arm64.dmg`（本地 119MB，版本号即问题）
- 之后：release tag `v0.4.0` 起在 GitHub Releases 产出 `Kin-v0.4.0-arm64.dmg` + `.sha256`；托盘检查更新走 GitHub API 对比 tag；实机 dogfood（检查→下载→打开 dmg→确认退出→拖装→重开新版）待第一次真实 tag
