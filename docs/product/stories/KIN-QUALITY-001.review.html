01 · 平板 · 820×1180（触摸，分栏）

默认阅读：一条 header、正文、一个 composer

Figma 帧

用户流程

  1. 起点在对话列表点开一段有长回答和表格的对话；分栏仍展开。
  2. 动作纵向读正文；表格需要时在自身容器里横向滑；不点状态。
  3. 立刻看到正文上方只有一条 ≤44px header；表格第一列完整，最后一行在 composer 之上完整可见。
  4. 慢 / 空 / 失败 / 断线加载保留已有内容并给局部等待面；空对话说明「还没有回答」；失败给可重试说明；断线见 06 屏。
  5. 键盘与焦点打开后焦点在正文阅读起点；Tab 到 header 入口、表格容器、composer；表格容器可用方向键滚动。
  6. 离开再回来回来恢复滚动位置和草稿；不重新播报已读内容。
02 · 手机 · 390×844

同一个阅读结构，收成单列

Figma 帧

用户流程

  1. 起点手机上从列表进入同一段对话。
  2. 动作拇指滚动阅读；表格在容器内左右滑；状态从 footer 的「用量」或 header 的「文件」进入。

  6. 离开再回来切到别的对话再回来，草稿与滚动位置仍按这段对话保存。

04 · 平板 · 820×1180

展开状态：复用既有入口，不新增面板

Figma 帧

用户流程

  1. 起点读者正在读，想确认用量或找一个会话动作。
  2. 动作点 footer 的「用量」、header 的「文件 · 2」（PR 面板也在这里）或「⋯」中的一处。
  3. 立刻看到对应的既有 popover/动作表出现；每个目标最多一个动作可达；阅读内容不被替换。
  4. 慢 / 空 / 失败 / 断线用量加载写「正在读取」；失败保留上次值并说明；空写「还没有用量」；被动打开不发 GitHub 请求、不读 secret。
  5. 键盘与焦点入口是按钮；Esc 关闭并把焦点还给入口；动作表行可 Tab。
  6. 离开再回来面板默认关闭，不记住上次展开；阅读滚动位置不变。
05 · 平板 · 820×1180

新进展：非内容通道，不盖单元格

Figma 帧

用户流程

  1. 起点读者停在回答中段，下方又来了新内容。
  2. 动作继续读；想跟上时点「有新进展」。
  3. 立刻看到通道在 composer 上方占一行，表格让位但不被覆盖；点后滚到末尾，通道自行消失。
  4. 慢 / 空 / 失败 / 断线没有新内容时不出现；断线时保留通道里的最后状态；新内容失败时用消息说明且不擦除旧内容。
  5. 键盘与焦点按钮有可见名字，Tab 可达，Enter/Space 触发；live region 礼貌播报一次，不抢焦点。
  6. 离开再回来已在末尾则不再出现；不在末尾则重新出现，不重复播报旧内容。
06 · 平板 · 820×1180

失败/断线：一条说明，内容和批准都在

Figma 帧

用户流程

  1. 起点阅读或发送时连接断开，或一次加载失败。
  2. 动作读那条说明；点重试或等待恢复。
  3. 立刻看到只有一条 transient 说明；表格、草稿、批准按钮都还在；恢复后说明自己走。
  4. 慢 / 空 / 失败 / 断线断线写「连接已断 · 恢复后继续」；失败给原因和重试；不显示永久红块，不擦除批准/回答 affordance。
  5. 键盘与焦点说明以 role=alert/status 播报一次；焦点不跳走；重试按钮可 Tab。
  6. 离开再回来恢复后不重复播报；内容、草稿、滚动位置都在。

要你拍板的

已定的不用回；只回不同意的编号。D6 是唯一还需要你确认的取舍。

D1 820 优先，阅读结构只留 header + 正文 + 一个 composer

已定：常驻 chrome ≤44px；状态收进既有入口，不加 bar、badge 或第二份状态面板。

代价：状态不再一眼可见，需要一次点按；换取正文完整。

D2 新进展不能盖内容，位移优先

已定：新进展占 composer 上方的非内容通道；内容 readability 优先于零位移。

代价：出现时会挤动阅读区域；换取任何可见单元格都不被遮挡。

D3 表格在自身容器内滚动，不缩字号

已定：列保持可读，页面不横滚；最后一行可完整进入视野。

代价：窄列需要横向滑动；换取不逐字换行、不靠 hidden 掩盖。

D4 失败/断线只留一条 transient 说明

已定：内容、草稿、批准与回答 affordance 保留；恢复后说明自己走。

代价：错误不再有永久红色区域；换取不占阅读空间、不制造假状态。

D5 列表重做不在这一条

已定：筛选、默认折叠与 ≥10 条目标 parked 到 R-list-scan，邻接 KIN-CONTINUE-004 / 003。

代价：这条交付后列表仍不是 T3；换取一次只交付一个连贯的阅读意图。

D6 平板的次要动作复用既有 ⋯，按对话列宽度挂载

推荐：复用手机已有的会话动作表/浮层，把「只在 <768 挂载」改成按对话列宽度与 useCoarsePointer() 判断；不新写第五个弹层（TASTE 13）。

代价：要动一处既有挂载条件，回归面比新组件小；若改成新浮层，代码更多、与手机行为分叉。
