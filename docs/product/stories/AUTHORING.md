# 写一条故事（AUTHORING）

任何新功能、行为改动，**先写故事，签字，再写代码**。故事是开发和回归共用的合同；
代码只是让它变绿的一种方式。写不出故事，说明还没想清楚要做什么。

## 一条命令开始

```bash
python3 scripts/stories.py new CONTINUE "一句话说清这件事" --journeys J1,J2 --surfaces mac,phone
```

它会分配下一个编号、复制模板、写进 `registry.json`、重新生成 `COVERAGE.md`。
填完再跑 `python3 scripts/stories.py` 验证；不过就是还没写完。

## 五步

### 1. 选意图

六条意图：接着问 / 新建 / 看结果 / 管理对话 / 设置与环境，以及离开控制台后被叫回来（通知）。一条故事只属于一条。

用 JTBD 句式写一句话："当我……，我想……，以便……。"

横跨两条意图说明切错了：要么拆开，要么并到更合适的那条。先在
`PLAN.md` 的六条故事里确认这件事归谁；不属于任何一条，先补方案，再写故事。

### 2. 定范围

写清"做"和"不做"。"不做"的每一条要写去处（哪条故事）。
范围外的事如果没有任何故事管，说明意图表缺一条，先补表再写故事。

### 3. 列步骤（job map）

按 Ulwick 的八段走：定义、定位、准备、确认、执行、监控、修改、收尾。
某一段这件事没有，就写一行"没有这一段，因为……"。

每一步填固定六项：起点、动作、立刻看到、慢/空/失败/断线、键盘与焦点、离开再回来。

六项是检查表，不是格式：
- **立刻看到**写不出 → 用户点了没反应。
- **慢/空/失败/断线**写不出 → 只想了顺利路径。
- **键盘与焦点**写不出 → 键盘用户会卡住。
- **离开再回来**写不出 → 状态会丢。

### 4. 写各面差异

Mac、手机各一行：这一面怎么呈现、为什么不同。没有这个能力就写"没有"和原因，不留空。
只写不同点；两边一样的部分写在步骤里，不重复。

### 5. 写验收

Given / When / Then，一条规则至少一个例子。能自动化的写成测试文件路径，
文件名或测试名里带故事编号。写不出测试的规则，要么规则不清楚，要么这一轮不该做。

### 6. 画设计稿（审批用）

文字说行为，Figma 说样子。审批看的是 Figma 帧和每屏的用户流程，不是表格。

在故事旁边建两样东西：

- `<编号>.figma/frames/*.svg`：每个界面一帧，Mac 1100×760、手机 390×844；
  状态和修改/收尾可以用更宽的状态板。这些 SVG 是 Figma 可导入的设计源；
  有真实 Figma 文件时把链接写进审阅页，但本地帧必须能离线打开。
- `<编号>.review.html`：从 `_REVIEW.html` 复制。它是不依赖网络/CDN 的单页，
  **手机可读**：
  单列、正文 16px、390px 不横滚、深色模式可读、不引 CDN 或外链，页内有粘性目录，
  页尾有可复制的回复模板。**Figma 帧是主体**；宽帧只在卡片内左右滚动，
  页面本身不横滚，帧下面必须有用户流程。

每一屏的固定顺序：

1. **帧**：`<img src="…/frames/….svg">`，标尺寸、写 alt、给「打开原图」；
   宽帧放进 `overflow-x:auto` 的容器，并说明「左右滑动看完整」。Mac 帧默认先露出主区
   （容器加 `data-start="330"`，模板里的脚本会设置初始滚动位置），仍可左右滑回侧栏；
   无脚本时从左侧开始，不影响阅读。
2. **六段用户流程**：起点、动作、立刻看到、慢/空/失败/断线、键盘与焦点、离开再回来。
   帧讲样子，流程讲发生什么；两者对不上就是没画完。

必须画：

- **先写 MECE 一节**：意图地图（这条在哪一格、别的格归谁）、job map 覆盖了哪几步、
  设备为什么只是差异维度、明确不做的事归哪条故事、四条大小自检。人先看这一节，
  确认切法对了，再看帧；检查器从 `approved` 起要求 `<h2>MECE` 存在。
- 每个 job map 步骤至少一屏，标出点哪里、出现什么。
- 这条故事涉及的状态：默认、空、加载、错误、断线、锁定、运行中、等待批准，按故事取用。
  状态多时用一张状态板，另列一遍可读的文案检查表。
- 两个面各画一套（Mac 1100×760、手机 390×844）。手机帧按 390 宽画；
  Mac 帧在手机页里保持 1100 宽、在卡片内横向滚动，**不要把桌面页缩到手机宽度**
  或让整页横滚。
- 一句"现在 → 之后"的对照，和需要人拍板的决策点。每条决策写“推荐 + 代价”；
  已经拍过板的写「已定」，不再重复问；页尾给 `D2 同意` 这样的回复模板，
  人只回不同意的编号。
- 页面顺序固定为：一句话 → 怎么审 → 切法 → 现在→之后 → 界面（帧 + 用户流程）→
  状态 → 决定 → 回复模板 → 签字。页首要写「Figma 审阅版 · 约几分钟 · 几个决定」。

页面必须带 `<meta name="kin-review-format" content="figma-flow-v1">`，包含“用户流程”
字样，并至少引用一个 `.svg` 帧或 Figma 链接。检查器从 `approved` 起要求这些；
`KIN-CONTINUE-001` 是规则之前的旧页，保留例外。

帧只用线框，不放真实数据、真实截图、真实主机名。真实截图留到交付验收时补。

## 签字前自检（12 问）

1. 这条故事只属于一条意图？
2. 每一步六项都填满？
3. 慢、空、失败、断线都写了？
4. 焦点从哪来、回哪去写了？
5. Mac 和手机各一行，没有能力的写了原因？
6. 和别的故事有没有重复的句子？（有就删一处，指向那条）
7. 每条验收都能变成测试？测试能先红吗？
8. 范围外的事都有去处？
9. 这条故事一次能交付完吗：一个用户能做完的动作、两端都成立，装得下测试、复审、390/1100 截图？装不下就按意图拆成两条故事，不要分阶段。
10. 有没有把实现细节（组件名、类名）当需求写？需求写行为，实现留给代码。
11. 草图是 Figma 优先的吗：每个界面都有帧，帧下面有六段用户流程；390px 不横滚，宽帧只在卡片内滚动？只看帧和流程能不能说出会发生什么？
12. 草图的 MECE 一节写了意图地图、job map 覆盖和不在这一条的去处吗？每条决策有推荐和代价、页尾有回复模板吗？

十二问都过，再把状态从 `draft` 改成 `approved`，然后才动代码。

## 检查器会拦什么

- 缺章节：谁/现在/范围/每一步/各面差异/设计/Do not/验收/证据/变更记录
- 某一步缺六项里的任意一项
- 面少一行、旅程对不上
- 验收表里没有 Given / Then
- Do not 为空
- 从 `approved` 起：草图不存在、没写编号、还留着 `（填）`、没有 `MECE` 一节，
  没有 `kin-review-format=figma-flow-v1` 标记、没有“用户流程”、没有引用
  `.svg` 帧或 Figma 链接，或没有 `width=device-width` 视口
  （旧页 `KIN-CONTINUE-001` 例外）
- 模板占位符没换
- 状态不是 `draft`，却没有 `<编号>.review.html`，或草图里没写编号
- 测试文件里没有故事编号
