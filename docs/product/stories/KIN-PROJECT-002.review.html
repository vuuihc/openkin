现在 → 之后

现在

  • 封面只显示 roots[0]；第二、第三个目录在界面上不存在。
  • 没有「默认」标记；用户不知道新对话会落在哪个目录。
  • 多 root 项目只能靠 API 或数据库改目录，改不了顺序。

之后

  • 封面上看到全部目录、顺序和默认，一句话说明它们为什么在一起。
  • 「编辑」里增删目录、把某个设为默认，保存后封面立即更新。
  • 移除时先说清后果：对话不删，只是不再出现在这个项目下。

01 · Mac · 1100×760

项目封面 · 工作目录块

Figma 帧

用户流程

  1. 起点从对话列表的项目标题或 /projects 集合进入封面；页头是项目名与模式。
  2. 动作不点任何东西，先读页头下方的工作目录块。
  3. 立刻看到全部目录按保存顺序列出，第一条带「默认」，块里写明「新对话默认落在第一个目录」；下面才是概览，页面上没有多出 tab。
  4. 慢 / 空 / 失败 / 断线项目加载中与页头共用骨架；没有目录写「这个项目还没有目录」并给「添加目录」；项目读取失败走整页失败态；离线显示上次缓存的列表并标「上次结果」，编辑禁用并说明。
  5. 键盘与焦点Tab 从页头到「编辑」再到概览控件；只读块里不逐行停 Tab；块读成标题为「工作目录」的 region。
  6. 离开再回来回到封面仍是保存后的列表与顺序，不闪空、不重排。
02 · Mac · 1100×760

编辑浮层 · 增删与设为默认

Figma 帧

用户流程

  1. 起点封面工作目录块 →「编辑」；浮层贴在块旁，封面留在后面。
  2. 动作点「添加目录」用新建对话同一套机器 / 目录选择器；点某一行的「设为默认」或「移除」。
  3. 立刻看到新目录追加到末尾；「设为默认」把那一行移到第一位；「移除」先出确认条；保存前封面不变。
  4. 慢 / 空 / 失败 / 断线选择器读目录时写「正在读取目录…」，失败给原因与重试且不清空已选；重复目录就地提示；离线时添加与移除禁用并说明。
  5. 键盘与焦点打开后焦点在标题；Tab 到每行的「设为默认」「移除」、「添加目录」、「取消」「保存」；Esc 关浮层并把焦点还给「编辑」。
  6. 离开再回来有未保存修改时关闭先确认；取消后回到打开前的列表。
03 · Mac · 1100×760

移除确认 · 后果写在行内

Figma 帧

用户流程

  1. 起点编辑浮层里至少两个目录。
  2. 动作点某一行的「移除」。
  3. 立刻看到行内确认条：「移除后，这个目录下的对话不再出现在这个项目下；它们仍然在会话列表里。没有对话会被删除。」确认后行从草稿消失；默认被移除时新的第一行接任。
  4. 慢 / 空 / 失败 / 断线移除最后一个目录时说明新对话将无处可落（「新建对话」会禁用），仍允许保存；离线时移除禁用；取消确认则行原样留下。
  5. 键盘与焦点确认条出现时焦点在「取消」；Esc 取消并回到这一行的「移除」；不用全屏二次弹窗。
  6. 离开再回来未保存的移除在关闭前确认；已保存的移除下次打开不再出现。
04 · 手机 · 390×844

手机 · 封面的工作目录块

Figma 帧

用户流程

  1. 起点手机对话列表点项目标题推入封面；左上返回至少 44px。
  2. 动作上下滑读工作目录块，点块标题右端的「编辑」。
  3. 立刻看到单列；三条路径按顺序排，长路径换行不横滚；第一条带「默认」；概览在块下面。
  4. 慢 / 空 / 失败 / 断线与 Mac 同一套文案；加载骨架、空目录、失败与离线各自说明；离线时编辑禁用并写明原因。
  5. 键盘与焦点外接键盘：Tab 到「编辑」；读屏把块读成标题为「工作目录」的 region，顺序念路径与默认。
  6. 离开再回来返回列表再进来，仍在原来滚动位置，列表是保存后的顺序。
05 · 手机 · 390×844

手机 · 编辑底部 sheet

Figma 帧

用户流程

  1. 起点手机封面 → 工作目录块的「编辑」；底部 sheet 从下方升起，封面留在后面。
  2. 动作点「添加目录」选目录；点「设为默认」「移除」；最后点「保存」。
  3. 立刻看到sheet 占大半屏，每行路径可换行，「设为默认」与「移除」各 44px；保存按钮在底部，不被键盘遮住。
  4. 慢 / 空 / 失败 / 断线保存中按钮禁用并写「保存中…」；失败保留草稿、给原因与重试；离线或只读说明原因并禁用保存。
  5. 键盘与焦点每个可点区域 ≥44px；外接键盘 Tab 顺序与 Mac 一致；Esc 等同关闭并确认草稿。
  6. 离开再回来保存成功后 sheet 关闭、封面块立即更新；取消不留下草稿。

状态

状态也是 Figma 帧的一部分；先看状态板，再读它下面的流程与检查表。宽板在卡片内左右滑动。

用户流程

  1. 起点封面块或编辑浮层，处在状态板中的任意一格。
  2. 动作读当前状态给出的下一步：添加目录、重试、等保存、恢复网络或继续编辑。
  3. 立刻看到每一格都有明确文案与一个主要动作；保存失败保留草稿，离线保留上次列表并标时间。
  4. 慢 / 空 / 失败 / 断线慢写「仍在保存…」；空写「这个项目还没有目录」；失败给原因与重试；断线标「离线 · 显示上次结果」。
  5. 键盘与焦点状态变化后焦点不丢：保存失败回「保存」，确认条回「取消」，离线时禁用控件仍可聚焦读原因。
  6. 离开再回来未保存的状态在离开前有确认；已保存的状态重新打开即服务器上的列表。

每条都写推荐和代价；只回不同意的编号就行。已经拍过板的写「已定」，不再重复问。

D1 这条放在哪个面

已定：工作目录块放在现有封面 /projects/:id 上，inline，从块打开编辑 sheet；不开新 tab、不加新路由。Mac 与手机都有。

代价：封面更长，手机上概览被往下推；换来的是不复制第二个项目页，也不破坏 KIN-PROJECT-001 D2 的单面结构。

D2 数据怎么读写

已定：复用 PATCH /api/projects/:id 的 roots，保存时发送完整有序列表（整体替换）；第一个 root 就是新对话的默认目录，「设为默认」= 移到第一位。

代价：没有局部更新接口，两个端同时改会以后保存者为准；换来零 schema、零新 API。

D3 移除目录时说什么

已定：明说后果：这个目录下的对话不再出现在这个项目下（仍在会话列表里），没有对话会被删除。不承诺删除对话。

代价：确认文案更长；换来的是不会有人以为移除目录等于清理对话。

D4 只承诺 API 能产生的状态

已定：不写「目录不存在 / 不可读」——当前没有对已保存 root 的文件系统检查端点。允许的状态只有：加载项目、没有目录、一个目录、多个目录、保存中、保存失败、离线 / 只读、未保存修改。

代价：移走磁盘上的目录时界面不会当场报警；换来的是不显示一个没人验证过的判断。

D5 工作目录块放在页头上面还是下面

推荐：放在页头（项目名 / 模式）与概览之间，先于摘要与最近活动。

代价：手机上前两屏看不到「最近发生了什么」；如果更看重继续对话，可以改到概览之后，但工作目录就会落到折叠线以下。这条听你的。
