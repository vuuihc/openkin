  • 为什么单独一条：封面已经把「发生过什么」和「由哪几个目录组成」讲清；「新对话该带着哪几条干活规则」是同一个容器上的第三件事，有自己的上限、截断、空态与编辑路径，装不进前两条。
  • 为什么不并进相邻故事：新对话怎么选项目归 START-001；项目改名、置顶、归档归 MANAGE-001；工作目录的增删与默认归 PROJECT-002；例行任务的调度与目录归 ROUTINE-001。这条只让「工作方式」这一段可见、可被对话修改、可被新对话收到。
  • job map：覆盖定义 / 定位 / 准备 / 确认 / 执行·监控 / 修改 / 收尾七步；每一步都有帧或流程，没有省略的段。
  • 设备只是差异：这条覆盖 Mac 和手机；块的位置与顺序相同，Mac 是左栏整宽、手机是单列 44px 行尾按钮，差异写在故事「各面差异」，不按设备拆故事。
  • 不在这一条：新的 tab / 路由 / 页面 → 明确不做（封面 inline）；新 schema / 表 / endpoint → 明确不做（复用 one-pager GET/PUT）；第二个编辑器 → 明确不做（编辑走对话，ADR 0013）；项目目录里的 AGENTS.md / CLAUDE.md → 未来故事（文件系统与 agent 自己的事）；项目记忆 → 未来故事；给运行中的对话补注入 → 明确不做。
  • 大小：1 个只读块 + 1 个对话启动器 + 1 段 digest 抽取/截断 + 1 个共用 helper；一次交付；两个面都成立；Go 单测、API 测、组件测、真浏览器与 390/1100 截图装得下，预计 6–8 个文件、约 350 行产品代码 + 测试（不含本页）。

现在

  • 新对话只收到 North Star、Current Focus 和最多三条 Next；「怎么干活」没有位置。
  • 把它塞进 Current Focus，就挤掉当下主线；每次重打一遍，对话一结束就丢。

之后

用户流程

  1. 起点从对话列表的项目标题或 /projects 集合进入封面；页头是项目名与模式。
  2. 动作不点任何东西，先读「一句话摘要」下面的「工作方式」块。
  3. 立刻看到块标题「工作方式」和一句「新对话开始时，Kin 会收到这段」；正文是原文，至多 400 字；标题右端是「让 Kin 改…」；下面才是最近活动，页面上没有多出 tab。
  4. 慢 / 空 / 失败 / 断线读取中与摘要共用骨架；没有这一段写「还没写工作说明」并给「让 Kin 写…」；读取失败走块内错误条与重试；离线显示上次缓存并标「上次结果」，启动器禁用并说明。

  6. 离开再回来回到封面仍是同一段原文，不闪空、不把截断脚注读成正文。
02 · Mac · 1100×760

让 Kin 改 · 新建对话已预填

Figma 帧

用户流程

  1. 起点封面工作方式块 →「让 Kin 改…」；跳到新建对话页，项目已选中。
  2. 动作读预填提示词，按需要增删，然后自己按发送；也可以直接返回。
  3. 立刻看到输入框里是选中的预填文本（读 ONE_PAGER.md 的「工作方式」、先复述现状、按我说的改、只改这一节）；没有任务开始跑，也没有任何保存发生。
  4. 慢 / 空 / 失败 / 断线新建页加载慢时保留导航结果并给加载态；离线或只读时封面上的启动器已禁用并写明原因；没有 One-Pager 文件时同一句预填，Kin 会新建这一节。
  5. 键盘与焦点到达后焦点在输入框文本末尾；Esc 不清空预填；返回封面时焦点回「让 Kin 改…」。
  6. 离开再回来预填只属于这次导航；回到封面，块内容没变——因为还什么都没保存。

手机 · 封面的工作方式块

用户流程

  1. 起点手机对话列表点项目标题推入封面；左上返回至少 44px。

用户流程

  1. 起点用户从任一端为这个项目开始一段新对话。
  2. 动作发送第一条消息，不经过封面。
  3. 立刻看到项目上下文里出现「How to work here」段，至多 400 字；与封面显示的是同一段原文；封面不弹提示。

状态也是 Figma 帧的一部分；先看状态板，再读它下面的流程与检查表。宽板在卡片内左右滑动。

用户流程

  1. 起点封面上的工作方式块，处在状态板中的任意一格。
  2. 动作读当前状态给出的下一步：写一段、重试、等加载、恢复网络或什么都不做。
  3. 立刻看到每一格都有明确文案与一个主要动作；截断写明只收到前 400 字；空态写明新对话不会收到这一段。
  4. 慢 / 空 / 失败 / 断线慢：与摘要共用骨架；空：还没写或没有文件；失败：原因 + 重试；断线：「离线 · 显示上次结果（时间）」，启动器禁用。

要你拍板的

每条都写推荐和代价；只回不同意的编号就行。已经拍过板的写「已定」，不再重复问。

D1 这条放在哪、数据放哪

已定：prompt-first，durable source 是项目自己的 ONE_PAGER.md——在文件里加一段有界的工作说明，让现有 digest 带上它。零 schema、零新端点、零新编辑器、零新 tab；块 inline 在现有封面上。

代价：工作说明和项目叙事共用一份文件，没有结构化字段可查询；换来的是它天然可被 agent 读写、可被用户直接编辑，也不新增任何持久化概念（PRINCIPLE 5.5、ADR 0013）。

D2 怎么改

已定：编辑走对话。封面只读，旁边一个「让 Kin 改…」按 ADR 0013 把预填提示词交给现有输入框；改的是同一份文件，不新造第二个编辑器。

代价：改一句话也要经过一次对话；换来的是不需要第二个 markdown 编辑器，也不会出现两份要同步的文档（TASTE 1、13）。

D3 标题叫什么、没有 One-Pager 文件时怎么办

推荐：主标题 ## 工作方式，别名 How to work here、Instructions；digest 按这三个名字找同一节。项目还没有 ONE_PAGER.md 时不合成任何说明——今天没有文件就没有项目上下文注入，封面就显示空态，由启动器让 Kin 新建这一节。

代价：用户写成别的标题（例如「工作说明」）时不会被注入，而且没有报错；换来的是不猜、不把别的小节冒充成工作说明。若你希望更宽松，可以加更多别名，但每加一个都要有测试。

D4 封面显示原文还是普通小节视图

推荐：显示 agent 实际会收到的原文——同一段、同一个 400 字上限，同一句截断脚注。封面不做「展开全文」，其余内容留在 ONE_PAGER.md。

代价：长说明在封面上看起来是断的，用户要判断「剩下的在文件里」；换来的是封面不承诺 agent 收不到的东西（PRINCIPLE 5.6）。

D5 块放在哪

推荐：紧贴「一句话摘要」下面、「最近活动」上面；Mac 在左栏，手机同一顺序。摘要回答「这是什么」，工作方式回答「怎么干活」，最近活动回答「刚发生了什么」。

代价：手机上最近活动被再往下推一屏；如果你更看重「从上一段继续」，可以放到最近活动之后，但工作方式就会落到折叠线以下。这条听你的。

D6 启动器写什么、预填还是直接开跑

推荐：按钮写「让 Kin 改…」（空态写「让 Kin 写…」），跳到新建对话、项目已选中、提示词已预填并选中；用户看完再按发送，任务不会自己开始。

代价：多一步「发送」；直接开跑少一次点击，但用户看不到、也改不了即将发送的提示词。这条听你的。
