# KIN-CONTINUE-004 · 手机列表：按最近活动排设备、每设备新建、搜索收成放大镜

## 谁、什么时候、为什么

当我早上拿起手机，想接着问昨天那段对话，或想在一台最近才用过的机器上开一段新的，我想设备按最近活动排序、每台设备标题旁就能新建、搜索收成一个放大镜，以便不用先在本机/在线的固定顺序里找机器，也不用让一整行搜索框常年占掉列表的第一屏。

这是 RSI `R-phone-list-story` 的合同。方向已于 2026-11-20 16:51 由 Ethan 拍板：「那按你的建议来吧」——CSS 玻璃先行、不写原生 bar、列表取便宜的一刀。本条只把列表这一刀钉死；底栏玻璃是页面上的唯一待决问题。

## 现在

今天手机列表已经能做到设备 → 项目 → 对话，但四个地方与目标不符（行号以 2026-11-20 的 `main` 为准，若漂移以代码为准）：

- **设备顺序固定**：`ui/src/lib/phoneSessionBuckets.ts:563` 先按 `isSelf`、`:564` 再按 `online`、最后才按 `lastActivityAt`。本机永远第一；一台昨天刚用过的远程机器会排在一台在线但一周没动的机器后面。
- **没有会话的设备根本不出现**：`ui/src/components/sessions/SessionList.tsx:564-584` 的 `deviceGroups` 只从会话 buckets 生成，`machines` 只用来补 label / online。一台刚连上、还没有对话的机器在列表里不可见，也没有入口在它上面新建。
- **新建只有头部一个入口**：`ui/src/components/mobile/SessionsHeader.tsx:55-66` 是标题 +「新建对话」+ 整行 `SessionsSearch`。新建总是落在当前默认设备；要指定机器得进新建页再改。
- **底栏是实色、四个带文字的入口**：`ui/src/components/layout/PhoneFooter.tsx:54` 的 `bg-kin-sidebar` 与 `:94` 的文字 label。**本条不改它**，见「范围」与页面上的唯一问题。

每设备新建的数据通路已经在了：`ui/src/lib/draftChat.ts:49` 的 `setDraftMachine`，`ui/src/pages/NewChatPage.tsx:170` 读取 `getDraftMachine()`；远程项目行今天已经会设置它（`SessionList.tsx:1072`）。所以这一刀大半是接线与排序，不是新模型。

## 范围

- 做：
  1. 设备按最近活动排序：`lastActivityAt` 倒序；本机只做并列时的 tiebreak（同为 0 时本机在前），在线状态不再抬升设备。
  2. 没有会话的设备也显示：设备标题 +「还没有对话」+ 新建；不展开项目，不画假的空行。
  3. 每台设备标题旁一个次级「新建」动作：点它就在那台设备上开草稿（`setDraftMachine` + 该设备最近项目 cwd / 首个根目录 / 空），返回落回列表原位置。
  4. 离线设备的新建禁用并就地说明原因；设备本身仍然显示，已有对话仍可打开（只读历史）。
  5. 手机头部搜索收成右上角放大镜：点开仍是同一个 `SessionsSearch`，仍写 `?search=`，清空、焦点返回、系统返回都不变；有搜索词时不允许把字段藏起来。
  6. 头部「新建对话」保留：空列表、无设备、或用户不想指定机器时仍需一个默认入口。
- 不做：
  - 底栏的颜色、玻璃、纯图标、入口数量：这是页面上的唯一待决问题；若 Ethan 选「并入」，另按答案改写范围与 CONTINUE-002 迁移，不在本轮偷偷做。
  - 设备内扁平化、项目名变成行副标题：下一条故事；`IA.md` 的「设备 → 项目 → 对话」在草稿阶段不改。
  - 行样式、diff 统计、筛选 chips、T3 的环境/项目筛选：没有故事，先不做。
  - Mac 左栏：布局、排序与搜索框都不变；它和手机共用 `SessionList`，本条只允许在手机壳上加行为，由 `Sidebar.dom.test.tsx` 回归守住。
  - 新建页表单本身（`KIN-START-001`）、项目分组内部排序（`lib/sessionBucketOrder.ts`）、接口、存储键、依赖。

签字交付时同步迁移 `KIN-CONTINUE-002` 的步骤 1：把「顶部搜索框」改成「右上放大镜，点开是同一个搜索字段」，J1 走查加一步「点放大镜」；头部新建那一句不变。`docs/product/IA.md` 在草稿阶段不改。

## 每一步的预期

### 1. 定义：打开列表，先认出哪台机器最近在用

| 项 | 预期 |
|---|---|
| 起点 | 手机上打开 `/sessions`（冷启动或从底部「对话」回来），列表有数据 |
| 动作 | 不点任何东西，先扫一眼设备标题 |
| 立刻看到 | 设备按最近活动倒序：最近有对话的机器在最上面；每台设备标题右侧有一个 44px 的次级「新建」按钮；本机不再被强行置顶，只在最近活动相同时排在前面；右上角是放大镜 |
| 慢 / 空 / 失败 / 断线 | 首次加载先出设备标题骨架；读失败保留头部与放大镜，给「重试」；断线时顶部横幅，已加载的分组不清空；一台设备都没有时说「还没有连接设备」并指向 Agent 运维 |
| 键盘与焦点 | 不自动弹键盘；外接键盘 Tab 顺序：头部新建 → 放大镜 → 每台设备的新建 → 项目折叠箭头 → 行；焦点环用 focus-ring token |
| 离开再回来 | 设备顺序与滚动位置保留；重连后刷新活动时间，若顺序变了，保持当前滚动锚点不跳 |

### 2. 定位：在设备 → 项目 → 对话里找到那一段

| 项 | 预期 |
|---|---|
| 起点 | 列表默认态，多台设备 |
| 动作 | 滚动，展开项目，点一行 |
| 立刻看到 | 每台设备下的项目与行都不变（行仍按 `at` 倒序、项目仍按 pin/active 规则）；没有会话的设备只显示标题与「还没有对话」，不显示折叠箭头 |
| 慢 / 空 / 失败 / 断线 | 项目内没有匹配行时保留设备标题，不让整段消失；行数据读失败时该设备下给一行「读取失败，重试」，其他设备不受影响；断线时行仍可打开（历史可读） |
| 键盘与焦点 | 设备标题不是 Tab 停点；Tab 从设备的新建到第一个项目箭头；行内动作沿用 KIN-MANAGE-001；打开对话再返回，焦点回到刚才那一行 |
| 离开再回来 | 折叠状态、搜索词、滚动位置保留；回到列表时设备顺序不因一次进对话而重排（活动时间刷新在行返回之后，且不抢滚动） |

### 3. 准备：在设备标题旁新建

| 项 | 预期 |
|---|---|
| 起点 | 某台在线设备的标题行，右侧「新建」次级按钮 |
| 动作 | 点这台设备的新建 |
| 立刻看到 | 先 `setDraftMachine(设备 id)`，再推出新建页；新建页的设备选择已经是这台机器，项目优先用它最近用过的 cwd，没有则用它报告的第一个根目录，再没有就留空并聚焦项目输入；列表留在下面不重新加载 |
| 慢 / 空 / 失败 / 断线 | 设备刚变离线时按钮禁用并写「离线，连上后可在本机新建」；设备列表加载中不出现新建按钮（避免点到一个还没确认的机器）；设备被吊销后草稿页按 START-001 的「机器不在了」路径回本机并保留提示词 |
| 键盘与焦点 | 按钮可 Tab 到，Enter/Space 触发；44×44 最小触达；aria-label 是「在设备名上新建对话」，读屏能听到是哪台；返回后焦点回到这台设备的新建按钮 |
| 离开再回来 | 关闭草稿直接回列表，设备、项目、提示词草稿保留；再次打开新建页仍是上次选的设备，除非从另一台设备的新建进入 |

### 4. 确认：搜索收成放大镜后仍然搜得到

| 项 | 预期 |
|---|---|
| 起点 | 列表默认态，右上角放大镜；地址栏没有 `?search=` |
| 动作 | 点放大镜；输入「发布」；点清除；按 Esc |
| 立刻看到 | 点放大镜后，标题下展开 `SessionsSearch`（不是第二个控件），焦点在输入框；输入即时过滤列表，地址栏变成 `?search=发布`；清除按钮只清词不收起；清空后按 Esc 或再点放大镜收起，焦点回到放大镜 |
| 慢 / 空 / 失败 / 断线 | 没有匹配时说「没有匹配的对话」并给「清除搜索」；搜索不发起网络请求，断线不影响过滤；带 `?search=` 冷启动时字段直接展开、放大镜显示激活态 |
| 键盘与焦点 | 放大镜是 44px 按钮，带 `aria-expanded`；展开后 Tab 进入输入框；Esc 先清词（有词时）再收起（无词时）；收起后焦点回放大镜，不落回页面顶部 |
| 离开再回来 | 刷新或从对话返回，`?search=` 与展开态都保留；有词时不允许收起成看不见的过滤条件；点底部别的入口再回来，搜索词仍按 CONTINUE-002 的记忆规则恢复 |

### 5. 执行：从新建页开始，落到那台设备

| 项 | 预期 |
|---|---|
| 起点 | 新建页，设备已经是刚才那台 |
| 动作 | 写提示词，按开始 |
| 立刻看到 | 草稿带着设备与 cwd 创建；进入对话页；返回一步落回列表，且这台设备因为刚有活动升到最上面 |
| 慢 / 空 / 失败 / 断线 | 设备离线、没有可用 agent、断线时「开始」禁用并就地说明；创建失败留在新建页，提示词不丢；离线设备的入口本来就不给进，直达 `/new` 时仍按 START-001 的禁用规则处理 |
| 键盘与焦点 | 开始后焦点在对话输入框；返回后焦点回到这台设备的新建按钮或刚才的行；⌘Enter 仍可开始 |
| 离开再回来 | 草稿、设备、项目、模型与权限保留；列表搜索与滚动位置不变 |

### 6. 监控：空列表、无会话设备、离线、断线

| 项 | 预期 |
|---|---|
| 起点 | 列表处于空、无会话设备、离线或断线之一 |
| 动作 | 等、重试、或直接点某台设备的新建 |
| 立刻看到 | 空列表：「还没有对话」，头部新建仍在，下面仍列出已连接设备及各自的新建；无会话设备：标题 +「还没有对话」+ 新建；离线设备：标题 + 离线标记，新建禁用并写原因；读失败：保留头部与放大镜，给「重试」；断线：顶部横幅，内容不清空 |
| 慢 / 空 / 失败 / 断线 | 加载中不显示「还没有对话」；重试保留搜索与滚动；断线恢复后自动刷新设备活动时间；任何状态都不藏起头部新建与放大镜 |
| 键盘与焦点 | 重试可 Tab 到；失败不抢焦点；断线横幅 `role=status`；禁用按钮用 `aria-disabled` 且原因在可达文本里，不靠 title |
| 离开再回来 | 重试后回到同一位置；断线恢复后顺序可能变化，保持当前可见行不跳走 |

### 7. 修改与收尾：返回、取消、换一台

| 项 | 预期 |
|---|---|
| 起点 | 从某台设备的新建返回，或搜索中途离开 |
| 动作 | 关闭草稿、清空搜索、或点另一台设备的新建 |
| 立刻看到 | 关闭草稿回到原列表位置，焦点回原设备的按钮；清空搜索后列表恢复全量，放大镜可收起；点另一台设备的新建会把草稿设备改成那一台（提示词保留，项目若不属于那台机器则清空并说明） |
| 慢 / 空 / 失败 / 断线 | 关闭后列表不重新加载；切设备时断线仍允许改草稿设备与提示词，只是开始禁用；设备在草稿期间消失时按 START-001 回本机并提示 |
| 键盘与焦点 | Esc 关草稿由 START-001 负责；本条只保证返回后焦点回触发点；搜索的 Esc 见第 4 步 |
| 离开再回来 | 列表的搜索、折叠、滚动、设备顺序都保留；草稿设备保留；不会因为一次取消多出第二层历史 |
