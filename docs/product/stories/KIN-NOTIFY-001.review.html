KIN-NOTIFY-001 · 这条
本页
  • 为什么单独一条：它不依赖打开哪个页面，既不属于「接着问」，也不属于「设置」。
  • 为什么不并进设置：设置管默认值；这条管离开后叫不叫、点开落到哪。设置页只是权限和状态的入口。
  • 设备只是差异：Mac 和手机一条故事；差异写在「各面差异」，不拆成两条，免得同一条要求写两遍、漏一遍。
  • 不在这一条：iOS 锁屏批准/拒绝 → KIN-NOTIFY-002；按事件开关、免打扰 → KIN-SETTINGS-001；Android 原生推送不做；UI base URL / 额度阈值不动。删除 Bark / ntfy / Web Push 在这一条里做。
  • 不改什么：通知的触发条件、文案语义、收件箱路由沿用今天；APNs 私钥不进设置页、导出或日志。
  • 大小：6 步、8 屏；一次交付；两端都成立。

现在 → 之后

现在

  • Mac 只弹批准和任务终态；提问、额度、例行报告没有原生通知。
  • iPhone 壳里没有 APNs，也没有 Web Push；设置页说“这个浏览器不能接收推送”。
  • 节点只有 Bark / ntfy / Web Push 扇出，没有设备登记、没有 APNs，也没有“这台设备能不能收到”的状态。

之后

  • 两端都用各自的原生通知中心；六类事件走同一条管道。
  • 点通知落到收件箱的那一条；设置页第一块是“这台设备”。
  • Bark / ntfy / Web Push 删除，升级时清理旧配置；浏览器控制台和 Android 不再收到 Kin 通知。
  • 通知丢了不影响收件箱；发送成功不等于看到。

01 · Mac · 1100×760 · 步骤 1 / 4

设置 → 通知 · 这台 Mac

Figma 帧

用户流程

  1. 起点菜单栏 Kin → 设置 → 通知。页首只有“这台 Mac”，没有“其他通道”。
  2. 动作点“在这台 Mac 上启用”；第一次由 macOS 弹通知权限；点“发送测试”验证。
  3. 立刻看到按钮从“正在登记…”变成“已开启”；同一块写 macOS 权限、最近一次成功/失败、会收到的六类事件；测试结果按这台设备列出。
  4. 慢 / 空 / 失败 / 断线权限被拒 → “被系统阻止” + “打开系统设置”；节点离线 → “连不上节点” + 重试；测试 10 秒无回执 → 说清超时和原因；没有设备 → “还没有设备” + 启用入口。
  5. 键盘与焦点Tab 依次到启用、发送测试、系统设置；触发后焦点留在状态行；Space / Return 可操作；VoiceOver 读状态和下一步。
  6. 离开再回来状态跨启动保留；已开启不再显示“启用”；从系统设置返回重新读权限，不缓存过期的“已开启”。

Figma 帧

用户流程

Figma 帧

用户流程

  1. 起点Kin 在菜单栏或后台；节点事件到达。通知不改变窗口状态。

十种状态 · 设置页和通知列表

Figma 板

状态流程

  1. 起点新安装，或刚打开设置 → 通知：未开启。
  2. 动作点“在这台设备上启用”；系统可能弹权限。
  3. 立刻看到登记中 → 已开启；或者落到被系统阻止、节点缺 APNs 凭据、测试失败、离线、没有设备。

在 Figma 板上看 D1–D5

先解释两个词

APNs（Apple Push Notification service）：苹果的推送服务器。iPhone 上的应用退到后台后自己弹不出通知，必须由苹果代送；节点要发，就得先在苹果开发者后台做一把专用钥匙（APNs 凭据），由节点管理员配置一次。没有这把钥匙，节点就发不到 iPhone。

设备 token：这台 iPhone 向苹果登记后拿到的一串地址，节点靠它把通知送到这一台手机；重装应用或恢复备份会换新的，旧的要删掉。

D1 删除 Bark / ntfy / Web Push 吗？

已定：删除。原生是 Mac/iPhone 的唯一通道；设置页不再有第二套通道，节点不再维护第二套扇出。升级时清理旧配置，不留回退开关。

代价：浏览器控制台、Android 和其他设备不再收到 Kin 通知；如果以后要，另开故事。

D2 APNs 凭据放在哪？

已定：放在节点，由节点管理员用 CLI 配置；设置页只显示“已配置/未配置”和最后一次错误。

代价：管理员要配一次；换来私钥不进 GET /api/settings、导出或日志，登记和发送在同一个 daemon。谁运行任务引擎、发通知，token 和凭据就登记在谁那里；Hub 只转发控制台请求，不能把 token 只留在另一台机器上。

D3 iOS 锁屏一键批准/拒绝现在做吗？

已定：不做，归 KIN-NOTIFY-002。先把“叫得到、点得开”做稳。

代价：锁屏上只能点开再批准；换来避免权限、审计和误触一起上。

D4 Mac 通知由谁触发？

已定：节点统一扇出；桌面壳只负责显示和点击。同一个事件管道产出 APNs / 桌面原生两路。

代价：节点多一条扇出路径；换来提问、额度、例行报告不漏，两端不各写一套触发条件。

D5 事件范围？

已定：六类事件全走同一条管道：批准、提问、任务终态、额度、例行报告、worker 离线；验收重点前三类。

代价：测试面更大；换来后续加事件不用再开一条故事。
