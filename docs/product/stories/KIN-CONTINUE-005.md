# KIN-CONTINUE-005 · 手机底栏：玻璃与纯图标，四个区域共用

状态：draft
优先级：P0
旅程：J1、J2
归属面：`IA.md`「手机底部导航」
面：手机

## 谁、什么时候、为什么

当我用手机在四个区域之间来回（接着问、看例行、管 agent、改设置），我想底部那条入口浮在内容上、像一层玻璃，四个入口只剩图标，以便一屏多留一点内容，同时仍一眼看出自己在哪、有几件事在等。

这是 RSI `R-phone-shell-story` 的 A 部分（合同 + 设计帧 + 账本）。D6（`KIN-CONTINUE-004.review.html:538`，CEO 2026-11-20）把底栏玻璃定为**单独的共享 shell 故事**；方向由 Ethan 2026-11-20 16:52 批准（CSS 玻璃先行，不写原生 bar）。本行只写故事与帧，`ui/` 一行不动；审阅页在 B 部分 `R-phone-shell-review`。

## 现在

底栏已经由四个 root 共用，行为与记忆都齐了，缺的只是材质与图标（行号以 2026-11-20 的 `main` 为准，若漂移以代码为准）：

- **实色条**：`ui/src/components/layout/PhoneFooter.tsx:54` 是 `bg-kin-sidebar` + `border-t`，内容不能从底下透出；挂在 `ui/src/components/layout/AppShell.tsx:716` 的 `!wide` 分支，四个区域根都有。
- **图标 + 文字**：`:82` 每个入口 `min-h-12`（48px），`:91` 的 `PendingBadge` 是「对话」链接内的计数标记，`:94` 常显 `tr(place.labelKey)` 文字；`:75` 的 `aria-current="page"` 标出当前区域。
- **材质已经在用**：`ui/src/index.css:745` 的 `.kin-glass`（panel 0.74 + `blur(24px)` + saturate）与 `:750` 的 `.kin-glass-float`（0.82 + `blur(28px)` + 描边 + 内侧高光）已用于头部与浮层；`:391` 的安全区花 `env(safe-area-inset-bottom)`，减弱透明与无 `backdrop-filter` 的回退已存在。`ui/src/lib/phoneNavigation.ts:273` 的 `PHONE_TAB_IDS`、`:341` 的 `phoneTabUrl`、`:429` 的 `returnListUrl` 决定顺序与各自回到哪里，本条不碰；`docs/product/IA.md:117` 的 D8 原写「四个同级入口」，本 PR 已同步为「四个同级图标入口（可访问名不变）」。

调研结论（`rsi/state/reports/2026-11-20-glass-and-session-list-research.md` §二）：CSS 能拿到八成观感——半透明、模糊、饱和、描边、内侧高光——但拿不到边缘折射；目标是并排看像，不是像素相等。

## 范围

- 做：
  1. 底栏表面从实色改为半透明玻璃：复用 `.kin-glass` 的填充与 `blur(24px)`，加 `.kin-glass-float` 同款的 1px 描边与内侧高光；不新造 token。底栏改为贴底悬浮的一整条：左右各 8px，底部在安全区之上再留 8px，圆角 22px；四个入口等宽，仍是最少 48px 高的触达。
  2. 四个入口从「图标 + 文字」改成「纯图标」；可访问名保持今天的四个名字（对话 / 例行任务 / Agent 运维 / 设置），读屏、Tab 与自动化选择器按名字仍能找到。
  3. 选中态不靠颜色单独表达：当前区域是实底胶囊 + 着色图标，其余是线性图标；`aria-current="page"` 不变。
  4. 等待数仍是「对话」链接内的一个标记，落在图标右上角；数字可读，不遮挡图标主体，不成为第二个控件；归零时消失，不显示「0」。
  5. 内容留白：列表与设置滚到底时，最后一行能完整滚到玻璃条上方至少 12px；底栏高度变化（等待数出现、安全区变化）不遮住内容。
  6. 回退与 zen：深色、`prefers-reduced-transparency: reduce`、不支持 `backdrop-filter` 时，表面变为近不透明（约 0.94）并保留描边，布局、图标、选中态不变，图标对比度仍 ≥ 3:1；zen 下底栏仍整体隐藏（`.kin-zen-hide` 不变），内容延伸到安全区，退出后选中态与区域记忆不变。
- 不做：
  - 原生 bar：`ui/src/native/*`、`mobile/` 不动，也不做边缘折射（调研 §二：CSS 做不到，方案 C 另议）。
  - 加/减入口、改顺序、改四个区域的路由、左右滑动、每个入口的返回记忆：`PHONE_TAB_IDS` / `phoneTabUrl` / `returnListUrl` 不改。
  - 主题色、`--kin-*` token 值、字体；Mac 的左栏与区域栏（Mac 没有底栏）。
  - 列表内容、头部搜索与新建、行操作：归 `KIN-CONTINUE-004` / `KIN-MANAGE-001`。
  - `PendingBadge` 的计数来源、`pendingCountsByTask`、接口、存储键、新依赖。

## 每一步的预期

### 1. 定义：打开任一区域，先认出自己在哪

| 项 | 预期 |
|---|---|
| 起点 | 手机上打开四个区域中的任意一个（冷启动、从通知或深链回来） |
| 动作 | 不点任何东西，扫一眼底部 |
| 立刻看到 | 底部一条悬浮玻璃，内容从下缘隐约透出；四个纯图标等宽；当前区域的图标是实底胶囊 + 着色，其余是线性图标；「对话」图标右上角若有等待，显示数字 |
| 慢 / 空 / 失败 / 断线 | 等待数还没读到时不显示徽标，不闪 0、不放骨架；断线时底栏本身不变，顶部横幅负责说明；深色或减弱透明下表面变近不透明，布局与图标不变 |
| 键盘与焦点 | 底栏不自动取焦；进入页面时焦点在内容，Tab 依次经过四个入口；焦点环在玻璃与回退表面上都可见（2px outline + offset） |
| 离开再回来 | 仍在同一区域；选中态从 URL 重建，不依赖一次过渡动画 |

### 2. 定位：在四个入口之间切换

| 项 | 预期 |
|---|---|
| 起点 | 任一区域默认态，底栏可见 |
| 动作 | 点另一个图标，或在内容空白区左右滑动 |
| 立刻看到 | 目标区域整页切换，选中胶囊立刻移到目标图标；底栏不重建、不闪白；目标区域按自己的记忆打开 |
| 慢 / 空 / 失败 / 断线 | 目标区域加载慢时先出它自己的骨架，底栏保持可点；断线时仍可切到已缓存的区域，未加载的给错误与重试 |
| 键盘与焦点 | 左右滑动不变；外接键盘 Tab + Enter/Space 触发；切换后焦点进入新区域标题，Shift+Tab 可回到底栏 |
| 离开再回来 | 每个入口仍回到上次的 URL（列表搜索 / 状态 / 归档、`?device=`、`?tab=`），逻辑不改 |

### 3. 准备：看清有几件事在等我

| 项 | 预期 |
|---|---|
| 起点 | 至少 1 件待批准或待回答，「对话」图标在底栏里 |
| 动作 | 看一眼「对话」图标 |
| 立刻看到 | 图标右上角一个小计数（1–9，更多显示 9+），不遮挡图标主体；数字与底色对比达标；计数变化就地更新，不弹 toast |
| 慢 / 空 / 失败 / 断线 | 未读到时没有徽标；读失败保留上一次已知计数直到下次成功，不显示 0；断线时保留最后已知计数，不假装清零 |
| 键盘与焦点 | 徽标不是独立控件，不进 Tab 序；读屏在入口名后播报「3 件在等」 |
| 离开再回来 | 计数随 pending 数据刷新；切区域不重置 |

### 4. 确认：玻璃上的图标仍然读得清

| 项 | 预期 |
|---|---|
| 起点 | 任意内容滚到玻璃后面（长列表、深色代码块、图片） |
| 动作 | 滚动页面，让深浅内容从底栏下穿过 |
| 立刻看到 | 图标与选中胶囊始终可辨；模糊让背后内容不形成干扰；1px 描边把底栏与内容分开 |
| 慢 / 空 / 失败 / 断线 | 开启减弱透明度或不支持 `backdrop-filter` 时表面近不透明、不模糊，图标对比仍 ≥ 3:1；深色主题同样成立 |
| 键盘与焦点 | 焦点环用现有 focus-ring token，在玻璃与近不透明回退上都可见 |
| 离开再回来 | 材质不因页面切换重新淡入；不对 `backdrop-filter` 做动画 |

### 5. 执行：内容不被底栏压住

| 项 | 预期 |
|---|---|
| 起点 | 列表或设置页滚到最底 |
| 动作 | 继续滚到底，打开最后一行 |
| 立刻看到 | 最后一行能完整滚到玻璃条上方（至少 12px 余量）；底栏不盖住行的操作；到底时内容不被裁切 |
| 慢 / 空 / 失败 / 断线 | 空态文字同样留出底栏高度，不与玻璃重叠；断线横幅出现时底栏不叠加成第二条 |
| 键盘与焦点 | Tab 到最后一个可聚焦元素时，浏览器把它滚进可视区且不被底栏盖住 |
| 离开再回来 | 滚动位置保留；底栏高度不因等待数或选中态变化 |

### 6. 监控：键盘、zen 与系统设置

| 项 | 预期 |
|---|---|
| 起点 | 搜索展开并弹起键盘 / 进入 zen / 切换减弱透明或深色 |
| 动作 | 输入搜索词、关键盘、退出 zen、切主题 |
| 立刻看到 | 键盘弹起时底栏不被顶到键盘上方，留在键盘后面；搜索字段与结果贴着键盘上沿；关键盘后底栏原位回来，搜索词与展开态不变。zen 下底栏整体隐藏，内容延伸到安全区；退出后底栏回来且选中态不变。减弱透明与深色即时生效 |
| 慢 / 空 / 失败 / 断线 | 键盘动画期间底栏不抖、不重排内容；zen 下断线横幅仍可见；不支持 blur 时走第 4 步同一回退 |
| 键盘与焦点 | Esc 收键盘后焦点回搜索框；zen 由现有入口控制，底栏不新增开关 |
| 离开再回来 | zen 状态按现有规则保留；底栏隐藏与恢复不改变区域、搜索与记忆 |

### 7. 修改与收尾：处理完等待，换主题、转屏也不变

| 项 | 预期 |
|---|---|
| 起点 | 有等待数，或位于某区域的深层页面；深色 / 浅色、竖屏 / 横屏、刘海机 / 无刘海机 |
| 动作 | 处理完最后一件事、返回到区域根、旋转屏幕或切换主题 |
| 立刻看到 | 计数减到 0 时徽标消失，不留空圈；当前区域的选中胶囊不变；点当前区域的图标仍回到它记住的 URL（今天的行为）。底栏始终在安全区之上再留 8px（无刘海时就是 8px）；横屏时左右也避开安全区；四个入口等宽，文字不参与布局所以不换行 |
| 慢 / 空 / 失败 / 断线 | 计数刷新失败保留旧值，没有等待时不出现「0」；断线时选中态不改、底栏不消失；安全区为 0 时不塌成贴边 |
| 键盘与焦点 | 徽标消失不抢焦点，焦点仍在原控件；横屏时 Tab 顺序不变，焦点环不被圆角裁掉 |
| 离开再回来 | 计数与选中态都从数据与 URL 重建；旋转或主题切换不改变区域、搜索、滚动位置 |

## 各面差异

| 面 | 这一面怎么呈现 | 为什么不同 |
|---|---|---|
| 手机 | 贴底悬浮玻璃条 + 四个纯图标入口，可访问名不变；内容从玻璃后透出，底部留出滚动空间 | 一屏只有当前区域，底栏是区域间唯一通道；纯图标把高度让给内容，玻璃保留方向感 |
| Mac | 没有底栏：用左侧区域栏（208px / 64px 图标栏）与 ⌘1–⌘4，布局、材质、图标都不变 | 底栏只属于手机壳；Mac 导航已由 S1 交付，并由 `AreaNavigation.dom.test.tsx` 守住 |

## Do not

- 不许做原生 bar、改 `ui/src/native/*` 或 `mobile/`，也不许为边缘折射引入 WebGL/快照。
- 不许加/减入口、改顺序、改四个区域的路由、左右滑动或返回记忆。
- 不许改主题色、`--kin-*` token 值、字体，或顺手动底栏以外的东西：Mac 左栏与区域栏、列表内容、头部搜索、新建、行操作（后者归 `KIN-CONTINUE-004` / `KIN-MANAGE-001`）。
- 不许把等待数做成第二个控件或独立按钮；它仍是指向列表的链接内部标记。
- 不许对 `backdrop-filter` 做动画，或让玻璃成为可读性的唯一来源（回退必须近不透明）。
- 不许把可访问名也省掉：图标可以常显，名字必须仍被读屏与 Tab 找到。
- 不许改 `pendingCountsByTask`、接口、存储键，或新增依赖。
