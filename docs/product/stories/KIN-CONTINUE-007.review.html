01 · 820×1180 · 粗指针 · 默认

默认列表：设备展开、项目折叠、十条对话同屏

Figma 帧

用户流程

  1. 起点竖着拿起 iPad，打开 Kin，落在 /sessions；左栏 304px，两台设备、四个项目、十条以上对话。
  2. 动作不点任何东西，先扫设备标题与项目标题；需要时点项目 Alpha 的工作方式披露行。
  3. 立刻看到设备标题一行；Alpha 展开并露出十条两行对话；Beta、Gamma 各一行标题；工作方式默认一行「工作方式 · 展开」；一屏十条完整行。
  4. 慢 / 空 / 失败 / 断线首次加载出设备标题骨架；项目读失败保留设备标题并给该组「重试」；断线顶部横幅、已加载项目与行不清空；没有项目时写「还没有对话」并指向头部新建。
  5. 键盘与焦点Tab 顺序：头部新建 → 搜索 → 设备新建 → 项目折叠箭头 → 打开项目的行；项目名不是停点，箭头才是；焦点环用 focus-ring token。
  6. 离开再回来折叠状态按项目记住，上次展开的仍是它；滚动锚点保留，不因一次返回跳回顶部。
02 · 820×1180 · 粗指针 · 一个项目展开

打开另一个项目：只开一个，工作方式可展开

Figma 帧

用户流程

  1. 起点Alpha 正展开，想看的对话在 Beta。
  2. 动作点 Beta 的折叠箭头；需要时再点 Beta 的工作方式披露行。
  3. 立刻看到Beta 在原地展开、Alpha 收起；工作方式展开后只多两句正文；行仍是两行一条，滚动位置不跳。

D1 一个列表组件，Mac 与手机共用

已定：同一个 SessionList，宽度只决定容器与溢出方式（IA.md:34、TASTE 1）。本条只在同一个组件里加行式与折叠默认。

D2 设备 → 项目 → 对话 三级不变

代价：比扁平列表多两层标题的垂直开销；用默认折叠与一行披露把它补回来。

D3 列表仍是唯一的对话列表

已定：归档与搜索是同一份列表的范围，不开第二份（TASTE 1、IA.md:34-40）。

代价：没有「最近对话」第二列表可以牺牲层级换密度。

D4 44px 地板在 768–1023.98 的去留

推荐：只把粗指针那条臂从 767.98 扩到 1023.98（pointer: coarse），宽度臂不动。2026-11-24 的测量里 820 的 shippedFloorMatches 是 false、注入后是 true，而项目名与标题宽度不变（126.5 / 97.7px）——扩展几乎不改今天的外观，它买的是「没写尺寸的控件也不会掉到 44px 以下」；AGENTS.md 规则 16 要求 820 的 44×44 来自粗指针检查，不是宽度断点。

代价：768–1023.98 的粗指针上每个 .touch-lg 控件都拿到 44px 地板；今天 820 的箭头与菜单本就显式 44×44，所以外观几乎不变，但将来任何一个漏写尺寸的控件会因此变高、可能减少一屏条数。窄窗口里的鼠标仍用紧凑密度。

D5 「默认折叠」到底折叠什么

推荐：设备保持展开；项目默认折叠，只打开「最近一条对话所在的项目」；展开项目的「工作方式」收成一行披露行。存过的折叠状态优先，返回时恢复。

代价：默认只看见一个项目的对话，比较另外两个项目要各点一次；换来一屏十条不被项目数吃掉，代价是失去「一眼看全所有项目」的概览。

D6 元数据行放什么、拿掉什么

推荐：第二行只放 agent 名 · 相对时间 · 一个状态（运行中 / 待批准 N / 例行 / 已完成）。拿掉行尾的设备名（设备已是分组标题）与单独的例行 chip；不加入模型名与 diff 计数。TASTE 2：对话只叫「对话」，agent 只出现一次。

代价：行内不再直接写设备名；想看模型或 diff 要打开对话。换来 97.7px 的标题变成完整一行、状态一眼可读。
