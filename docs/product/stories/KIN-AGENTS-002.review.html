三组，三个问题，三种写权限

同一个 tab 里正好三组，顺序固定。每组标题下一句规则，规则句就是这一组的写权限说明。

组一句话规则读什么写什么什么时候写
安装状态（探测） 自动读取，不改变任何东西 本机 provider、状态、原因、能力徽标、上次检测时间（/api/agent-providers、/api/agents） 不写 永不
导入会话 只在按下时发生，只写会话索引 同一份 provider 与能力元数据，但自己读，不依赖探测组的渲染 只写会话索引 只在按下行内「导入」或组底「立即导入会话」时
角色默认 保存后在新对话里用，不改变安装 daemon 设置键 agent_roles 同一个键，随页面的一次保存落盘 按下「保存会话设置」时

这个切法不包含什么

  • 不删 agents tab，也不把导入或角色搬走。删 tab 是删能力，不是删半成品检测（KIN-CONTRACT-001.md:40、KIN-AGENTS-002.md:134）。
  • 不重做整个安装检测。本故事只画边界；检测重做是 R-agents-detect 的后续，不在这条里改检测算法（KIN-AGENTS-002.md:13、:134）。
  • 不新增数据表、后端接口或状态机。用现有的 /api/agent-providers、/api/agents、设置保存与导入接口（KIN-AGENTS-002.md:139，PRINCIPLE §5.5）。
  • 不长成第二张 agent 管理表。完整列表、安装、更新、卸载、登录、smoke 与用量仍归 operations console（KIN-AGENTS-002.md:29、:138；KIN-AGENTS-001.md:24、:26）。

面这一面怎么呈现为什么不同合同行

要你拍板的

3 条待定，每条都有推荐和代价；只回不同意的编号就行。5 条已定来自合同，不再重复问。

D1 探测失败时，行留在屏上还是清空？

推荐：行留在屏上，状态不变，失败写在组头的一条横条里，时间戳停在旧值。合同已经要求「失败保留上次结果并说明」（:25、:84、:159），但没说失败提示放在哪；放在组头，行里的状态与能力徽标就不用逐行改写。

代价：旧状态看起来像新的，只能靠「上次检测 14:02」自证。若把行变灰，又会与「未检测到」混淆——两种都得靠文字，横条至少把原因集中在一处。

D2 导入组的 provider 元数据由谁读？

推荐：页面读一次，两个组各自渲染；探测组的「刷新检测」重发这一次读，导入组保留自己的读取入口。合同要求导入组不依赖探测组的渲染（:28、:160），所以删掉探测半之后，导入组仍能自己拿到 provider 与能力。

代价：共用一次读时，刷新会同时改变导入按钮的可用性，两组可能有一瞬间不一致；拆成两次读则多一次请求，还可能读到不同版本。推荐把「一次读」作为默认，把「导入组独立入口」作为删探测半时的退路。

D3 手机上行内「导入」放行尾还是收进菜单？

推荐：行尾常显，至少 44px；能力徽标换到单独一行。合同要求三句规则常显、行内按钮至少 44px（:126），并要求「这台机器的（provider 名）」写清楚（:72）。现有代码已经把能力徽标在窄屏换到独立一行（ui/src/components/settings/LocalAgentSettingsSection.tsx:133-150），沿用它即可。

代价：每行更高，手机一屏看到的行更少；收进菜单能省高度，但会把「按下才发生」的动作藏起来，正好撞上这条故事要说的边界。

S1 三组的顺序就是边界

已定：安装状态 → 导入会话 → 角色默认，顺序固定，不靠折叠表达（KIN-AGENTS-002.md:37、:39）。

代价：角色组在最底下，改角色要多滚一点；但把角色提到前面会让「自动读」和「只是保存」混在一起。

S2 导入只在按下时发生

已定：不自动导入、不自动接入；导入只写会话索引，不改源历史（:26、:135；KIN-AGENTS-001.md:125）。

代价：换了机器或新装了 agent，要自己按一次；少一次点击，也就少一次「它怎么自己多出来了」。

S3 角色是共享的提示词前缀

已定：存在 daemon 设置键 agent_roles 里，同一 daemon 的设备共享；不新增表、不同步、不改变模型或权限（:27、:141；internal/api/api.go:1788-1792）。

代价：两台 daemon 的角色不共享；角色只是文字，不会替人选中模型或权限。

S4 半写的角色行保存时丢弃

已定：没有名字或没有提示词的行，保存时被丢掉；已有覆盖在 ui/src/lib/agentRoles.test.ts:95-108（does not persist a row that would insert nothing）。

代价：只填了一半的行会静默消失；编辑器需要提示「保存时丢弃」，不能让用户以为它被存下了。

S5 「上次检测」用现有的时间戳

已定：直接显示 AgentProvider.last_scanned_at（ui/src/api/client.ts:559，daemon 在每次扫描时写入口径见 internal/server/agents.go:57、:105）；没有值就写「从未」。合同要求显示时间但不要求新字段，且不允许新增后端接口（KIN-AGENTS-002.md:61、:139）。

代价：它表示「这台 daemon 上次读 provider 的时间」，不是「provider 自己刚刚变了」；跨时区或重启后要按本机时间格式化。
