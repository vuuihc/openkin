  • 为什么单独一条：改名、置顶、多选、归档、删除是同一个人在同一份列表上做完的一件事，共用一个行菜单、一套确认与取消、一套「离开再回来」。
  • 为什么不并进相邻故事：CONTINUE 从「打开一段对话」开始；PROJECT 管项目行的置顶、封面和归档。把对话行的菜单塞进任何一条，都会让那份合同同时说两层的事。
  • Job map 覆盖：定义/打开＝第 1 步，定位＝第 2 步，准备＝第 3 步，多选＝第 4 步，执行＝第 5 步，修改＝第 6 步，监控＝第 7 步，收尾＝第 8 步；八段都有落点，没有「先做 Mac 再做手机」。
  • 设备只是差异：Mac 是贴行菜单 + 248px 侧栏，手机是底部动作面板 + 390 列表；入口、菜单项、退出路径和文案是同一套，差异写在故事「各面差异」。
  • 不在这一条：拖拽排序 → R-drag-reorder（gap-log.md 2026-11-15 中条）；批量改名 → 本版不做，已有的批量置顶 / 归档（含已归档下的恢复）/ 删除保持；回收站 / 撤销 → 不做，归档是安全网；后端、API 与同步协议 → 不碰——改名和置顶跟 taskPins.ts 一样只写浏览器 localStorage，搜索在本地与服务端结果合并。
  • 四条大小自检：① 标题只含一个动作（整理）；② 一个人一台设备一次能走完（开菜单 → 改名/置顶/多选 → 归档/删除 → 退出）；③ 一次交付装得下测试、复审和 390/1100 截图；④ 8 步 ≥ 3 步，验收每行都能写成 Given / Then。

现在 → 之后

现在

  • 实测（2026-11-15）：iPad 的 248px 左栏走触屏路径，多选工具条约 400px 宽——三个批量动作的标签按视口断点全部展开，四个按钮各自 min-w-11；最右边的「取消」被推出可视区，只能横向滚动列表才够得到。
  • 当时键盘只有 ↑/↓，Esc 不退出；进入多选后行尾没有 ⋯，没有任何就地出口。报告人原话：「不知道怎么退出」。工具条换行与 Esc 已在 PR #62 修好，行菜单的「多选 / 退出多选」已在 PR #170 修好。
  • 仍然缺的：长按直接进入多选，没有先开这一行的菜单；改名还没有；置顶已有，但两个面的入口还不一致。

之后

  • 工具条在 248px 和 390px 都折成两行放下，退出始终可见且至少 44px；Esc 退出并把焦点还给发起行。
  • 每一行的 ⋯ 菜单都有「改名 / 置顶 / 多选 / 归档 / 删除」；多选状态下同一个菜单变成「退出多选」。
  • 长按打开这一行的菜单，不再直接进入多选；改名在行内完成，置顶与改名、多选排在同一个菜单里。

01 · Mac · 1100×760

行菜单：一段对话的全部整理动作

Figma 帧

用户流程

  1. 起点Mac 左栏把对话按 设备 → 项目 排好；鼠标移到一行，行尾出现 ⋯，标题和最近时间都在。
  2. 动作点行尾 ⋯，或在行上右键。
  3. 立刻看到贴行弹出菜单：改名 / 置顶 / 多选 / 归档，分隔线后是警示色的删除；第一项带焦点环，行标题仍看得见。
  4. 慢 / 空 / 失败 / 断线菜单立刻出现，不等网络；正在运行的对话在菜单顶部多一句「正在运行」，归档和删除仍可用；断线时归档照常点、进本地队列，删除禁用并说明原因。
  5. 键盘与焦点打开后焦点在第一项；↑/↓ 移动，Enter 执行，Esc 关闭并把焦点还给这一行；菜单外的行不被 Tab 走到。
  6. 离开再回来菜单关闭，没有副作用；再打开仍指向同一行、同一位置。
02 · Mac · 1100×760

多选：248px 侧栏里的工具条

Figma 帧

用户流程

  1. 起点248px 左栏，某一行菜单里选「多选」；这一行立刻选中，工具条出现在搜索框下方。
  2. 动作点其它行加选或减选；点「退出多选」，或按 Esc。
  3. 立刻看到工具条折成两行：第一行「已选 N 项」和退出多选，第二行 置顶 / 归档 / 删除；行左侧出现勾选圈，选中的行有底色；侧栏没有横向滚动条。
  4. 慢 / 空 / 失败 / 断线批量动作进行中按钮禁用并显示进行中；部分失败只保留失败项并说明；断线时归档排队、删除不可用；0 项时批量按钮禁用，退出仍可用。
  5. 键盘与焦点Tab 进工具条；Esc 退出并把焦点还给发起行；↑/↓ 换行；Shift+Enter 仍从行进入多选。
  6. 离开再回来退出即清空选择；归档或删除后滚动位置不跳回顶部；再进入从 0 项开始。
03 · 手机 · 390×844

行菜单在手机上是底部动作面板

Figma 帧

用户流程

  1. 起点手机列表页，设备 → 项目 → 对话，行高至少 44px。
  2. 动作长按一行约 500ms，或点行尾 ⋯。
  3. 立刻看到底部动作面板：标题是对话标题，下面是「项目一 · 本机」；条目 改名 / 置顶 / 多选 / 归档，分隔线后是红色 删除，最下面单独一块 取消。
  4. 慢 / 空 / 失败 / 断线面板立刻出现；正在运行的对话多一句「正在运行」；长按期间位移超过 8px 就取消长按、改回滚动；断线时归档排队、删除禁用并说明。
  5. 键盘与焦点打开即聚焦第一项，焦点困在面板内；每个条目至少 44px；外接键盘 Esc 关闭并回原行。
  6. 离开再回来点外面或「取消」关闭，无副作用；面板不记忆上次选项。
04 · 手机 · 390×844

多选：390 列表里的工具条

Figma 帧

用户流程

  1. 起点手机列表，从行菜单选「多选」；这一行选中，工具条贴在列表顶部。
  2. 动作点其它行加选或减选；点「退出多选」，或用外接键盘按 Esc。
  3. 立刻看到第一行「已选 2 项」和退出多选，第二行 置顶 / 归档 / 删除；选中行有勾和底色；页面与工具条都不横向滚动。
  4. 慢 / 空 / 失败 / 断线同 Mac；批量删除的确认框写明「删除后不能恢复」；删除中按钮显示「删除中」；部分失败保留失败项并说明。
  5. 键盘与焦点每个按钮至少 44px；Esc 退出并回发起行；读屏读出「已选 N 项」和每一行的选中状态。
  6. 离开再回来退出清空选择；滚动位置保留；归档的行从当前范围消失，已归档里出现。

用户流程

  1. 起点列表在冷启动、刚刷新、断线，或某段对话正在跑的时候打开；也可能正在行里改名。
  2. 动作看每一格，或在行里改名。
  3. 立刻看到空有新建；加载是骨架且不跳版；失败有原因和重试；断线时已加载的行不清空、顶部提示、归档排队可见；运行中的菜单多一句「正在运行」；改名在行内变成输入框并全选当前标题。

要你拍板的

每条都写推荐和代价；只回不同意的编号。D1 和 D3 已经拍过板，写出来是为了让后来的人知道为什么。

D1 长按现在打开行菜单，拖动排序以后再接管这个手势

已定（2026-11-17）：长按一行 500ms 打开这一行的菜单；从菜单选「多选」进入多选。拖动排序（R-drag-reorder）落地后由它接管长按；在那之前，长按不得把人带进一个没有可见出口的状态。

代价：进入多选多一步（先开菜单，再点「多选」）；换来长按不再被一个退不出的模式占用，两条故事也不用互相等。

D2 248px 工具条折两行、保留文字标签

推荐：第一行计数与「退出多选」，第二行「置顶 / 归档 / 删除」；按钮保留文字，不缩小字号、不横向滚动。390 手机用同一套折行规则。

代价：列表顶部固定多占约 44px 高；换来每个动作都读得懂。现已合入的图标版（PR #62）能放下一行，但第一次用的人要先认图标。

D3 Esc 退出多选并把焦点还给发起行

已定（gap 2026-11-15）：Esc 与「退出多选」走同一条退出路径，清空选择，焦点回到发起多选的那一行；Shift+Enter 进入多选的行为保留。

代价：搜索框里的 Esc 仍归搜索框，只有列表有焦点时 Esc 才退多选；换来键盘用户永远有一条确定的路。

D4 退出即清空选择；菜单里的「多选」选中它所在的那一行

推荐：退出多选就清空选择；从某一行的菜单点「多选」，该行立刻处于选中态。多选状态下同一个菜单只显示「退出多选」。

代价：不能「先选几行、退出看一眼、回来接着选」；换来进入多选时永远至少有一行，「多选模式但什么都没选」不会出现。

D5 改名留在行内，不弹第二层对话框

推荐：Mac 和手机都在行内把标题变成输入框、全选当前标题；Enter 确认，Esc 取消且不改；改名和置顶一样只写本机浏览器（localStorage），立即生效、没有网络重试；浏览器拒绝存储时提示并保留旧标题。

代价：390 的窄行编辑长标题时输入框只能横向滚动；改名不跨设备，换一台机器看不到，与置顶一致；换来改一个名字不需要多一层页面，不需要新的后端接口，也不会分成「改名页」和行内两套实现。
