# KIN-PROJECT-003 · 项目的工作说明：新对话一开始就知道这里怎么干活

状态：covered
优先级：P1
旅程：J4
归属面：`IA.md`「项目」行（对话列表里的项目标题 → `/projects/:id` 封面上的「工作方式」块）
面：Mac、手机

## 谁、什么时候、为什么

当我有一个反复干活的目录（有固定的构建命令、不许手改的生成文件、动手前必须先读的文档），我想把「在这里怎么干活」在项目里写一次，让每个新对话一开始就带着它，以便我不用每次重打一遍，也不用指望自己记得。

## 现在

`ONE_PAGER.md` 是用户拥有的项目文档，`GET/PUT /api/projects/:id/one-pager` 读写整份 markdown（`internal/api/api.go:567-568`，上限 1 MiB）；带项目的新对话在创建时由 `maybeInjectProjectContext` 注入，只对机器持有者生效，`BuildContinuePrompt` 从 One-Pager 里取 North Star、Current Focus 和最多三条 Next，整段以 1200 字为上限（`internal/store/onepager.go:302-334`、`internal/api/projects.go:681-737`）。没有一段装「怎么干活」：它既不在新对话的项目上下文里，封面上也没有它的位置。用户只能把「先跑测试、别手改生成文件」塞进 Current Focus，挤掉当下主线，或者每次新对话重打一遍——后者随对话结束就丢。Lody 在会话开始时发送项目说明（`docs/plans/2026-11-02-lody-parity-gap-report.md` §7），这是要补的差。

产品选择（CEO，2026-11-18）：**prompt-first，durable source 是一份文件**——在 `ONE_PAGER.md` 里加一段有界的工作说明，让现有 digest 带上它；零 schema、零新端点、零新编辑器、零新 tab。编辑走对话（ADR 0013），封面只读并给一个启动器。

## 范围

- 做：在 `ONE_PAGER.md` 里约定一段有界的工作说明（工作标题 `## 工作方式`，别名 `How to work here`、`Instructions`）；新项目模板带一个空段，已有项目不迁移；`ParseOnePagerSummary` / `BuildContinuePrompt` 把这一段（至多 400 字）带进新对话的项目上下文，整段仍在现有 1200 字预算内；封面加一个只读的「工作方式」块，正文就是新对话会收到的原文（空、截断各有说法），旁边一个「让 Kin 改…」把预填提示词交给现有输入框。
- 不做：新的 tab、路由、页面（块 inline 在现有封面，KIN-PROJECT-001 D2）；新的 schema、表或 API（读写仍走现有 one-pager GET/PUT 与项目记录）；第二个 One-Pager 编辑器或独立的工作说明表单（改它走对话，或直接编辑文件）；每项目设置项、开关、模板库、推荐提示词；自动生成或在刷新封面时改写工作说明（它与 North Star 同级，属于用户）；读取或编辑项目目录里的 `AGENTS.md` / `CLAUDE.md`（那是文件系统里 agent 自己的事，归未来故事）；把说明补写进已经开始的对话（只影响新对话创建）；`.gitmodules` 自动发现、跨设备同步（各自归 KIN-PROJECT-002 列出的未来故事）。

## 每一步的预期

### 1. 定义 / 打开：封面上这一段是什么

| 项 | 预期 |
|---|---|
| 起点 | 项目封面（从对话列表的项目标题或 `/projects` 集合进入），页头下方 |
| 动作 | 读「一句话摘要」下面的「工作方式」块，不点任何东西 |
| 立刻看到 | 块标题「工作方式」，一行说明「新对话开始时，Kin 会收到这段」；正文是新对话实际会收到的原文，至多 400 字；块标题右端一个「让 Kin 改…」；页面上没有多出 tab 或第二份文档列表 |
| 慢 / 空 / 失败 / 断线 | 项目或 One-Pager 读取中：块与摘要共用骨架，不先画「还没写」；没有这一段：正文位置写「还没写工作说明」，并给「让 Kin 写…」；读取失败：块内错误条与重试，不猜内容；离线：显示上次缓存的那段并标「上次结果」，启动器禁用并说明 |
| 键盘与焦点 | Tab 从摘要的「编辑」到「让 Kin 改…」，再到最近活动；块读成标题为「工作方式」的 region；正文不是需要滚动的内嵌框，完整 400 字随页面滚动 |
| 离开再回来 | 回到封面仍是同一段原文，不闪空、不把脚注当正文 |

### 2. 定位：它和 North Star、Current Focus 各管什么

| 项 | 预期 |
|---|---|
| 起点 | 封面，工作方式块与摘要块都在 |
| 动作 | 比较两块：摘要回答「这个项目是什么、现在做到哪」，工作方式回答「在这里干活要守什么」 |
| 立刻看到 | 两块各有标题和一句说明；工作方式不复制 North Star 或 Current Focus 的内容，摘要块也不显示它；块的说明写明它来自 `ONE_PAGER.md` 的「工作方式」一节 |
| 慢 / 空 / 失败 / 断线 | 只有其中一块有内容时，另一块按自己的空态说话，不互相借文本；离线时两块各标自己的「上次结果」时间 |
| 键盘与焦点 | 只读正文不逐行停 Tab；读屏按页面顺序先读「一句话摘要」再读「工作方式」 |
| 离开再回来 | 两块的内容与先后顺序不变 |

### 3. 准备：想改，从对话开始

| 项 | 预期 |
|---|---|
| 起点 | 工作方式块 →「让 Kin 改…」（空态时是「让 Kin 写…」） |
| 动作 | 点它，进入新建对话的输入框；项目已选中，提示词已预填（读 `ONE_PAGER.md` 的「工作方式」、先复述现状、再按我说的改、只改这一节） |
| 立刻看到 | 输入框里是选中的预填文本，可改可删；项目选择显示当前项目；没有任务开始跑，也没有任何保存发生；发送要等用户按 |
| 慢 / 空 / 失败 / 断线 | 新建页加载慢时保留导航结果并给加载态；离线或只读时启动器禁用并说明原因；项目还没有 One-Pager 文件时预填同一句，Kin 会新建这一节 |
| 键盘与焦点 | 点按后焦点落在输入框文本末尾；Esc 不丢预填；从新建页返回封面时焦点回「让 Kin 改…」 |
| 离开再回来 | 预填只在这次导航里存在；回到封面，块内容没变——因为什么都还没保存 |

### 4. 确认：看清 Kin 究竟会收到什么

| 项 | 预期 |
|---|---|
| 起点 | 工作方式块，正文超过 400 字，或为空，或刚好完整 |
| 动作 | 读完正文与块脚注，不展开任何编辑器 |
| 立刻看到 | 超过 400 字：正文到第 400 字为止，脚注写「已截断：新对话只收到前 400 字，其余留在 ONE_PAGER.md」；空：写完空态文案后脚注写「新对话不会收到这一段」；完整：脚注写「新对话会收到这段原文」 |
| 慢 / 空 / 失败 / 断线 | 截断提示不因窗口变宽而消失；离线时脚注标「上次结果」；读取失败时不显示任何正文，也就没有可误认的「原文」 |
| 键盘与焦点 | 正文与脚注在同一个 region 内被读屏连续读出；截断只用文字说明，不靠渐隐或省略号猜 |
| 离开再回来 | 截断与否按文件当前内容重新判断，不记忆上次的展开或折叠 |

### 5. 执行 / 监控：新对话开始时注入

| 项 | 预期 |
|---|---|
| 起点 | 用户从任一端为这个项目开始一段新对话 |
| 动作 | 发送第一条消息（不经过封面） |
| 立刻看到 | 新对话的项目上下文里出现「How to work here」段，至多 400 字，排在 Current Focus 之后、Next 之前；封面不变、不弹提示；对话里能看到 agent 收到的上下文（沿用现有 transcript 行为） |
| 慢 / 空 / 失败 / 断线 | 没有这一段或为空：项目上下文照常注入，只是少了这一段；One-Pager 读不到：注入整体跳过，任务照常开始（现有行为，不因缺说明让对话失败）；断线：与现有新建流程同一套失败态；已存在的对话、追问和正在跑的任务都不改写，也不再重新注入 |
| 键盘与焦点 | 这一层没有新控件；焦点仍在输入框或发送按钮上 |
| 离开再回来 | 已开始的对话保留它开始时的 prompt；改文件只影响下一次新对话 |

### 6. 修改：改的是同一份文件

| 项 | 预期 |
|---|---|
| 起点 | 与 Kin 的对话里，或直接打开 `ONE_PAGER.md` |
| 动作 | 让 Kin 只改「工作方式」一节，或自己编辑文件后保存 |
| 立刻看到 | 保存走现有整份 markdown 的 PUT；成功后回到封面，工作方式块显示新原文；失败时对话或编辑器保留草稿并给原因（沿用现有保存路径的失败态） |
| 慢 / 空 / 失败 / 断线 | 保存中沿用现有提示；409 冲突沿用摘要编辑器的「保留我的 / 用对方的」；离线时保存禁用并说明；Kin 改完在对话里说改了哪几句，用户看 diff |
| 键盘与焦点 | 封面这一块没有编辑态，不抢焦点；从对话回到封面时焦点回「让 Kin 改…」 |
| 离开再回来 | 再打开封面是新原文；不存在「未保存的工作说明」这种状态——编辑发生在对话或文件里 |

### 7. 收尾：离开与信任

| 项 | 预期 |
|---|---|
| 起点 | 封面，工作方式块已读 |
| 动作 | 返回列表、切到另一个项目，或直接关掉控制台 |
| 立刻看到 | 块保持原样；列表的搜索、过滤与折叠不变 |
| 慢 / 空 / 失败 / 断线 | 断线时块显示上次结果并标明时间；不会因为离线把说明清空或显示成「还没写」 |
| 键盘与焦点 | Esc 从封面返回时焦点回列表里原来的项目标题；块本身没有关闭或丢弃动作 |
| 离开再回来 | 说明只存在于文件里：换设备、重启 daemon、重开控制台，只要文件在，新对话仍会收到它 |

## 各面差异

| 面 | 这一面怎么呈现 | 为什么不同 |
|---|---|---|
| Mac | 工作方式块在左栏「一句话摘要」下面、「最近活动」上面，占满左栏宽度；「让 Kin 改…」在块标题右端；正文按段落显示，不折叠、不内嵌滚动 | 左栏是读项目叙事的地方，工作方式紧跟摘要；窗口宽，400 字不用折叠，改说明跳到新建对话页 |
| 手机 | 同一顺序单列：摘要 → 工作方式 → 最近活动；「让 Kin 改…」是块内 44px 行尾按钮；正文换行，不横向滚动；启动器跳转到新建对话页，项目已选中 | 一屏只能放一件事；改说明要离开封面去对话，返回时封面保持原来的滚动位置 |

## Do not

- 不开新 tab、不加新路由、不加新页面；块 inline 在现有封面（KIN-PROJECT-001 D2，TASTE 1、13）。
- 不改 schema、不加新 endpoint：读写仍走 `GET/PUT /api/projects/:id/one-pager`，封面读取沿用现有项目与 One-Pager 响应。
- 不新造第二个 One-Pager 编辑器，也不给这一段做独立表单；改它走对话，或直接编辑文件。
- 不为工作说明建独立存储（表、JSON 字段、每项目设置项）。
- 不承诺改写运行中的对话或已存在的对话；说明只在新对话创建时进入 prompt。
- 不放松 holder-only 注入规则，也不把 digest 发给非持有者。
- 不读取或编辑项目目录里的 `AGENTS.md` / `CLAUDE.md` 等 agent 文件。
- 不自动生成工作说明，也不在「刷新封面」里改写这一段。
- 不改 1200 字总预算，不给这一段另开注入通道；它和其他段共用同一次注入。
- 不把这一段显示成可编辑的 textarea 或「保存」按钮。
