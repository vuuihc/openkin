# KIN-RESULT-003 · 对改动逐行评论并发回对话

状态：approved
优先级：P0
旅程：J2、J1
归属面：`IA.md`「对话详情 → 文件工作区」
面：Mac、手机

## 谁、什么时候、为什么

当我让 Kin 改完一件事、正在 diff 里逐行看时，我想直接指着某一行说"这里不对、应该这样"，并把攒下的几条一起发回去，以便不必离开对话、回到输入框凭记忆重述文件名和行号，也不必一次只问一条。

## 现在

diff 已经能看：`WorkspacePanel` 的「改动 / 文件」标签里有文件列表，`CodeViewer` 用现有 diff 渲染（Mac 可切左右对照与统一视图），`ChangedFilesList` / `ChangedFilesBar` 给出文件与增删数。但行上没有评论入口——想说某一行不好，只能退回输入框，用散文描述"那个文件里设置标题的那一行"，文件路径和行号全靠记忆。这是 review 流程（看改动 → 评论 → 发回 → 再改）里唯一缺失的一环；提交、推送、开 PR 不在这里，它们本来就归另一条意图。

## 范围

- 做：在 diff 的一行上留一条评论（Mac 评论栏、手机评论面板）→ 攒成一组 → 在托盘里回看、跳回、改、删 → 一次发回对话（一条普通后续消息）→ 发完清空 → agent 重跑后按文件、块头、引用行重新落位，找不到时标「该行已变化」并保留。
- 不做：Git 提交、推送、开 PR（`KIN-RESULT-001` 已排除 Git 操作；把一次已审阅的改动变成一个 PR 是另一条意图，按意图另开一条故事，不在这条里分轮）。
- 不做：评论跨设备同步、评论的回复线程、把评论变成可一键应用的 suggestion、编辑文件。
- 不做：评论表、评论接口、新事件类型或迁移；发送只走现有后续消息路径（`TaskDetailPage` 的 `pendingUserMessages` 与输入框同一条）。

## 每一步的预期

### 1. 定义 / 定位：想指出哪一行

| 项 | 预期 |
|---|---|
| 起点 | Mac 或手机的对话里，从「改动 / 文件」打开一个文件的 diff，且 diff 已渲染 |
| 动作 | Mac 把指针移到一行（或用键盘聚焦该行）；手机点一行 |
| 立刻看到 | 该行高亮，行尾出现「评论这一行」入口；已打开的评论框不会被指针离开抢走 |
| 慢 / 空 / 失败 / 断线 | 还在加载时没有行可评，入口不出现；读取失败说明原因并可重试，不给空白 diff；断线时已加载的行仍可评论，评论只留在本地 |
| 键盘与焦点 | Mac：行获得焦点后可用键盘打开该行操作并选「评论」，不需要鼠标；焦点进入评论输入框；Esc 关闭并回到该行 |
| 离开再回来 | 已保存的评论不因切换文件或刷新丢失；评论落在哪一行由文件、块头、引用行决定，不靠滚动位置 |

### 2. 准备：写下这条评论

| 项 | 预期 |
|---|---|
| 起点 | 某一行上的评论框刚打开（手机是盖在 diff 上的评论面板） |
| 动作 | 输入这条评论；可以引用相邻几行后写 |
| 立刻看到 | 输入立刻可见；评论框标出它挂在哪：文件路径、块头（`@@` 那行）、被引用的行文本；「保存」把评论放进本轮托盘 |
| 慢 / 空 / 失败 / 断线 | 空内容或只有空白不能保存，提示「写点什么再保存」；保存是本地动作，断线不阻止保存，也不显示成已发送 |
| 键盘与焦点 | 打开即聚焦输入框；Mac ⌘Enter、手机「保存」保存并关闭，焦点回原行；Esc 取消，已有输入不丢 |
| 离开再回来 | 未保存的输入按对话和文件保留，与输入框草稿同一层；切文件、关面板、刷新后还在；保存后进入托盘 |

### 3. 确认：回看这一组评论

| 项 | 预期 |
|---|---|
| 起点 | 托盘里已有一条或多条评论 |
| 动作 | 打开托盘，逐条看文件、块头、引用行和自己的话；跳回那一行，或改、删 |
| 立刻看到 | 每条一行：文件路径、引用行摘要、自己的话；点一条跳到 diff 对应行并高亮；托盘显示条数 |
| 慢 / 空 / 失败 / 断线 | 没有评论时托盘不出现，而不是空面板；锚点失效的条目仍在，标「该行已变化」；断线不影响本地托盘 |
| 键盘与焦点 | Mac：托盘是贴着评论入口的浮层，↑/↓ 在条目间移动，Enter 跳到该行，Esc 关闭并回到打开它的按钮；手机：托盘是可滚动面板，每条 ≥44px |
| 离开再回来 | 托盘内容按对话保留，刷新后还在；回看本身不改文件、不产生发送 |

### 4. 执行：一次发回对话

| 项 | 预期 |
|---|---|
| 起点 | 托盘里有多条评论，人在 diff 里 |
| 动作 | 点「发送 N 条评论」 |
| 立刻看到 | 对话里出现一条普通用户消息：一句短说明，然后每条一段——文件路径、块头、引用行、自己的话；消息带回到这次改动的入口；托盘清空并显示「已发回对话」；输入框和正在流式的回答不中断 |
| 慢 / 空 / 失败 / 断线 | 走现有后续消息路径：离线或失败时消息显示未送达并可重试，评论不丢；没有评论时按钮不出现，不是禁用；agent 正在跑时按现有"再发一条"规则处理，不另造队列 |
| 键盘与焦点 | Mac：⌘Enter 发送，焦点回到 diff 原行；手机：发送 ≥44px，发送后面板关闭，焦点回对话 |
| 离开再回来 | 发出去就是一条普通消息，进 transcript、可被引用；未发送的评论留在本地；刷新后已发内容不会在托盘里复活 |

### 5. 监控：agent 重跑，评论还指着那段代码

| 项 | 预期 |
|---|---|
| 起点 | 已有评论，agent 又改了一轮，重新打开同一文件的 diff |
| 动作 | 看托盘与行上的评论标记 |
| 立刻看到 | 每条按文件路径、块头、引用行重新落位；行号变了也跟着走 |
| 慢 / 空 / 失败 / 断线 | 引用行不在了：评论保留，标「该行已变化」，并显示原来的块头和引用文本；整个文件不在了也一样保留；不静默丢弃，也不改指向"最近的一行" |
| 键盘与焦点 | 失效条目仍可聚焦、可读、可删；读屏读出状态，不只靠颜色 |
| 离开再回来 | 失效锚点不会因为刷新自动"修好"或消失；同样的行再出现时恢复指向它 |

### 6. 修改 / 收尾：改一条、删一条、离开

| 项 | 预期 |
|---|---|
| 起点 | 托盘里有评论，或刚发完 |
| 动作 | 改一条、删一条，或收起面板回对话 |
| 立刻看到 | 改动即时生效；删除立即生效并可撤销；托盘条数同步 |
| 慢 / 空 / 失败 / 断线 | 改和删都是本地操作，不等网络；断线时仍可整理；已发出的消息不因本地删除而改变 |
| 键盘与焦点 | 删除后焦点落到相邻条目；托盘空了就关闭并把焦点还给评论入口；Esc 不丢已保存的评论 |
| 离开再回来 | 关面板再打开，未发送的评论还在；换一台设备看不到（本故事不同步） |

## 各面差异

| 面 | 这一面怎么呈现 | 为什么不同 |
|---|---|---|
| Mac | 左右对照 diff 右侧一条评论栏：行尾入口、贴行的评论框、底部托盘与「发送 N 条评论」；键盘可完成评论、跳转与发送 | 窗口宽，代码和评论可以并排；键盘是主操作，侧栏不遮代码 |
| 手机 | 统一 diff + 盖在 diff 上的评论面板；行尾标记点开面板，托盘是第二层面板，点按 ≥44px | 一屏只能放一件事，左右对照放不下；触屏没有悬停 |

## 设计

设计稿：`KIN-RESULT-003.figma/frames/`（4 张 SVG：Mac 评论栏、手机评论面板、`该行已变化` 状态板、发回对话后的消息）与 `KIN-RESULT-003.review.html`（Figma 帧为主体，每屏六段用户流程）。

必须画到的状态：默认、空（本轮没有评论，托盘不出现）、加载、失败、断线、锚点失效（`该行已变化`）、agent 运行中、已发送。

## Do not

- 不新建评论表、接口、事件类型或迁移；发送只走现有后续消息路径，不造第二条发送通道。
- 不把评论做成对话里的第二份列表；评论在 diff 的托盘里，发出去才是消息。
- 不做 Git 提交、推送或开 PR。
- 评论未发送前不写进 transcript，不同步到别的设备。
- 锚点失效时不许静默丢弃，也不许挂到"最近的一行"；必须标出来并保留原文。
- 不给 diff 引入新的渲染依赖，不重写现有 diff/面板；评论入口加在现有渲染之上。
