# KIN-MANAGE-001 · 整理一段对话

状态：draft
优先级：P1
旅程：J5
归属面：`IA.md`「Mac 上接着问」「手机上接着问」的列表部分
面：Mac、手机

## 谁、什么时候、为什么

当列表里的对话多起来、标题又都是开头那几个字，我想把一段对话改名、置顶、归档或删掉，以便下次一眼找到，而不是在一堆相似标题里翻。

## 现在

归档和删除已经有了：手机列表有逐条归档和批量删除（`sessionArchiveWiring.test.ts`、`sessionDeletionWiring.test.ts`），删除会先确认。改名还没有；置顶已经有了，Mac 和手机的入口却不一致；归档后的对话去"已归档"，入口在左栏底部，不明显；删除后没有说明能不能恢复。

多选已经存在，但入口和出口都不完整。2026-11-15 的 gap 记录了一次实测：iPad 的 248px 左栏仍走触屏路径，多选工具条约 400px 宽，「取消」被推到可视区外，键盘 Esc 不退，进入多选后行尾也没有出口（报告人原话「不知道怎么退出」）。工具条换行与 Esc 已在 PR #62 修好，行菜单的「多选 / 退出多选」入口已在 PR #170 修好；长按仍直接进入多选，行菜单里也还没有改名。这一条把长按改成打开行菜单，并补齐改名和两个面一致的入口。

截图：`03-sessions-1280.png`、`01-sessions-390.png`、`05-archive-1280.png`。

## 范围

- 做：在列表里找到一段对话 → 打开这一行的菜单 → 改名 / 置顶 / 多选 / 归档 / 删除 → 确认或取消 → 列表、搜索、归档页同步。
- 不做：批量改名（已有的批量置顶 / 归档（含已归档下的恢复）/ 删除保持不动）；拖拽排序（归 `R-drag-reorder`，见 `gap-log.md` 2026-11-15 条目）；回收站和撤销（归档是安全网）；跨设备同步协议的改动；任何后端或接口改动——改名和置顶跟 `taskPins.ts` 一样只写浏览器 localStorage，搜索把服务端结果与本地改过的标题合并，批量动作走现有的归档 / 删除路径。

## 每一步的预期

### 1. 定义 / 打开：列表该收拾了

| 项 | 预期 |
|---|---|
| 起点 | Mac 左栏或手机列表页，对话多到要翻 |
| 动作 | 看列表 |
| 立刻看到 | 每行显示标题、所属项目和最近时间；置顶的对话在列表最上面的「置顶」分组里（不在各自项目里），有一个不抢眼的置顶标记 |
| 慢 / 空 / 失败 / 断线 | 列表加载出骨架；没有对话时说"还没有对话"并给新建；断线时顶部提示，已加载的行不清空 |
| 键盘与焦点 | Mac：Tab 能进列表，↑/↓ 换行；手机：行高至少 44px |
| 离开再回来 | 置顶和改名都还在 |

### 2. 定位：找到要整理的那段

| 项 | 预期 |
|---|---|
| 起点 | 列表或搜索结果 |
| 动作 | 搜索，或按 设备 → 项目 找 |
| 立刻看到 | 结果按 设备 → 项目 → 对话 分组，置顶单独一组在最上面；搜索能命中本地改过的标题（服务端结果与本地改名合并） |
| 慢 / 空 / 失败 / 断线 | 无结果说"没有匹配的对话"并保留输入；搜索失败说原因 |
| 键盘与焦点 | Mac：⌘F 进搜索，↑/↓ 选结果，Esc 退出；手机：点搜索框，取消回列表 |
| 离开再回来 | 搜索词保留 |

### 3. 准备：打开这一行的菜单

| 项 | 预期 |
|---|---|
| 起点 | 列表里的一段对话 |
| 动作 | Mac 右键或点行尾的更多按钮；手机长按一行约 500ms 或点行尾的更多。长按打开的就是这个菜单，不直接进入多选 |
| 立刻看到 | 菜单里有：改名、置顶/取消置顶、多选、归档、删除；选「多选」进入多选并选中这一行；删除用警示色，和其余项分开。多选状态下同一个菜单只显示「退出多选」 |
| 慢 / 空 / 失败 / 断线 | 菜单立刻出现，不等网络；正在跑的对话，归档和删除仍然可用，菜单里多一句「正在运行」；长按期间手指位移超过 8px 就取消长按、改回滚动列表 |
| 键盘与焦点 | Mac：菜单打开后焦点在第一项，↑/↓ 移动，Esc 关闭并把焦点还给那一行；手机：底部动作面板，点外面关闭，外接键盘 Esc 关闭 |
| 离开再回来 | 菜单关闭，没有副作用；从菜单进入多选后的离开见第 4 步 |

### 4. 多选：一次整理几段

| 项 | 预期 |
|---|---|
| 起点 | 列表里已经有一段对话；从这一行的菜单选「多选」（Mac 和手机同一个入口），或在行上按 Shift+Enter |
| 动作 | 进入多选；点其它行加选或减选；选「置顶 / 归档 / 删除」之一，或「退出多选」 |
| 立刻看到 | 打开菜单的那一行立刻选中；工具条出现在列表顶部：第一行是「已选 N 项」和「退出多选」，第二行是「置顶 / 归档 / 删除」；248px 侧栏和 390 手机都不横向滚动，退出始终可见、至少 44px |
| 慢 / 空 / 失败 / 断线 | 批量动作进行中按钮禁用并显示进行中；部分失败只保留失败项并说明；断线时归档排队、删除不可用并说明；0 项时批量按钮禁用，但「退出多选」永远可用 |
| 键盘与焦点 | Mac：进入后焦点留在发起多选的那一行，↑/↓ 在行间移动，Tab 进工具条，Esc 退出并把焦点还给发起行，Shift+Enter 仍可进入；手机外接键盘同样 Esc 退出；状态区读出「已选 N 项」 |
| 离开再回来 | 退出多选即清空选择；归档或删除后列表滚动位置不跳回顶部；再进入从 0 项开始 |

### 5. 执行：改名或置顶

| 项 | 预期 |
|---|---|
| 起点 | 这一行的菜单 |
| 动作 | 选"改名"，输入新标题，确认；或选"置顶" |
| 立刻看到 | 改名：行内变成输入框，当前标题全选，确认后列表里的标题立刻变；置顶：这一行移到列表最上面的「置顶」分组，出现标记 |
| 慢 / 空 / 失败 / 断线 | 空标题不能确认；改名和置顶只写本机浏览器（localStorage），立即生效、不等网络，断线也照常可用，没有重试队列；浏览器拒绝存储时提示并保留旧标题 |
| 键盘与焦点 | 改名：Enter 确认，Esc 取消且不改；置顶：选完焦点回到那一行 |
| 离开再回来 | 新标题和置顶位置都在（本机浏览器）；搜索用新标题能找到 |

### 6. 修改：改错了再来一次

| 项 | 预期 |
|---|---|
| 起点 | 刚改完名或置顶 |
| 动作 | 再打开菜单，改回原名或取消置顶 |
| 立刻看到 | 和第一次一样的入口，当前值已经填好；取消置顶后回到原来的时间顺序 |
| 慢 / 空 / 失败 / 断线 | 同第 5 步；连续改名不叠加出两条历史提示 |
| 键盘与焦点 | 同第 5 步 |
| 离开再回来 | 最终值保留 |

### 7. 监控：归档和删除

| 项 | 预期 |
|---|---|
| 起点 | 这一行的菜单 |
| 动作 | 选"归档"；或选"删除"并在确认里确认 |
| 立刻看到 | 归档：这一行从当前列表消失，已归档里出现；删除：确认框写明"删除后不能恢复"，确认后消失，列表剩下的人保持选中状态（批量删除时） |
| 慢 / 空 / 失败 / 断线 | 删除进行中按钮禁用并显示"删除中"；部分失败时只保留失败的选中项并说明；断线时删除不可用并说明，归档进入本地队列 |
| 键盘与焦点 | 确认框打开时焦点在确认框，Esc 取消，焦点回到那一行 |
| 离开再回来 | 归档的对话在已归档里；删除的对话不再出现，搜索也搜不到 |

### 8. 收尾：列表恢复秩序

| 项 | 预期 |
|---|---|
| 起点 | 整理完几段对话 |
| 动作 | 回到列表继续找下一段 |
| 立刻看到 | 置顶在前、改名生效、归档和删除的都没了；当前滚动位置不跳回顶部 |
| 慢 / 空 / 失败 / 断线 | 断线时未完成的归档排进队列，恢复后自动继续，队列可见 |
| 键盘与焦点 | 焦点留在刚才那一行的位置，不回到列表顶部 |
| 离开再回来 | 所有整理结果都在，重开应用也一样 |

## 各面差异

| 面 | 这一面怎么呈现 | 为什么不同 |
|---|---|---|
| Mac | 右键或更多按钮打开贴行的菜单；改名在行内完成；置顶就在菜单里；多选工具条折成两行放进 248px 侧栏 | 鼠标和键盘都在，就地改最快；侧栏窄，工具条必须自己换行而不是横向滚动 |
| 手机 | 长按或更多打开底部动作面板；改名在行内完成，键盘弹出；多选工具条折成两行；删除确认是系统式对话框 | 触屏没有右键，底部面板是正确形态；390 宽放不下三个批量动作加「退出多选」的一行排布，同一套折行规则两端通用 |

## 设计

草图：`KIN-MANAGE-001.review.html`（Figma 优先；5 张帧在 `KIN-MANAGE-001.figma/frames/`：Mac 行菜单、Mac 多选、手机行菜单、手机多选、状态板）。

必须画到的状态：默认、空、加载、失败、断线、正在运行、行内改名。删除确认沿用现有的系统式对话框（已交付），状态板不重画它，只在验收里覆盖。

## Do not

- 不新增批量改名；已有的批量置顶 / 归档（含已归档下的恢复）/ 删除保持不动。
- 不做回收站、撤销、拖拽排序。
- 删除不许无确认，确认文案不许写"可以恢复"。
- 不改同步协议、API 或后端存储；改名和置顶只写浏览器 localStorage（沿用 `taskPins.ts` 的做法）；不改 `kin_permission_mode` 之类的设置键。
- 归档不是删除：归档的对话必须还能在已归档里找到。
- 不在列表行里塞第二套操作按钮；操作只在菜单里。
