  • 为什么单独一条：“看”与“说”是两件事。RESULT-001 只到“看清改了什么”；把评论发回去是同一意图下一个人能独立完成的一步，有自己的空、慢、失败和“离开再回来”。
  • 为什么不并进 RESULT-001/002：那两条的验收是“能找到、能打开、能返回”；评论要求“锚点跟内容走、一次发回一条消息”，是新的行为，不该塞进已排队的合同。
  • Job map 覆盖：定义/定位＝第 1 步，准备＝第 2 步，确认＝第 3 步，执行＝第 4 步，监控＝第 5 步，修改/收尾＝第 6 步；八段都有落点，没有“先做 Mac 再做手机”。
  • 设备只是差异：Mac 是左右对照 + 右侧评论栏，手机是统一 diff + 评论面板；同一套锚点、同一条发送路径。
  • 不在这一条：Git 提交 / 推送 / 开 PR → 另一条意图（把一次已审阅的改动变成一个 PR）；跨设备同步、评论回复线程、一键应用 suggestion → 本版不做。
  • 大小自检：标题只有一个动作；一个人一台设备一次能走完；一次交付含测试、复审、390/1100 截图；6 步 ≥ 3 步，装得下。

现在 → 之后

现在

  • diff 里没有行级评论入口，只能说“那个文件里设置标题的那一行”。
  • 文件路径和行号要自己重述，agent 还得猜。
  • 一次只能发一条；agent 重跑后，连自己说过哪一行都难对上。

之后

  • 在 diff 的一行上留一条评论，攒几条一起发。
  • 发出去是对话里一条普通消息：文件、块头、引用行、自己的话。
  • agent 重跑、行号移动，评论仍指向同一段代码；找不到时标「该行已变化」并保留原文。

01 · Mac · 1100×760

左右对照 + 右侧评论栏

Figma 帧

用户流程

  1. 起点对话里从「改动 / 文件」打开一个文件的 diff，左右对照；文件列表仍在左边，代码不被推走。
  2. 动作指针移到一行（或键盘聚焦该行后打开行操作，选「评论」），在右侧评论栏写一句，⌘Enter 保存；再评论两行。
  3. 立刻看到该行高亮、行尾出现入口；评论框标出文件、块头和引用行；保存后行上出现标记，托盘计数变 3，「发送 3 条评论」出现。
  4. 慢 / 空 / 失败 / 断线空内容提示「写点什么再保存」；diff 读取失败在代码区说明并可重试；断线时保存仍成功但绝不显示成已发送；发送失败时消息标未送达、可重试，评论留在托盘。
  5. 键盘与焦点行 → 评论框 → 保存 → 回原行；托盘 ↑/↓ 选条目，Enter 跳回该行，Esc 关闭并回到打开托盘的按钮；⌘Enter 发送。
  6. 离开再回来切到另一个文件再回来，未发送评论和未保存输入都在；刷新后同一段对话的评论还在；换一段对话不串。
02 · 手机 · 390×844

统一 diff + 评论面板

Figma 帧

用户流程

  1. 起点手机对话 →「改动 / 文件」→ 一个文件的统一 diff；顶部「‹ 对话」和「‹ 文件」两个出口始终在外层。
  2. 动作点一行（整行 ≥44px）打开评论面板；写一句；保存；收起面板看本轮条数；点「发送」。
  3. 立刻看到面板从底部盖上来，标题是「评论第 N 行」，引用行与块头可见；保存后面板收起、行尾出现评论数；本轮条数跟着涨。
  4. 慢 / 空 / 失败 / 断线diff 加载或失败时没有行可点，代码区说明原因；空内容不能保存；断线仍可保存，发送失败显示未送达并可重试；键盘弹起时输入框不被遮住。
  5. 键盘与焦点打开面板即聚焦输入框；保存 / 取消 ≥44px，焦点回原行；收起面板焦点回打开它的入口；外接键盘 Esc 关闭面板。
  6. 离开再回来回文件列表再进同一文件，未发送评论仍在；刷新后还在；换一台设备看不到（本故事不同步）。
03 · Mac · 1100×760

发回对话：一条普通消息

Figma 帧

用户流程

  1. 起点托盘里有三条评论，人在 diff 里，对话和工作区同屏。
  2. 动作点「发送 3 条评论」，或 ⌘Enter。
  3. 立刻看到对话里多一条普通用户消息：一句短说明，然后每条一段——文件路径、块头、引用行、自己的话；托盘清空并显示「已发回对话 · 3 条」；右侧 diff 不被推走。
  4. 慢 / 空 / 失败 / 断线消息立刻出现（和现有发送一致）；失败标未送达并可重试，评论不丢；没有评论时发送按钮不出现，不是禁用；agent 正在跑时按现有“再发一条”规则，不另造队列。
  5. 键盘与焦点发送后焦点回 diff 原行；消息可被键盘读到、可被引用；托盘空后发送按钮从 Tab 顺序消失。
  6. 离开再回来这条消息进 transcript，刷新或换设备（同一 Hub）都能看到；未发送的新评论留本地；已发内容不会在托盘里复活。

状态

状态板画的是“agent 又改了一轮之后”：一条评论的引用行不见了，其余两条仍然有效。宽板在卡片内左右滑动。

用户流程

  1. 起点评论还在（已发或未发），agent 又改了一轮，重新打开同一文件的 diff。
  2. 动作看行上的标记和托盘，或点一条失效的评论。
  3. 立刻看到有效的评论跟着行走，行号变了也对；引用行不见的那条标「该行已变化」，并保留原块头与引用文本。
  4. 慢 / 空 / 失败 / 断线agent 还在跑时标记不闪、不重复；整个文件被删也一样保留；断线不清空托盘；不静默丢弃，也不改指向最近的一行。
  5. 键盘与焦点失效条目仍可聚焦、可读、可删；读屏读出「该行已变化」，不只靠颜色。
  6. 离开再回来失效不会因刷新自动“修好”或消失；同样的行再出现时恢复指向它。
空本轮没有评论：托盘不出现，不是空面板；行上也没有标记。
加载diff 还在加载时没有行可评，入口不出现；不拿旧行冒充新 diff。
失败diff 读取失败在代码区说明原因并给重试；评论入口不出现，已有评论仍在托盘。
断线已加载的行仍可评论，保存成功但不显示成已发送；发送失败的消息标未送达并可重试。
空内容 / 禁用空内容或只有空白不能保存，提示「写点什么再保存」；没有评论时发送按钮不出现，而不是灰着。
运行中 / 等待批准agent 正在跑时按现有“再发一条”规则；已发出的评论不受影响，行上灰点保留（D5）。
锚点失效标「该行已变化」，保留原块头与引用文本，可删、可复制原文；不做模糊匹配。

要你拍板的

D0–D4 是已经拍过的板，写出来是为了让后来的人知道为什么。只回 D5。

D0 只做评论回路，不做 Git / PR

已定：评论、托盘、一次发回、锚点跟随；提交、推送、开 PR 不在这一条。

代价：review 到 PR 的最后一段还要再走一次；换来这一条能一次交付完，不和 Git 权限混在一起。PR 那一步按意图另开故事。

D1 评论是提示词，不是机器

已定：「发送 N 条评论」把评论变成一条普通用户后续消息，走现有发送路径；不加评论表、接口、事件或迁移。

代价：没有服务端评论历史、不能跨设备续编；换来没有第二份真相，也不用为评论造一套同步。

D2 锚点跟内容走，丢了要看得见

已定：按文件路径 + 块头 + 引用行重新落位；行号移动不影响；引用行消失时保留评论并标「该行已变化」。

代价：要维护一点本地锚点与重定位逻辑（在现有 diff 之上，不引依赖）；换来人的话不会因为 agent 重跑而静默消失。

D3 评论属于对话，不属于设备

已定：评论按对话 id 存在内存 / localStorage，和输入框草稿、置顶同一层；发送前不进 transcript，也不同步。

代价：换设备看不到未发送的评论；换来不新增存储协议，评论也不会在没发出去时出现在对话里。

D4 一次一条消息，形状稳定

已定：一条短说明，然后每条一段：文件路径、块头、引用行、自己的话。用用户能读懂的话写，不是模板字符串。

代价：不能每条评论单独发、单独回；换来 agent 一次看全，人也只需读一条消息。

D5 发完之后，行上还留不留痕迹？

推荐：留一个灰点，点开能看到「已发回对话」和那条消息的跳转；灰点按对话保存在本地，直到这段对话结束。

代价：要多记一份“哪条评论发去了哪条消息”的本地对应，比发完即清多一层状态；换来重新打开 diff 时知道自己评论过哪几行，不会重复提问。若选“发完不留痕”，实现更简单，但重开 diff 就看不出来。
