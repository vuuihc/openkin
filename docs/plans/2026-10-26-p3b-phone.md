# P3b — 手机端：主入口

2026-10-26。对着 `main`（`fbdc4d8`，P3 已合入）读代码，并用真机宽度**实测**过一遍：
dev server `:5199` 从本工作树起、`/api` 代理到本机 live daemon `:7777`，视口 390×844（iPhone 15/16 类）
与 320×568（SE 类），截图与 DOM 尺寸都记在下面。

交付清单是五项：会话列表按 Today / This week / Older 聚合；会话视图的手机布局；审批收件箱空状态；
推送通知 + 从通知直接进会话；设置页收口。**实测下来其中一项（空状态）已经在树里，一项（推送）服务端早就通了、
断的是落地那一半**，真正要建的是三件：列表的时间聚合、深链的落点、设置里的「手机怎么用」。

  它是唯一会多出「运行中 + 停止」的状态）：390 时 358/358 刚好放下、不滚；320 时**第一个 chip 落在 x=-2**，

  桌面 1280 时 561/561、单行、标题正常截断。这条已修，见 §3 S2。

### 1.3 深链：服务端早就通了，断的是落地那一半

发送端（`internal/notify/notify.go`）：Bark 与 ntfy **同时配置就同时发**（`:218-239`），2 次尝试、5s 超时，
即发即弃（`:204-214`）。触发点六类：审批、用户问题、任务终态、routine、额度等待、worker 租约丢失（表见 §5）。
基址来自 `ui.base_url`（`internal/server/server.go:879-883`，隧道场景在 `:735-746` 重写），
`DeepLink` 只拼 `base + path`、**不带任何凭据**（`notify.go:79-88`）—— 这是对的，推送要过 Bark/ntfy 的服务器，
token 不能进 URL。

落地这一半缺的三处（**三处都已修，见 §3 S3**；下面引的行号是**改动前**的）：

- **审批推送不带 id**：`NotifyApproval(... approvalID ...)` 收了参数却没用（`notify.go:91` vs `:99`），
  链接是 `/approvals`（再被 `App.tsx:151` 重定向到 `/inbox`）。从通知点进来，落在收件箱顶上，**不知道是哪一条**。
- **问题推送带了 id，但页面接不住**：`?focus=<qid>`（`notify.go:104-113`）在 `ApprovalsPage.tsx:45-52` 只搜
  审批数组；问题列表是另一份（`:183-200`），`UserQuestionCard` 接受 `focused`（`:8`、`:39`）但页面从没传（`:191-196`）。
- **`?focus=` 不滚动、不解释**：命中的卡片只加描边与徽章（`ApprovalCard.tsx:59-61`、`:71-75`），
  没有 `scrollIntoView`、也没有锚点；命中的 id 不在列表里时**什么都不发生**（已处理、已过期、不在加载窗口内
  都一样），页面从第 0 条开始画。

**交付清单第 3 项「审批收件箱空状态」已经在树里**：`ApprovalsPage.tsx:147-160` 的虚线卡 + `inbox.allClear`
+ 提示，实测 390 上渲染为「没有待审批项 / 全部处理完了 / 当 agent 需要权限时，会在这里一键批准或拒绝。」
（来自 `aa0f3e8`，早于 P0–P3）。这一项改成「深链落地」，见 S3。

另一件实测：**没配对的手机打开通知深链落到连接闸门**（`App.tsx:39-46`、`:107-124`），文案是
「此浏览器没有认证 token… 在主机上：`~/.kin/token`；从已授权设备：设置 → 连接二维码」。也就是说
「通知直接进会话」有一个一次性前置条件：**这台手机得先在同一个浏览器里配对过一次**。
设置页要把这句话说出来（S4），因为配对前通知就是个死链。

没有 service worker，也没有 web push：`ui/public/manifest.webmanifest` 只是 `display: standalone`、
`start_url: "/"`、图标齐全（`ui/index.html:11-17` 另加 apple 那几个 meta），全树没有 `sw.js`、没有
`navigator.serviceWorker`/`PushSubscription`/`applicationServerKey`。**手机上的「推送」就是 Bark App 或 ntfy App**，
这一点与 P3b 的交付清单一致，不引入 SW（理由见 §2.4）。

## 2. 目标形状

### 2.1 手机第一屏要回答「现在能做什么」，不是「历史有多长」

`/sessions` 的手机视图按四段画，顺序固定：

```
正在跑       ← 状态是 running/queued/waiting 的（跨机器合并）
今天         ← 其余里 at >= 今天零点
本周         ← 其余里 at >= 今天零点 - 6 天
更早         ← 其余的
```

- **「正在跑」优先于时间**，所以三天前开始、现在还在跑的那条出现在第一段而不是「更早」段里；
  每条只出现在一段里（先判 running，再判时间）。这是分桶函数要写死的第一条规则，也是它与
  `SessionsPage.tsx:65-69` 现有 active-first 排序的关系：**active-first 从全局排序降级为段内排序**。
- 分桶是**纯函数**，进 `ui/src/lib/sessionBuckets.ts`：`bucketOf(at, now)` 与 `groupSessions(rows, now)`，
  复用 `relativeTime.ts` 的 `WEEK_MS`，不碰 DOM、不读时钟（`now` 由调用方传，测试才可写）。
  日界用本地零点，和 `TrayPage.tsx:36-40` 一致，顺手把那两处内联收敛到同一个 helper。
- 段标题用 i18n（en/zh 同改）：`sessions.groupRunning/Today/Week/Older`。
- 手机行补**未读点**：`sessionViewed` 已有（`lib/sessionViewed.ts:111`），侧栏怎么用手机行就怎么用。
  理由：从通知进来的人是来找「哪条是新的」，而现在只有状态胶囊。
- 段标题在桌面 `/sessions` 上也画（同一个页面，不做两套）；侧栏与 `/tasks` 不动。

### 2.2 通知必须落到「那一条」

- 审批推送带上审批 id：`notify.go` 的 `NotifyApproval` 用上它已经收到的那参数，深链改成
  `/inbox?focus=<approvalID>`（与问题推送对称）。
- `ApprovalsPage` 的 `?focus=` 变成完整语义：命中 → 滚动到可见 + 描边 + 键位仍然作用于它；
  问题列表也接受同一个参数（把 `focused` 传给 `UserQuestionCard`）；
  **没命中 → 说一句**（「这条已经处理过了」+ 回列表），而不是静默。
- 落地页在手机上是收件箱，这一点不变；变的是「点进来就知道该看哪一条」。

### 2.3 设置里要有一个「手机」的位置

**位置改成「通用」tab 的第一块**（原计划写在通知 tab 顶部），理由两条：手机上打开设置落的就是通用，
而通知是第 6 个 tab、在 390 上本来就在屏幕外 —— 把「手机怎么用」放进去等于藏起来；通用在独立节点上
又正好只有「外观」一张卡。这一块回答四句话：怎么配对（按钮跳「远程」，那里有连接二维码）、
通知落在哪（`<ui.base_url>/inbox`，空的时候用橙色说明「链接是相对路径，点开无处可去」）、
推送通道在哪（按钮跳「通知」）、以及配对是**每个浏览器/每个主屏幕图标各一份**的。

**不放第二份连接二维码**：`connect_url` 带 token（§1.4），设置页是被动视图，把凭据复制到另一个屏幕
上不是便利；而且在手机自己身上那个二维码本来就是空的（配过对的设备不是 master 请求），
复制过去正好在最需要它的地方显示成一个空框。这是对原计划的一处收紧，按钮跳转替代复制。

另外给 tab 条加横滚提示（哪边还有 tab，哪边渐隐），并让**被选中的 tab 永远落在渐隐之外**：
手机块的两个跳转、`?tab=` 直达、键盘方向键都会让某个屏幕外的 tab 变成选中态。

### 2.4 明确不做的

| 不做 | 理由 |
|---|---|
| service worker / web push | 手机上的通知已经由 Bark/ntfy 落到系统通知中心；引入 SW 要连带缓存语义、更新策略、iOS 安装态调试，收益是「多一个通道」而不是「从无到有」 |
| 标签拖拽排序 | 手机没有标签条，见 §1.5 |
| 横屏/平板的触摸密度 | `index.css:61-66` 的 640/768 界在横屏手机（844×390）上会让触摸设备拿到桌面密度。**没有证据说明这是真实场景**（用户的用法是竖屏），按「最小可逆步骤」记为已知限制，不提前建 |
| 手机上的 zen | 唯一触发是 `Cmd+.`（`AppShell.tsx:384-387`），手机没有键盘；zen 会藏掉手机导航，给了入口反而有害。不动 |
