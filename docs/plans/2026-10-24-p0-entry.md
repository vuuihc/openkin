## 1. 这一层要删掉的那个决定

parity §0 第四条的判据是「这个功能替用户删掉了哪一个**必须坐到电脑前才能做的决定**」。
这一层的答案只剩一句话：

> **手打一个绝对路径。** 手机上你不知道那台机器的目录结构，而 Kin 今天要求你记得它。

验收（parity §6 原文）：**只用手机开两个新会话——一个换到远端机器、进到一个你不能凭记忆
打出路径的目录；一个是从没 clone 过的仓库。全程不碰电脑。**

两条路径的产物是同一个东西：一次 `POST /api/tasks`（`cwd` + `executing_device_id`）。
**这一层不发明新的任务类型，只发明「怎么在手机上把 cwd 填出来」**——这是它敢做得小的原因。

```
新建会话
├── 通用：机器 → 文件夹（浏览）→ 分支
└── 快捷：GitHub → owner/repo → 分支   →  机器上 clone 出来，路径回填
```

## 2. 现状（2026-10-24 核实）

| 能力 | 现状 | 证据 |
|---|---|---|
| 选远端机器 | **已有** | `ui/src/components/chat/MachinePicker.tsx`、`ui/src/hooks/useMachines.ts`；`CreateTaskRequest.executing_device_id` |
| 选文件夹（桌面 Electron） | **已有，不动** | 原生对话框 `pickDirectory`（`ui/src/components/chat/CwdPicker.tsx:31,87` → `lib/desktop.ts`） |
| 选文件夹（手机/浏览器） | **只能手打 + 最近目录** | `CwdPicker.tsx:32`：「Browser: manual path + recent cwds (web cannot expose absolute paths)」 |
| 浏览远端目录树 | **不存在** | `/api/fs`、`readdir` 全树 0 命中 |
| 选分支 | **有，但只对「本机已存在的 checkout」成立** | `BranchPicker` → `checkoutGitBranch` → `POST /api/git/checkout` |
| 从 GitHub 开会话（免 clone） | **不存在** | Go 侧 `clone` 只在 `internal/skills`；`internal/workspace` 没有 clone / ls-remote |

**缺陷 1（本次修）：`/api/git/branches` 与 `/api/git/checkout` 不知道机器是谁。**
两者直接拿 `cwd` 去读**本机**文件系统（`internal/api/git.go:29-38`、`:52-58`），
没有 `workspace.go:150-165` 那道 `RunsElsewhere` 守卫——因为它们的入参里根本没有机器。
桌面「选远端机器 + 该机器上的 cwd」今天就能走到这里：同一个路径在两台机器上都存在
（那正是 anchor 的前提），于是**分支列表可能来自错误的副本**，而不是报错。
手机流程是第一个**必然**指向另一台机器的调用者，所以它必须先把端点补成有机器概念的。

## 3. 形状：唯一的新机制是「Hub 向 Node 提问」

通道上今天只有两类帧：Hub→Node 的**命令**（`turn.dispatch` / `turn.cancel` /
`approval.decision`）和 Node→Hub 的**报告**（`turn.*` / `approval.request` / `heartbeat`）。
**缺的是一次带答案的提问**——手机在 Hub 上，目录在那台机器上，Hub 不能替它回答。

### 3.1 帧

`internal/remote/worker/protocol.go` 的 `allowedFrameKinds` 是封闭集合，加两个：

| 帧 | 方向 | 载荷 |
|---|---|---|
| `query` | Hub → Node | `{id, method, params}` |
| `query.result` | Node → Hub | `{id, error?, result?}` |

一个信封 + 一个**封闭的方法表**，而不是每种问题一对帧：方法表是一处 switch，
两侧都能一眼读完；帧种类继续封闭，不长的协议不给自己造 N 个几乎相同的分支。

- `id` 由 Hub 生成，全局唯一（含 device 前缀），两侧都校验（非空、长度上限）。
- `params` / `result` 是 `json.RawMessage`，各自方法的类型在方法表里解码；
  **解不开的参数是错误，不是空值**。
- 未知 method：Node 侧回 `query.result{error}`（有答案比沉默好——沉默会让 Hub 等到超时）。

### 3.2 Hub 侧：待答表 `node.Queries`

```
Ask(ctx, sender, method, params) (json.RawMessage, error)
Route(sender, frame) error      // query.result → 配对
Abandon(sender) []string        // 连接结束：把所有还没答的提问立刻结束
```

- 按 `(device, id)` 存一个 channel；`Ask` 发帧后等，超时/ctx 结束/连接结束都返回错误。
- `NewConnections(onEnded)` 已经存在的钩子（`internal/server/server.go:335`）里加一句
  `Abandon`：**连接断了不能让提问挂到超时**——那是一个必然失败的等待。
- 超时按方法给（列目录/列分支 15s；clone 5min）。超时值是一处常量表，不是散落的魔数。
- 同一 device 上的两次提问互不干扰（各有 id），并发提问不需要串行化。

### 3.3 Node 侧：`node.Responder`

```go
type Responder struct {
    Roots        []string  // 与 Executor.Roots 同一份：这台机器同意工作的目录
    CheckoutRoot string    // 这台机器放它 clone 出来的仓库的地方
    Warn         func(format string, args ...any)
}
```

- `OnFrame` 的分派里加一个 case（`internal/server/node.go:265`），与 `approval.*` 并列。
- **每个方法都以这台机器自己的 roots 为界**，containment 判定复用 `Executor.allowedCwd`
  的那套（`filepath.EvalSymlinks` 之后的真路径比较）——抽成一个共用函数，两处调用，
  一处实现。理由与 Executor 上那段注释相同：Hub 是另一方，不能由它来界定自己。
- **写操作的目的地由机器自己推导**。Hub 只说「哪个仓库」，不说「放到哪」——
  Hub 能指定路径就等于 Hub 能在任意 root 里落文件，而 roots 是「可以跑 agent」的许可，
  不是「Hub 可以直接写」的许可。

### 3.4 三个方法（v1）

| 方法 | 参数 | 结果 | 说明 |
|---|---|---|---|
| `fs.list` | `{path}` | `{path, parent, roots[], entries[{name}]}` | 空 `path` = 这台机器的 roots。**只列目录**，不返回文件、大小、内容：这不是通用文件浏览器。目录项按名字排序，上限 500 条 + `truncated`。根之上没有 `parent`（边界可见）。 |
| `repo.branches` | `{repo}` | `{repo, default_branch, branches[]}` | `git ls-remote --heads`，不 clone。私有仓库用**那台机器**的 git 凭据。 |
| `repo.prepare` | `{repo, branch}` | `{path, branch, cloned}` | 目的地 = `<checkout_root>/<host>/<owner>/<repo>`，由 Node 推导。**幂等**：已存在同源 checkout 就 fetch + 切分支，已存在但不是这个仓库就拒绝。目的地加锁，双击不会并发 clone。 |

`repo` 接受 `owner/repo`（GitHub 简写）或完整 URL；规范化复用
`workspace.CanonicalRemote`（`internal/workspace/anchor.go:115`，已经会剥 userinfo——
token 不会随 URL 进日志或库）。

### 3.5 HTTP 面（`holderOnly`）

```
GET  /api/machines/{device}/dirs?path=
GET  /api/machines/{device}/repo/branches?repo=
POST /api/machines/{device}/repo/prepare   {repo, branch}
```

- `{device}` 取 `self` 或本机 `desktop_id` 时走**同一份方法实现**的本地分支
  （Hub 自己也是一台机器：手机浏览 NAS 的目录同样要能用）。
- 不在线的机器：`409` + 「机器离线」；未知/已吊销：`400`（复用 `ValidateExecutingDevice`
  的判定口径）。
- 门槛是 `holderOnly`（`internal/api/api.go:629`）：配对手机是这台机器的完全客户端，
  访客账号不是。

### 3.6 不改的东西（重要）

- **不加表、不加任务字段、不动 engine**。
- 远端任务在 Hub 侧仍是 **shared 工作区**：`engine.go:1343-1364` 明确拒绝
  「远端 + worktree」，并写明「它的工作区就是那台机器自己的 checkout」。
  所以这一层的会话**跑在那台机器的一个真实目录里**（已有的 checkout，或刚 clone 出来的
  那一个），不是每任务隔离的 worktree。
  - 已知限制：同一仓库的第二个手机会话落在**同一个 clone**（两个会话互相看得见改动）。
  - 远端隔离 = 让 Node 拥有 workspace 层（generation / worktree / 清理），
    那是独立的一层，且是 **P0b（publish 需要分支）的前置**——在那一层单独设计，
    不在这里顺手做半个。

### 3.7 checkout root

`--checkout-root`（默认 `<stateDir>/checkouts`，取 `off` 关闭）是这台机器放 clone 的目录，
**它进入这台机器上报的 roots**——否则 `Executor.allowedCwd` 会拒绝在那里跑会话。

这是一次**有意**的边界放宽：Hub 从此能让这台机器 clone 一个它选的仓库并在里面跑 agent。
收窄它的方式写在这里，也写在启动日志里：

- 放宽的只有这一个目录，且由这台机器的操作者命名；
- `--checkout-root=off` 时快捷路径直接拒绝（`repo.prepare` 报「这台机器没有 checkout 目录」）；
- 派发回合仍然过 `AllowYOLO`（`internal/node/executor.go:143`）那道闸。

## 4. UI 形状

**规则**：桌面 + 本机 → 原生对话框（**一行不改**）；其余（手机、浏览器、远端机器）→ 浏览。

- `CwdPicker` 增加浏览模式：当前路径 + 子目录列表（点进去）+ 上一级 + roots 快捷入口，
  手打输入框**保留**（浏览是给人用的，手打是给记得路径的人的逃生口）。
- 快捷路径是同一个入口的第二档：`owner/repo` + 分支 → `repo.prepare` → 用返回的 path 建任务。
  分支来自 `repo.branches`（先选仓库再选分支，顺序与 LODY 一致）。
- 所有文案进 i18n（中英同改）；手机宽度（390×844）实测。

## 6. 不做

- 不做通用文件浏览器（只列目录；不读文件内容、大小、mtime）。
- 不做「列出你的 GitHub 仓库」（v1 手输 `owner/repo`；列表需要账号级凭据，见 §2.7 边界）。
- 不做远端的每任务隔离与清理（§3.6）。
- 不动桌面原生目录对话框，不改本机 `--root` 语义。

## 7. 风险与未验证

- **真实验收在手机上**，而手机连的是你 NAS 上那个 Hub：这份代码要跑到那里才算数。
  本机能验证的等价路径：**本机起一个 Hub + 本机 Node 走真实 ws 通道**，
  再用手机宽度（390×844）的浏览器把两条路径各开一个会话。NAS 的部署不在本次自动授权里。
- 私有仓库 clone 依赖那台机器上 `gh`/git 的凭据状态；本机当前**没有**可用的 GitHub 凭据
  （见 P0 实测），所以 S3 的私有仓库分支只能靠单元测试覆盖，实机走公开仓库。
- 无独立评审：本环境所有 subagent 都走 Codex 网关，而它 429（配额耗尽）。
  每个切片以自审 + 红测试顶替，残余风险写在这里。
