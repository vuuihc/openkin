## 三条铁律（写死，避免走偏）

1. **只有 Hub 分配序号。** Node 从不写自己的事件日志，只上行事件。
2. **秘密不出设备。** provider key、agent 登录凭据永不上行；Hub 只存非敏感能力元数据。
3. **一个会话同时只有一个活跃 turn。**

外加一条本次明确的前提：**不写兼容层**。旧数据、旧行为、旧接口一律直接改；
`tasks.session_ref` 这类"兼容投影"直接换成 `(device_id, agent_id, external_ref)` 三元组，
牵动的 adapter 一次改到位（ADR 0022 结论里"保留 session_ref"那段按此作废）。

## M1 — 多端看到同一批会话

目标：桌面端和手机打开看到**同一批会话**；断网恢复后能补齐变化。

| 步骤 | 内容 | 状态 |
|---|---|---|
| **M1.1** | schema：`tasks` 加 `hub_seq` + owner/executing_device/anchor 列；`devices` 注册表；`agent_sessions` 唯一键改 `(device_id, agent_id, external_ref)`；索引 | ⬜ |
| **M1.2** | 事件追加时同事务分配全局 `hub_seq`（`MAX(hub_seq)+1`），并更新 `tasks.hub_seq` | ⬜ |
| **M1.3** | `GET /api/sessions?updated_since=<hub_seq>&limit=` → `{sessions, next_cursor, has_more}` | ⬜ |
| **M1.4** | 实时通道：**SSE 优先** + 有界 long-poll 兜底；WS 降级为加速（消息带 `hub_seq`） | ⬜ |
| **M1.5** | 控制台改为"一个 Hub + 游标续拉"，替换今天的整表重拉 | ⬜ |
| **M1.6** | 移动端：Capacitor + React 壳替换 SwiftUI，删除 `ios/` | ⬜ |
| **M1.7** | 验收：A 机建会话 → B 机不刷新即见；B 断网 5 分钟重连靠游标补齐且无重复 | ⬜ |

**验收口径（照抄设计 §P0-A）：** ① Hub 在 A，浏览器在 A、iOS 在 B；② A 上新建会话并跑完一个 turn；
③ B 无刷新可见，且 `GET /api/tasks/{id}/events` 的 `seq` 连续无洞；④ B 断网 5 分钟后重连靠游标补齐且无重复。

## M2 — 各设备用自己的 agent 干活

目标：手机上发一个任务 → 在装了 agent 的那台桌面机上跑起来 → 过程回到手机 → 能批准/拒绝权限请求。

**内部顺序是硬性的：先用现有 adapter 把链路跑通，再把执行层换成 ACP。**
这样 ACP 出问题时有一个已知可用的对照组，而不是两个新东西同时不确定。

| 步骤 | 内容 | 状态 |
|---|---|---|
| **M2.1** | Node 角色：注册 / 心跳 / 能力上报（`hello`、`heartbeat`），Node 主动外连 Hub | ⬜ |
| **M2.2** | turn 派发：Hub 落 turn 行 → `turn.dispatch` → Node 执行 → `turn.event` 上行 → Hub 分配 `seq` | ⬜ |
| **M2.3** | 工作区锚点：`workspace_anchors` + 每设备路径解析；解析不到就明确失败，不静默换设备 | ⬜ |
| **M2.4** | turn 终结与重连：掉线 / 重启 / 被杀都必须收敛到 `failed`/`canceled`，保留部分 transcript | ⬜ |
| **M2.5** | 跨设备审批：`approval.request` / `approval.decision` 走控制通道，绝不自动批准 | ⬜ |
| **M2.6** | ACP 客户端 + 事件映射 + `session/request_permission` → 审批收件箱 | ⬜ |
| **M2.7** | 验收：手机发任务 → 桌面机执行 → 过程与结果回手机 → 手机批准一次权限请求 | ⬜ |
