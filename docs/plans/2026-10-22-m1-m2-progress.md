## 三条铁律（写死，避免走偏）

1. **只有 Hub 分配序号。** Node 从不写自己的事件日志，只上行事件。
2. **秘密不出设备。** provider key、agent 登录凭据永不上行；Hub 只存非敏感能力元数据。
3. **一个会话同时只有一个活跃 turn。**

外加一条本次明确的前提：**不写兼容层**。旧数据、旧行为、旧接口一律直接改；
`tasks.session_ref` 这类"兼容投影"直接换成 `(device_id, agent_id, external_ref)` 三元组，
牵动的 adapter 一次改到位（ADR 0022 结论里"保留 session_ref"那段按此作废）。

目标：桌面端和手机打开看到**同一批会话**；断网恢复后能补齐变化。

| 步骤 | 内容 | 状态 |

| **M1.7** | 验收：A 机建会话 → B 机不刷新即见；B 断网 5 分钟重连靠游标补齐且无重复 | ✅ 已实测，逐条见下 |

**M1.1 的一处推迟：** `agent_sessions` 的唯一键改成
`(device_id, agent_id, external_ref)` 没有跟着做。改唯一键要重建表并改所有写入点，
而写这些行的 adapter 在 M2 本来就要按设备重写；现在改会把同一处代码改两遍。
先把 `devices` 注册表建好，M2 做 Node 时一次改到位。

**验收口径（照抄设计 §P0-A）：** ① Hub 在 A，浏览器在 A、iOS 在 B；② A 上新建会话并跑完一个 turn；
③ B 无刷新可见，且 `GET /api/tasks/{id}/events` 的 `seq` 连续无洞；④ B 断网 5 分钟后重连靠游标补齐且无重复。

**M1.7 实测怎么做的（2026-10-22）：** 起了一个用完即弃的 Hub（`/tmp/kin-m17`，state dir 独立），
前面套一个自己写的 TCP 转发（`127.0.0.1:7799` → Hub 的 `7800`）。两个独立浏览器标签页都连 7799：
A 页就是"机器 A 上的浏览器"，B 页是"机器 B"。**断网 = 杀掉那个转发**，Hub 本身照常跑，
所以"B 掉线期间 Hub 上还在变"是真的，不是模拟出来的。

| 验收项 | 结果 |
|---|---|
| ① A 建会话，B 不刷新即见 | ✅ B 页 2 秒内出现该会话（走 SSE） |
| ② 完整 turn 的事件 seq | ✅ m17-beta 跑完一个真 turn：18 条事件 `seq 1..18` 无洞；另三个会话 `1..3` / `1..2` 无洞 |
| ③ B 断网后仍然陈旧（证明断的是真网） | ✅ 5 秒内出现"正在重连"横幅；期间 Hub 上新增/删除的三个会话 B 一个都不知道，且**原有行一条没丢** |
| ④ 断网满 5 分钟 → 恢复 → 靠游标补齐 | ✅ 恢复后 B 的会话集合与 Hub **完全一致**（6 条），被删的那条正确消失，无重复行（每个会话在侧栏恰好一行；另加详情页标题链接共 2 个锚点），横幅消失 |

顺带发现并修掉一个真问题：`streamEvents` 原来把"连不上 Hub"也算作"这条网络不能推流"，
两次失败后就永久放弃流，一个睡醒的笔记本从此只能靠 long-poll（不丢数据，但白白多 25 秒延迟）。
现在两种情况分开了——**连不上就继续重试**（这是暂时的），**只有 Hub 收下了请求却一个字节不发**
（CDN 缓冲）才判定为不能推流并永久降级。新增 `ui/src/api/client.stream.test.ts` 三个测试钉住这条策略。

**M1.3 的一处与原设计不同：** 设计文档说"`MAX(hub_seq)+1` 天生单调无洞，不需要额外的序列表"。
这句话漏了**删除**：删掉游标最大的那条会话，它的号会被下一个写入者重用，持有该游标的客户端
就永久看不到那次变更。所以删除时写一行 `task_tombstones`（迁移 035），它既是"这条会话没了"的
通知，也是游标的下界。墓碑永远不清理（一行几十字节），离线再久的客户端也能补齐。

## M2 — 各设备用自己的 agent 干活

目标：手机上发一个任务 → 在装了 agent 的那台桌面机上跑起来 → 过程回到手机 → 能批准/拒绝权限请求。

**内部顺序是硬性的：先用现有 adapter 把链路跑通，再把执行层换成 ACP。**
这样 ACP 出问题时有一个已知可用的对照组，而不是两个新东西同时不确定。

### 手头已经有的（先说清楚，免得重造）

盘点了一遍代码，M2 需要的东西一半已经在仓库里，只是没接线：

| 已有的 | 位置 | M2 怎么用 |
|---|---|---|
| 四张表：`devices` / `device_agents` / `workspace_anchors` / `workspace_anchor_roots` | 迁移 034 | 建好了但**一行 Go 代码都没读它**；M2 就是给它们接上读写 |
| `tasks` 的 `owner_user_id` / `origin_device_id` / `executing_device_id` / `workspace_anchor_id` | 迁移 034 | 同上，schema-only |
| 设备配对 + 可吊销设备凭据 | `device_credentials`、`store.AuthenticateDevice`、`remote.PrincipalDevice` | **直接就是 Node 的传输凭据**，不用新造认证 |
| Worker 协议类型：`Hello` / `Heartbeat` / `Assignment` / `TaskEvent` / `Frame`（带校验） | `internal/remote/worker/protocol.go` | 帧格式已经定义好了，`Assignment` 就是 `turn.dispatch` 的雏形；**但没有任何代码发送或接收过 `Assignment`** |
| Worker 注册表 + HTTP register/heartbeat | `internal/remote/worker/registry.go`、`internal/api/workers.go` | 注册/心跳的形状照抄；但注册表是**进程内的内存 map**（ADR 0020 明说"intentionally process-local"），M2 必须落库 |
| Turn 执行的唯一入口 | `adapter.Adapter.Start(ctx, TaskSpec) (RunHandle, error)` | **这是 M2 最重要的一个缝**：远端执行写成一个 adapter，Hub 的引擎、事件落库、游标、总线、审批、重试全都不用动 |
| 崩溃恢复的先例 | `store.FailOrphaned` + "daemon restarted" 事件 | M2.4 的收敛照这个写 |
| 审批送达的两种既有路径 | 进程内 waiter channel；`kin approve-mcp` 走 loopback HTTP | 本机场景已经有了；跨设备要的是把裁决送过网 |

### 四条定死的决定

1. **控制通道是 Node 主动外连 Hub 的 WebSocket**（`GET /api/node`，用设备令牌认证），帧用现有
   `worker.Frame` 信封，按设计 §6.1 补上 `turn.*` 那几个 kind。Node 在 NAT 后面不用开端口；
   以后要挂到 relay 上（P0-E）也不用换协议。
2. **远端执行实现成一个 `adapter.Adapter`**：`Start` 发 `turn.dispatch`，返回的 handle 把
   `turn.event` 帧喂进 `Events()`，`Cancel()` 发 `turn.cancel`。Hub 侧一行引擎代码都不用改——
   这是 D8「一条代码路径」的落法，也让 standalone 与远程走完全相同的下游。
3. **秘密不过线**（D7）：`turn.dispatch` 不带 `ProviderCfg`/API key，Node 用自己的本地配置。
4. **`session_ref` 是设备本地的**：派发时按 `(device_id, agent_id)` 取那一台自己的 ref。
   M1.1 推迟的 `agent_sessions` 唯一键重建，就在这一步一次改到位。

### 每步落在哪些文件

| 步骤 | 落点 |
|---|---|
| **M2.1** Node 角色 | `internal/node/`（新：`Transport` 接口 + 帧定义 + 直连实现）；Hub 侧 `api.go` 加 `/api/node`；`hello` 写 `devices` + `device_agents`（能力元数据，不含秘密）；`--role node --hub URL` |
| **M2.2** turn 派发 | `internal/task/`：`startOne` 选 adapter 时，若 task 的 `executing_device_id` 指向远端则用远端 adapter；Node 侧收 `turn.dispatch` → 解析锚点 → 起本地 adapter → `turn.event` 上行（带 turn 内局部序号，Hub 按 `(turn_id, local_seq)` 去重） |
| **M2.3** 工作区锚点 | `workspace_anchors` + `workspace_anchor_roots` 接上读写；解析不到就明确失败，**不静默换设备** |
| **M2.4** 收敛 | Node 掉线/被杀/Hub 重启 → turn 落 `failed`/`canceled`，已收到的事件保留；对照 `store.FailOrphaned` |
| **M2.5** 跨设备审批 | `approval.request` / `approval.decision` 走控制通道；绝不自动批准 |
| **M2.6** ACP | `internal/adapter/acp/`，结构照 `internal/adapter/droid/`（双向 JSON-RPC over stdio + 反向请求） |
| **M2.7** 验收 | 两个 daemon（不同 state dir）+ 一个 Hub，真跑一个 turn，真批一次权限 |
