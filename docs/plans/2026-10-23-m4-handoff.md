### Node 服务是干什么的，以及为什么值得是 launchd

Hub/Node 分工（ADR 0022）：**Hub 在 NAS 上常年开着**，拥有 session、是 `events.seq` 的唯一
分配者、也是唯一的审批权威；**Node 才是真正跑 turn 的机器**——有你的仓库、你的 CLI agent、
你的文件。Node 主动**拨出去**连 Hub 并保持一条 WebSocket，所以路由器上不用开洞。

推论：手机想把活派到这台 Mac，**派活的那一刻这台 Mac 上得有一个 node 在跑**。手动起的话，
重启或登出之后它就悄悄没了，Hub 那侧只看到设备掉线、不报错。launchd
（`dev.openkin.node`：`RunAtLoad` + 崩溃重启）解决的就是这个——把 Mac 变成
"随时能接活"，而不是"你记得手动起才有"。所以它是必要的，不是可选的装饰。

二进制为什么是**副本**而不是指向仓库：`install-node-service.sh` 的原话——worktree 会来来去去，
登录项指向一个被删掉的路径会在下次重启时**静默失败**。代价是副本会过期，
所以 `desktop-rebuild.sh` 第 `[3/5]` 步负责刷新（见上面第 3 条）。

## 4. 改这套 UI 的五个坑（都踩过，省得再踩）

1. **Tailwind 3.4 不产出真正的 `@layer` 块。** 自定义工具类一定排在核心工具类**之后**，
   同权重平局必胜。所以安全区助手必须写成 `max(1rem, env(...))`，不能指望 `px-4` 赢。
   在编译产物里可以直接看到偏移量。
2. **`overflow-x` 只要不是 `visible`，`overflow-y` 就会被算成 `auto`。** 这是分支气泡被
   44px 高的横向滚动条整条裁掉的原因（面板矩形明明在，`elementFromPoint` 却全打在后头）。
3. **`position: fixed` 逃逸祖先的 padding。** 根节点的 `.safe-pad` 够不着抽屉、sheet；
   它们得自己补 inset。而且 inset 要放在**有背景色那一层**上，否则 inset 那两条会露出 scrim。
4. **判断"有没有上一页"要用 `window.history.state.idx > 0`**，不是 `location.key`、
   也不是 `history.length`（后者会算上别的站点，冷启动能把人送出 app）。
5. **`.touch-lg` 的媒体查询上界必须停在 `md`（767.98px）。** ≥768px 是桌面布局
   （248px 侧栏 + hover 才出现的行按钮），在那里套 44pt 不是"更好点"，是换了个布局：
   实测五个被撑到 44px 的键会把项目名挤成 0px。

审计脚本（一次报：横向溢出数、小于 44pt 的控件、可见 h1、shell bar 的标题、重复标题数）。
两个坑已经修在里面：bar 自己渲染的 h1 不算"重复标题"，44pt 兜底只在触屏媒体查询里生效，
否则桌面宽度上会满屏假警报。

```js
(() => {
  const vw = innerWidth;
  const floorOn = matchMedia(
    "(max-width: 639.98px), ((pointer: coarse) and (max-width: 767.98px))",
  ).matches;
  const vis = (el) => {
    if (!el) return false;
    const b = el.getBoundingClientRect();
    const s = getComputedStyle(el);
    return b.width > 0 && b.height > 0 && s.display !== "none" && s.visibility !== "hidden";
  };
  const bar = document.querySelector("div.md\\:hidden.flex.items-center.pt-safe");
  const barOn = vis(bar);
  const barTitle = barOn ? bar.querySelector("h1, span").textContent.trim() : null;
  const h1s = [...document.querySelectorAll("h1")].filter(
    (e) => vis(e) && !(barOn && bar.contains(e)),
  );
  const small = floorOn
    ? [...document.querySelectorAll(
        ".touch-lg button, .touch-lg select, .touch-lg [role=button], .touch-lg input",
      )].filter((e) => {
        if (!vis(e)) return false;
        const b = e.getBoundingClientRect();
        return b.height < 44 || b.width < 44;
      }).map((e) => e.textContent.trim().slice(0, 10) || e.getAttribute("aria-label"))
    : [];
  const scrollsX = (el) => {
    let p = el.parentElement;
    while (p) {
      const s = getComputedStyle(p);
      if (s.overflowX === "auto" || s.overflowX === "scroll") return true;
      p = p.parentElement;
    }
    return false;
  };
  const over = [...document.querySelectorAll("body *")].filter(
    (e) => e.getBoundingClientRect().right > vw + 1 && !scrollsX(e),
  ).length;
  return JSON.stringify({
    vw, path: location.pathname, floorOn, over, small,
    h1s: h1s.map((e) => e.textContent.trim().slice(0, 14)),
    barTitle,
    dup: barTitle ? h1s.filter((h) => h.textContent.trim() === barTitle).length : 0,
  });
})()
```

**注意**：`.touch-lg` 兜底只对 `button/select/input/[role=button]` 生效，所以上面这份
`small` 检查是"兜底有没有漏"，不是"这个页面所有可点区域都够大"——`<a>`、`<div onClick>`
不在内。本轮 `/tasks` 那 86 个行内文字链就是这么漏过去的。要全量查可点区域得自己加选择器。

安全区和刘海在桌面浏览器里恒为 0，验的办法是**注入**：
`el.style.paddingTop = '34px'` 之后重测面板和首行的位置，看位移对不对、底色盖没盖住。

## 8. 如果以后要收费：开源边界怎么切

> 这一节是**讨论记录 + 建议**，不是已决定的事。记在这里是因为它会影响
> 代码怎么拆，越晚动手越疼。注意这文件本身在公开仓库里（见第 7 节）。

### 现状：这个决定其实已经做完了，而且不可撤回

- `LICENSE` 是 **Apache-2.0**（PRINCIPLE §10 自己写的 "prefer a permissive license"），
  已发布的副本永远归那个许可，改不回来。
- **Hub 和 Node 是同一个二进制**（`serve --role standalone|hub`）——Hub 的实现已经公开。
- **`relay/` 也在仓库里**，而且 README 明写它是 BYO 基础设施
  （用户用自己的 Cloudflare account 部署，"OpenKin does not operate a shared relay"）。

**推论**：今天任何人都能 fork 一份、改个名、拿去卖。Apache-2.0 只要求保留版权声明和
NOTICE，不要求衍生作品开源。要收钱，卖的不能是"这份代码"，得是别的东西。

### 唯一一条判断标准

> 护城河不在代码，在**"我替你运维的东西"**。

所以切法是「**跑在你机器上的** vs **我替你运维的**」，不是「客户端 vs 服务端」。
照抄"服务端闭源"方向对，但**位置要往后挪**——这个产品跑在用户机器上，服务只是让它更方便。

### 该闭源的四类（对应现在的代码位置）

| 闭源侧 | 现状 | 为什么它能收钱 |
|---|---|---|
| **托管中继** | `relay/` 已开源，且是用户自部署 | 用户不想配 wrangler、不想管证书、不想开端口。**但 `relay/README.md` 自己写了 "Relay v2 does not provide end-to-end encryption"，Cloudflare 能看流量——托管版要卖得动，先补 E2E**，否则是在卖一个"我看得见你流量"的服务 |
| **多租户控制面** | 不存在 | 账号、组织、计费、配额、设备编排、备份、可观测。纯 SaaS 层，与本地 agent 无关 |
| **企业管控** | 不存在 | SSO/SAML、审计、策略下发、密钥托管、合规报告。买的人是 IT 不是开发者——他们对"能不能审代码"不敏感，对"能不能强制策略"敏感。open-core 最干净的闭源侧 |
| **模型网关** | 不存在 | 若以后转售推理：路由、配额、计费、反滥用全在服务端 |

### 这四样闭了产品就死

| 必须开源 | 原因 |
|---|---|
| **Node / daemon** | 跑在用户机器上、能读仓库、能执行命令、能碰 agent 凭据。闭源＝没人敢装。**ADR 0022 D7 承诺的"密钥不出设备"只有代码可审才可信** |
| **协议规范** | Hub↔Node 线协议、事件格式。实现可以闭，**规范不能闭**，否则没人能写第三个客户端 |
| **控制台前端** | 它是发到浏览器/手机上的 JS，**物理上无法保密**，devtools 一开就全在。别把定价规则、feature flag 判定写进 UI 逻辑 |
| **CLI** | 开发者工具闭源 CLI 等于自杀 |

### 三条路

| 路线 | 做法 | 代价 | 先例 |
|---|---|---|---|
| A 全开源卖托管 | 代码全开，收"我帮你跑 Hub / 中继 / 备份" | 别人能自己托管，只能靠省事和品牌赢 | Tailscale、Supabase |
| B open-core | 核心开源，企业功能闭源单独授权 | 两套构建/许可；社区会长期吵"这功能本该免费" | GitLab、Sentry |
| C 对新版本换许可 | 新版本 AGPL-3.0 或 BSL/FSL，老版本保持 Apache | 会被骂一轮 | Grafana、HashiCorp |

**倾向 A + C**：核心永久 Apache（信任是这产品的命，比短期收入重要），**新版本考虑
AGPL-3.0 + 商业双授权**——自建/个人用不受影响，只有"拿它对外提供网络服务"才要求开源改动。
这比 open-core 干净，因为它不制造"哪个功能该免费"的永恒争论。

**比代码更实用的杠杆是商标**：Apache-2.0 明确不授予商标权，所以别人可以 fork 代码、
**但不能叫 OpenKin**。README 里 "Searchable open-source name" 就是这个意思，值得早注册。

### 如果重来，仓库切成三个

```
openkin         公开  CLI、Node、协议、控制台、桌面壳、iOS 壳
openkin-hub     公开  自建 Hub（单租户，就是现在 --role hub 那份）
openkin-cloud   私有  多租户控制面、账号计费、relay 托管版、企业功能
```

第三块从**第一天**就该在私有仓库。现在唯一提前公开的是 `relay/`，而它恰好是最不该闭的
那个（BYO 基础设施是信任卖点，不是收入来源），所以**损失比看起来小**。

### 一条工程债，越晚还越疼

**Hub 和 Node 同一个二进制**——概念上的缝 ADR 0022 已经画好了，代码上还没拆。
如果确定以后要卖托管 Hub，那个拆分会变成"协议边界 + Go 模块边界"一起动。
不需要现在拆，但**要在写下一批 Hub 代码之前决定**，否则新代码会长在错误的一侧。
