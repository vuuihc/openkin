## 0. 一句话

自部署：agent 在我自己的域名上一句话装好 Hub，只给我一条链接；我在 Mac 和 iPhone 原生壳用同一账号登录，看到同一份会话，手机能收到审批推送。
托管：同一个二进制、同一个壳；统一域名，登录后只看到自己的空间；同一个已验证邮箱默认合并。
**先做前者，能 dogfood 再扩后者。**

## 1. 两种形态

| | 托管 | 自部署 |
|---|---|---|
| 域名 | 统一单域 `https://kin.example.com`；租户由登录账号决定 | 用户自己的域名或隧道域名，安装时配置一次 |
| 登录 | Google / GitHub OAuth | 一次性登录链接；OAuth 可选 |
| 账号 | 一个账号一个个人租户 | 一个 Hub 一个 owner（可邀请 member） |
| 数据 | 每租户逻辑独立 store | 一个 SQLite |
| 计算 | 用户自己的 Mac / Node 执行 | 同左 |
| 谁运营 | 我们 | 用户 |
| 产品地位 | 可选；不用也能用 | 一等公民；核心承诺 |

**术语**

| 词 | 含义 |
|---|---|
| 租户 | 一个用户的逻辑 Hub：独立数据、独立 owner；不要求独立子域 |
| 控制面 | 账号、身份、租户目录、OAuth；以后放 Postgres |
| 数据面 | 会话、任务、审批、设备、推送；每租户独立 store |
| cell | 以后扩容的单位；本轮不实现，只保证路由 key 是租户 id |

## 2. 决定

| # | 决定 | 说明 |
|---|---|---|
| D1 | 托管与自部署的关系 | 托管可选；自部署保持同等能力，不需要 OpenKin 账号 |
| D2 | 托管用统一单域还是每用户子域 | 统一单域 `https://kin.example.com`；所有用户同一个源，租户由登录账号决定；不要求 handle、不做 per-user 子域 |
| D3 | 同邮箱是否自动合并 | **默认合并**：provider 明确 `email_verified=true` 时，邮箱先小写/去空格；没有命中就新建账号；只命中一个未删除、未禁用的账号，就把新身份绑到该账号，不新建账号。命中多个历史账号属于异常，不静默选一个，要求先登录一个再显式绑定；未验证邮箱不合并；已删除/禁用账号不自动复活，按删除/禁用流程给出具体下一步。合并后 24h 内通知所有设备，可解绑，审计一次 |
| D4 | 租户数据怎么隔离 | **先锁接口，不锁文件布局**：现在所有 store 调用带租户上下文；托管多租户开工前做 spike 对比“每租户 SQLite”与“共享 Postgres + RLS”，默认倾向每租户 SQLite |
| D5 | 一个账号几个租户 | 首发一个个人租户；团队/多工作区以后再加 |
| D6 | 桌面登录 | 本地模式不需要登录；登录只增加同步，不接管本地权限 |
| D7 | 内容存储 | Hub 存会话文本和元数据；附件走对象存储，不把大文件塞进 SQLite |
| D8 | 托管自定义域名 | 首发不做；托管统一单域，自部署天然是用户自己的域名或隧道域名 |
| D9 | 计费 | 不在本清单内，单独设计 |
| D10 | Docker 由谁装 | agent 可在用户明确同意后安装（可能需要 sudo）；安装脚本不静默 sudo，不自动装 Docker |
| D11 | 遥测 | 首发不接第三方分析；只保留服务端必要日志，不含正文/秘密 |
| D12 | 事件重放窗口 | 30 天；超出后设备必须重新同步快照，UI 明确说“需要重新同步” |
| D13 | 会话生命周期 | 滑动 30 天、绝对 180 天、单账号并发 ≤20 个设备会话（不是 WS 连接）；每台设备独立可撤销 |
| D14 | 注册方式 | 首发邀请制；公开注册以后另立清单，不在本清单 |
| D15 | 自部署 iOS | **同一个通用原生壳**：运行时输入/扫码/深链填入 Hub URL，持久化、可修改，不按部署单独构建。OAuth 和链接登录都走系统浏览器，回传一次性 code。公网必须 HTTPS；仅局域网 HTTP 若允许，必须在壳内和安装输出标明不安全 |
| D16 | iPhone 原生推送 | **APNs 纳入首发**，不做“首发可以没有推送”的例外；Web Push 保留给浏览器/PWA；两者按设备去重。代码已合入 `kin-multidevice` 的本地 main（`cf556915` + `92027ed7`），当前 `feat/hub-oauth-login` 工作树尚未包含；本轮只做同步到本轮分支、真机验收、隔离与密钥测试，不重写 |
| D17 | L3/L4 | 不列。规模、压测、多 cell、租户迁移、计费、合规、多区域、团队/RBAC 都以后再说；现在只保证 L2 的形状不挡路 |

## 3. 本轮 goal（可直接作为下一个 agent 的 goal）

> **目标**：把自部署 Hub 做到我能 dogfood。用我自己的域名，agent 一句话装好；我在 Mac 和 iPhone 原生壳用同一账号登录；消息、审批双向同步；iPhone 收到 APNs；没有默认密码，没有 `docker exec`，不需要为 iOS 单独构建。
>
> **完成条件**：G1–G20 全绿；干净机器 + 真机（蜂窝网络）走一遍；留证据。
>
> **不做**：托管多租户、邀请制、公开注册、计费、L3/L4。
>
> **已有能力算完成，只补差距；不要重写。**

交付顺序：

1. 域名/公网访问自动化 + 干净机器安装（G1–G4）。
2. 原生壳运行时 Hub URL（G8）。
3. 系统浏览器登录回传（G9）。
4. Node token 显式确认与撤销（G7）。
5. 同步、离线、审批（G10–G13）。
6. 同步 main 上已有的 APNs 代码 + 真机验收（G14–G15）。
7. 状态、导出、恢复、安全底线（G16–G19）。
8. 干净机器 + 真机总验收（G20）。

## 4. 自部署 dogfood 验收（G1–G20）

| # | 验收动作 | 通过标准 |
|---|---|---|
| G1 | 干净机器（无 Kin 数据、无容器），agent 运行 `scripts/install-hub.sh --domain hub.example.com --email owner@example.com` | 有 Docker 时 stdout 只有一条 URL（登录链接，其 origin 即 Hub URL），进度/错误走 stderr；无 Docker 时先给出安装命令并等用户同意，不静默 sudo；没有默认密码；不需要 `docker exec`；不出现 OpenKin 的域名 |
| G2 | 重复运行安装脚本；升级现有 Hub | 幂等；启动同一个 Hub；不丢数据；打印新链接，旧链接失效；member/invite、会话、Node 仍工作；旧 iOS 壳/旧 Node 得到可行动提示，不静默失败 |
| G3 | 域名与公网可达 | `--domain` 写进 `.env` 且不覆盖已有值；检查 A/AAAA（或 CNAME）；80/443 可达；证书自动签发/续期；失败时说明 DNS/端口/速率限制；公网登录不降级 HTTP；用手机蜂窝打开 `https://hub.example.com/api/health` 和首页 |
| G4 | 没有公网 IP / 没有域名 | 四条路径：自有域名+公网、隧道+自有域名、quick tunnel、仅局域网；不默认用 OpenKin 域名；隧道 token 不进日志；仅局域网明说手机在外网连不上；已有反代可让 Hub 监听内部端口，只信自己配置的反代头 |
| G5 | 打开安装输出的一次性链接完成 owner 登录 | 链接 30 分钟、一次性；复用/过期有明确提示；完成后直接进控制台；链接不出现在服务端日志、Referer；没有默认密码 |
| G6 | 第二台设备登录；撤销一台设备 | 用新链接或 OAuth 登录，看到同一份会话，能审批；设备列表可单独撤销；撤销后该设备立刻不能收新事件，其他设备不受影响；重新登录可恢复；单账号 ≤20 个设备会话，滑动 30 天/绝对 180 天 |
| G7 | Mac 桌面连接 Hub；管理 Node token | 设置里填 Hub URL，或 `kin supervise --hub https://hub.example.com`；Node 主动连出；签发 Node token 需要本机显式确认（显示 Node 名称/指纹，浏览器不能代确认）；可列出/命名/撤销；撤销后 WS 立即断开；token 不能跨 Hub 使用 |
| G8 | iPhone 原生壳连接自部署 Hub | 一个通用壳：首次打开输入/扫码/深链填入 Hub URL；持久化；设置里可改；不需要为每个部署重新构建；托管和自部署用同一个壳；公网必须 HTTPS，公网 HTTP 被拒；仅局域网 HTTP 若在壳内允许，必须显式标明不安全；URL 不可达、证书错误都有具体提示 |
| G9 | iPhone 登录回传 | OAuth 和一次性链接登录都在系统浏览器/ASWebAuthenticationSession 完成，不在 WKWebView 内；回调把一次性、≤5 分钟、设备绑定、PKCE 的 code 交给 app；app 用 code 换一次性登录链接，在自己的 webview 打开并获得第一方 cookie；OAuth 授权码/cookie 不进入 app；旧壳被识别并提示升级或改用 Safari |
| G10 | 手机发一条消息，Mac 看；反向同样 | Mac 在线时 1 秒内出现；不重复、不乱序；两台设备打开同一会话内容一致；会话列表顺序一致 |
| G11 | Node 离线/睡眠 | 手机显示“Mac 离线/睡眠”和最后在线时间；消息排队；Node 醒来后按顺序同步；不假装已执行；排队有上限，超限显示未发送/重试，不无限增长 |
| G12 | 手机批准/拒绝一个待批动作 | 桌面立即消失；审计只记一次；批准人显示正确；重复点击/过期审批幂等且提示明确 |
| G13 | 断线重连、离线写入 | 从 cursor 续，不丢不重；超过 D12 的 30 天窗口时明确要求重新同步；离线写入本地立即显示、标记未发送、重连按到达顺序发送 |
| G14 | iPhone APNs + Web Push | `kin notify apns --key-file …` 配置 Node 的 Apple 推送身份；iPhone 注册 APNs token；`kin notify test` 能在锁屏收到；点开进入正确会话；前台/后台/静音/勿扰有定义；无权限/无效 token 有具体原因和开启指引；只发给该账号的设备，撤销设备后停止；Web Push 对浏览器/PWA 仍工作，同一事件不重复打扰 |
| G15 | APNs 密钥与设备 token | APNs 私钥只存服务端/Node 安全存储或 0600；不出现在 API 响应、日志、导出、明文备份；`push_apns_configured` 只返回布尔/原因，不返回 token/key；可轮换，轮换后旧 key 失效；泄露有处置步骤 |
| G16 | 空、错、离线、加载 | 四态都有具体文案和下一步；键盘可操作、焦点可见、语义控件；不出现假成功；重试不重复执行动作；新增用户可见文案中英同步；测试断言具体文案/角色 |
| G17 | 导出自部署数据；备份/恢复 | 导出包可解压、会话按原顺序、不含秘密、可重复生成、有完成提示；备份文件加密或 0600；恢复演练一次，恢复后登录/会话/审批可用；不打印秘密 |
| G18 | 安全底线 | 公网/隧道：会话 cookie HttpOnly+Secure+SameSite，HSTS、CSP、frame-ancestors `none`、nosniff、Referrer-Policy；自签 TLS：同样 Secure cookie，提示安装/信任证书，不强制 HSTS；仅局域网 HTTP：显式非 Secure，并在安装输出和文档标明“同网段可被窃听”；状态变更校验 Origin/Sec-Fetch-Site；默认同源、无宽 CORS；登录限流 10 次/10 分钟/IP；隧道/反代下按可信头还原真实客户端 IP，不能还原时改按账号限流；日志、URL、Referer 无 token/secret/正文 |
| G19 | 自部署可选 OAuth + 同邮箱合并 | 配置 Google/GitHub 后可用，回调 `https://<user-domain>/api/auth/oidc/callback`，scope 最小；OAuth 和链接登录都走系统浏览器 + 一次性 code 回传；同一个已验证邮箱默认合并到同一账号，不新建重复成员；未验证邮箱不合并；命中多个历史账号时要求显式绑定；合并后 24h 内通知设备、可解绑、审计一次；关闭 OAuth 不影响链接登录 |
| G20 | 干净机器 + 真机总验收 | 一台干净机器 + 一台 Mac + 一台 iPhone（蜂窝网络，不用内网）完整走一遍；G1–G19 全绿；留安装日志、截图、测试名；不用内部账号/内部域名；没有 `docker exec`、没有默认密码 |

## 5. 托管 L2（下一个 goal，本轮不验收）

| # | 验收动作 | 通过标准 |
|---|---|---|
| H1 | 打开 `https://kin.example.com`，选 Google 或 GitHub | 不需要密码；30 秒内进入自己的空间；退出再登录正常；OAuth 拒绝/取消/回调失败可读、可重试、不丢 return path |
| H2 | 先用 Google 注册，再用 GitHub 登录，两个 provider 返回同一个已验证邮箱 | **默认合并**：进入同一空间；不创建第二个账号；设备列表还是同一份 |
| H3 | 自动合并发生；以及异常冲突 | 24h 内通知所有已登录设备，离线设备下次打开可见；可解绑（解绑前保证还有至少一个可用登录方式）；审计一次。未验证邮箱不合并；同一邮箱命中多个历史账号时不静默选一个，要求先登录一个再显式绑定，并说明影响哪些设备 |
| H4 | 访问统一域名 | 所有用户同一个源；租户由登录账号决定，不从 Host 推断；URL 不携带租户标识；未登录进登录页，已登录进自己的空间；不出现“选择租户” |
| H5 | 邀请制注册 | 运营者生成一次性邀请，可指定邮箱、过期/撤销；接受后进入自己的租户；邀请邮箱已有账号时登录后进入该账号，不创建重复账号；重复接受幂等；未登录先登录；不能接受别人的邀请进错租户；邀请码不进服务端日志 |
| H6 | Mac 和 iPhone 用同一账号登录托管版 | 同一个通用壳；看到同一份会话；打开同一会话内容一致；移动 OAuth 走系统浏览器 + 一次性 code 回传（同 G9） |
| H7 | 账号页查看/撤销登录设备 | 每台设备一行；可单独撤销；撤销后立刻失效；单账号 ≤20 个设备会话；滑动 30 天/绝对 180 天；重新登录可恢复 |
| H8 | 删除账号、导出数据 | 删除说明影响范围、二次确认；24h 内线上不可见；30 天内备份清除；抽样恢复后无该租户数据；导出 24h 内生成、7 天内可下载、不含秘密；有删除/导出记录 |
| H9 | 分享一个会话/产物 | 分享是登录后授权访问，不是公开链接；未授权 404；不做公开产物链接；分享 id ≥128 位随机 |
| H10 | 用不存在的邮箱、错误邀请码/过期链接、重复请求试探 | 不泄露账号是否存在；登录 10 次/10 分钟/IP、注册 5 次/小时/IP、分享查询 60 次/分钟/IP；429 有 Retry-After；反代/隧道下按真实客户端 IP 限流 |
| H11 | 最小配额 | 每租户默认 5 GB 附件、10 万条会话、20 个并发 WS（与设备会话分开计数）；超限返回具体上限和下一步 |
| H12 | 运营者威胁模型 | 控制面/运营者不能伪造或注入任务、审批事件绕过 Node 本地策略；权限模式变更只能由本地设置；管理操作全审计；用户可查谁访问过自己的数据 |
| H13 | 托管推送 | APNs 和 Web Push 只发给该账号的设备；点开进入正确会话；无权限/关闭状态有具体文案和开启指引；跨租户不投递；设备撤销后停止 |
| H14 | 托管最小运维 | 部署/回滚一条命令、重复部署幂等；健康/就绪检查；证书 30 天到期告警；登录失败率 >5% 持续 5 分钟告警；WS 掉线 >1% 告警；日志带 tenant id，不含 token/secret/正文 |
| H15 | 第一个真实外部用户 | 受邀用户用自己的手机和 Mac 走完 H1–H14；不用内部账号；备份/恢复/删除至少演练一次；最小配额和会话生命周期已生效 |

## 6. 技术底线（两版共用）

> 本轮 goal 必须过 T5–T20；不启用 OAuth 时 T5/T17 记 N/A，一旦启用必须过。T1–T4 的完整隔离矩阵在托管 L2 goal 过，但 T1/T2 的接口形状本轮就要落。

| # | 验收 | 通过标准 |
|---|---|---|
| T1 | 租户解析 | 从已认证会话/账号解析出唯一租户；不从 Host 推断；没有默认租户兜底 |
| T2 | 存储入口 | 所有 store 调用带租户上下文；handler 里没有全局 store；CI lint/测试能在出现全局调用时失败 |
| T3 | 隔离矩阵 | 任务、会话、审批、产物、设备、推送、上传、设置、搜索、WS、SSE、变更流、对象存储逐项有跨租户负向测试 |
| T4 | id 不是授权 | A 的 token + B 的 id 一律 404；不泄露存在性 |
| T5 | OAuth 校验 | state/nonce/PKCE/return path/发起端绑定服务端一次性事务；事务在多副本/重启后仍在，不依赖第三方 cookie；租户在回调后解析；重放被拒 |
| T6 | 移动端回传 | 一次性 code ≤5 分钟、一次性、设备绑定、PKCE；换取的一次性登录链接只能消费一次；OAuth 授权码/cookie 不进入 app；有红测试 |
| T7 | Cookie / 会话 | 公网/隧道/自签 TLS：HttpOnly、Secure、SameSite；仅局域网 HTTP：显式非 Secure 并标明风险；登录后轮换 session id；不把会话 token 写 localStorage；每台设备独立会话，单账号 ≤20 个设备会话，滑动 30 天/绝对 180 天 |
| T8 | Node token | 绑定租户；签发要一次显式设备确认（桌面本地显示 Node 名称/指纹，浏览器不能代确认）；可枚举、可撤销；撤销后 WS 立即断开；跨租户/跨 Hub 连接被拒 |
| T9 | WebSocket / 重放 | 按租户 id 路由（cell 以后再加）；校验 Origin；不跨租户广播；重连从 cursor 续；超过 30 天窗口时要求重新同步 |
| T10 | 文件路径 | 每租户独立根（自部署为 store 根）；`..`、symlink、大小写变体不能逃出根 |
| T11 | 秘密存储与轮换 | OAuth client secret、APNs 私钥、VAPID private key、会话签名/加密密钥、隧道 token 只存服务端/Node 安全存储或 0600；不进日志、导出、明文备份；可轮换；有泄露处置 |
| T12 | 安全响应头与 CSRF | 公网/隧道：HSTS、CSP、frame-ancestors `none`、nosniff、Referrer-Policy；状态变更请求校验 Origin/Sec-Fetch-Site；默认同源，无宽 CORS；仅局域网至少 CSP + Origin；有负向测试 |
| T13 | 日志与审计 | 带 tenant id；不含 token/secret/正文；可按租户审计；管理员访问租户数据有记录 |
| T14 | 限流与真实 IP | 登录 10 次/10 分钟/IP；只信自己配置的反代/隧道头；不能还原真实 IP 时改按账号限流并在文档说明，不得把所有用户算作一个 IP 桶；429 有 Retry-After |
| T15 | 备份与恢复 | 单租户/自部署备份、恢复、删除不影响其他租户；备份静态加密，密钥不与备份同存；抽样恢复验证；有演练记录 |
| T16 | 推送隔离 | APNs/Web Push 设备 token 绑定账号+租户+设备；API 不返回 token；撤销设备后停止；不跨账号/跨租户投递 |
| T17 | OAuth scope | OIDC：`openid email profile`；GitHub：`read:user user:email` 或等价最小集；生成字符串有回归测试 |
| T18 | 错误文案契约 | 每条错误说清“类别 + 下一步 + 是否可重试”；测试断言具体文案/角色，不接受“可读”这种形容词 |
| T19 | 迁移 | 有序迁移；空库和已有数据都测；旧 Node/旧客户端能降级或有明确提示；失败可隔离 |
| T20 | 部署 | 部署/回滚幂等；健康/就绪检查；证书到期告警；重复部署不破坏数据 |

## 7. L2 形状（现在不实现，但不能挡路）

1. 租户从**已认证会话/账号**解析，不从 Host、URL path 或子域推断；没有“默认租户”兜底。
2. 所有 store 调用带 tenant context；handler 不直接拿全局 store；出现全局调用 CI 失败。
3. 租户 id 不可变；显示名可改；URL 不依赖租户名/id。
4. 控制面（账号、身份、租户目录、OAuth）与数据面（会话、任务、审批、设备、推送）分开；数据面按租户隔离。
5. 每租户逻辑独立 store；文件布局先锁接口，托管多租户开工前做 spike 再定“每租户 SQLite”还是“共享 Postgres + RLS”。
6. WS/SSE/事件流按 tenant id 路由；cursor/重放按租户；cell 以后再加。
7. 托管和自部署共用一个二进制、一套线协议；不为托管分叉。
8. 托管一个 OAuth 应用/回调；不按用户建应用；租户不靠子域。

这些形状由 T1–T4 的红测试保证；本轮只落接口和负向测试骨架，不要求完整隔离矩阵。

## 8. 怎么验收

- **自动化**：单元 + 集成 + 跨租户矩阵；每个安全判据都要有红验证（`scripts/mutants.py`），不能只靠“读代码觉得对”。
- **浏览器**：Playwright 走真实流程，桌面和 390 宽都看；单测全绿不算界面通过。
- **真机**：Mac + iPhone 原生壳；手机用蜂窝网络，不用内网；干净账号；留截图和步骤。移动 OAuth 必须在系统浏览器里走一遍，并验证回传后的 webview 会话。
- **i18n**：新增用户可见文案中英同步；错误、空、离线状态都有测试。
- **外部集成**：打开设置不读取 secret、不调第三方；OAuth scope 有回归测试。
- **证据**：每条验收写清测试名、日志或截图；口头“试过了”不算。
- **完成定义**：代码 + 测试 + i18n + 文档 + 已部署；不提交已知失败。

- L4：计费、发票、合规认证、多区域、数据驻留、托管自定义域名、团队/RBAC、SAML/SCIM。
