## 3. 风险

| 项 | 说明 |
|---|---|
| 组件测试的假绿 | 渲染测试最容易写成「断言组件渲染了它自己写的东西」。三条都断言**与输入有关的行为**（busy 与 disabled、回调参数、标签随状态变），不是快照 |
| jsdom 拖慢测试 | 用逐文件环境声明，不换全局环境；量一次 `npm test` 的耗时并记下来 |
| 删死代码删错 | 判据是「零 importer」，且删除前对每个文件再 grep 一遍全仓（含动态 import、`.md`）。`monacoSetup.ts` 就是这样被抓回来的：它是 `import "./monacoSetup";` 这种裸副作用导入，第一版扫描没认出来 |
| 预算脚本误报 | 阈值 1 MiB 是上游目标；脚本量 gzip 后的入口 chunk。若哪天入口真的变大，应当**先看它变大的原因**再决定是调阈值还是拆包 |

### P6b — 首屏预算钉住（`scripts/check-bundle-budget.sh` + CI 一步）

量的是 `web/dist/index.html` **自己点名**的文件：入口 module script 与样式表。
动态 chunk 不计入（`CodeViewer` 光它自己就 865 kB gzip，算进去这个数就没有意义）；

### P6d — 桌面壳接入 CI

`ci.yml` 末尾新增独立的 `desktop` job（不是一个 step）：它不需要 Go、不需要 UI 构建，
独立跑就能和 `build` 并行。三步 —— `npm ci --ignore-scripts`（`postinstall` 会去下

（esbuild 打 `main.ts` / `preload.ts`，`external: ["electron"]`，不需要 Electron 运行时）。

本地把这三条按 CI 的写法跑过一遍（`npm ci` exit 0，typecheck 无输出，build 出
`dist/main.js` + `dist/preload.js`）；`desktop/.gitignore` 已经忽略 `node_modules/` 与
`dist/`，所以这个 job 的产物不会弄脏工作树。
