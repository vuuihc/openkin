## 1. 切片

### P6a — 组件测试台（验收就是这一条）

- 依赖：`jsdom`、`@testing-library/react`、`@testing-library/dom`、`@testing-library/user-event`（都是 devDependencies）。
- 环境：**不把全局环境改成 jsdom**。现有 832 条测试是纯逻辑，跑在 node 环境里 3 秒结束；
  把它们全部搬进 jsdom 只是让每次提交慢几倍。组件测试用文件头 `// @vitest-environment jsdom`
  逐文件声明，另加一个 `src/test/setup.ts`（只做 `afterEach(cleanup)` 与 `matchMedia` 之类的桩）。
- 测哪三条关键路径（挑的都是「坏了只有人眼能发现」的那种）：
  1. `Sidebar` 的导入菜单：导入中两类菜单项都 `disabled`（不是点了没反应）；点 provider 那一行，
     回调收到的是**那个 provider 的 id**。
  2. `useAgentSessionImport`（`renderHook`）：两个实例共享同一个 busy；
     `importsInFlight()` 在导入开始后**同步**为真、结束后为假 —— 自动同步那一跳读的就是它。
  3. `LocalAgentSettingsSection`：`importingSessions` 为真时主按钮是「Importing…」且禁用；
     per-provider 行渲染出「Import」并回调 provider id。
- **红验证**：逐个把组件改坏（删 `disabled`、把 busy 判断反过来、把回调参数换成常量），
  确认**为对的原因**变红，再逐字节还原。这一条就是验收原话。

### P6b — 首屏预算钉住

- 目标已达标（321 kB gzip），所以这一片的产出不是「优化」，是**防止它悄悄退化**：
  `scripts/check-bundle-budget.sh` —— gzip 量入口 chunk，超过 1 MiB 就非零退出；
  接进 `.github/workflows/ci.yml` 的 UI 那一步（在 `npx vite build` 之后）。
- 脚本读构建产物而不是源码，所以它量的是真东西；阈值写成脚本里的常量并注明出处（上游 §6）。

### P6c — 删死代码

- 判据是「**没有任何文件 import 它**」，用一遍静态扫描得出（脚本 + 人工逐条复看），
  而不是「看起来没人用」。当前命中 3 个文件：
  `ui/src/components/StatusBadge.tsx`（23）、`ui/src/components/Truncated.tsx`（45）、
  `ui/src/components/cards/CompletedTaskCard.tsx`（79）。
- 同一遍扫描里，**活文件里的死导出**（`Skeleton.tsx` 的 `SkeletonCard` / `PageHeaderSkeleton`、
  `icons.tsx` 的 `IconMore` / `IconUsage`）一并处理：确认文件内也没人用再删。
- 删完检查连带：被删文件用到的 i18n key、图标若因此没人用，一起删；`tsc` / `eslint` / 测试全绿。
- **不删**的东西也要写下来：`client.ts` 那一批「无人引用」的导出**是响应类型**，
  它们是契约的一部分（对照 openapi 生成物），不是死代码。

### P6d — 桌面壳接入 CI

- `ci.yml` 新增 `desktop` job：`npm ci --ignore-scripts`（`postinstall` 会去下 Electron 二进制，
  CI 里不需要；`--ignore-scripts` 仍会装到 electron 这个包本身，`tsc` 要的 d.ts 来自它）、
  `npm run typecheck`、`npm run build`（esbuild 打包，不需要 Electron 运行时）。
- 目的只是「这 2,784 行至少有编译门」，不是补测试 —— 补测试是另一个片。

### P6e — 中英文档对齐

- `PRINCIPLE.zh.md` §14：补上英文版有的那两段「拿不定主意就先去看一个能跑的实现在怎么做」
  （Lody 作为 tie-breaker，以及它不是 spec 的边界）。
- `SYSTEM_DESIGN.md` / `SYSTEM_DESIGN.zh.md` 关于账户那一段：**两份都改**。
  今天的事实是：隔离已实现（`store.ScopeForPrincipal`），注册也已实现

  还没实现的是「member 能在控制台上自主发现合法 cwd / 项目根」那类可用性补齐（P5 §6 记的账）。
  顺手修掉指向不存在文件的那条链接（`2026-10-23-hosted-mode.md` → `2026-10-26-p5-hosted.md`）。

## 3. 风险

| 项 | 说明 |
|---|---|
| 组件测试的假绿 | 渲染测试最容易写成「断言组件渲染了它自己写的东西」。三条都断言**与输入有关的行为**（busy 与 disabled、回调参数、标签随状态变），不是快照 |
| jsdom 拖慢测试 | 用逐文件环境声明，不换全局环境；量一次 `npm test` 的耗时并记下来 |
| 删死代码删错 | 判据是「零 importer」，且删除前对每个文件再 grep 一遍全仓（含动态 import、`.md`）。`monacoSetup.ts` 就是这样被抓回来的：它是 `import "./monacoSetup";` 这种裸副作用导入，第一版扫描没认出来 |
| 预算脚本误报 | 阈值 1 MiB 是上游目标；脚本量 gzip 后的入口 chunk。若哪天入口真的变大，应当**先看它变大的原因**再决定是调阈值还是拆包 |
