一份列表，两种壳

手机和 Mac 现在各有一套对话列表。这一轮收成一套数据、一套行、一套操作， 宽度只决定壳（侧栏 / 整页），不再决定功能。待批准从收件箱回到对话行，项目收进列表， 导入会话默认收起。

先看结论

五个决定。前四个定交互，第五个是已签决定的执行边界。每张卡给出建议和代价；不同意就改一行字。

D1 · 项目进列表，不留第二份列表

R0a 已签合并

建议：列表只有一份，层级固定为 设备 → 项目 → 对话。项目是列表里的分组头，不是导航目的地；点项目头进 /projects/:id，项目详情页保留。删 /projects 索引页，手机 dock 去掉「项目」。

理由：IA 已经把唯一列表定为这三级；`/projects` 是第二份项目列表，页头自己都写着「和侧栏按目录分组的『项目』是同一件事」。再留一个入口，就是把已经合并的东西又拆回去。

代价：项目头占纵向空间；折叠状态要按设备记住。项目为空时仍显示头（带 0），否则用户会以为项目丢了。

D2 · 待批准放在行尾，不放进收件箱

待签

建议：对话行尾放一个带数字的待批准标记（铃铛 / 计数），整行仍是唯一点击目标：点行进入对话，批准面板已经展开。系统通知点开也落这一行。删 /inbox，不再有独立图标按钮。

理由：待批准属于那条对话，不属于一个跨对话的收件箱。行尾是视线扫过标题和时间后的落点，不会把行首的未读 / 状态挤掉；把标记本身做成按钮会产生「点图标去哪、点行去哪」的第二个问题。

代价：列表很长时会有多个标记；只显示 >0，超过 9 显示 9+，不聚合到顶部。通知落到对话而不是行内滚动位置，因为批准面板本来就是该对话的顶层。

D3 · 一套行组件，壳只决定容器

待签

建议：手机整页与 Mac 左栏共用同一个 SessionRow 和同一套列表控制器（数据、搜索、过滤、行操作）。宽度只决定：容器是整页还是 300px 侧栏、溢出菜单是行内按钮还是长按 / 滑动加速。功能清单必须一致。

理由：现在两套实现各有自己的行类型、分组和操作集合，同一个对话在两个端能做的事不一样；合并实现比「对齐两份功能」更便宜，也更难再次分叉。

代价：侧栏更窄，标题截断更早；溢出菜单必须键盘可达，不能只剩滑动。手机保留单行行高，不因为共用组件退回两行卡片。

D4 · 导入会话：每台设备末尾收起

待签

建议：导入会话按设备收进列表末尾的「导入的会话 (N)」分组，默认折叠；展开后与原生会话同样的行、同样的详情头，没有彩色 rail、没有可用性徽标。新导入的会话不自动展开，只更新计数。

理由：R0a 签的是「默认收起、同样式、不特殊标记」。行本身没有展开态，所以「收起」只能落在分组上；放在设备末尾保留了设备归属，也不需要给导入会话硬造项目。

代价：可发现性下降，用计数补偿；跨设备找一条导入会话要先选设备。详情页保留来源信息，但放在「更多」里，不占头部。

D5 · 任务页删切换与 PR，保留会话保活

R0a 已签

执行边界：删顶部 SessionTabs、手机 SessionSwitcherSheet 和 header 按钮；删 PullRequestPanel 及入口；保留 TaskSessionHost 的会话保活与返回位置。

理由：列表切换已经覆盖顶部切换；「创建 PR」没有功能，留着只会让人以为坏了。

代价：在同一项目里连续切换会话要多回一次列表；这是列表合并后本来就该承担的，不再用第二套切换器补偿。

通知点开直接进入那条对话，批准面板在顶部；不做「通知 → 收件箱 → 对话」的第二跳。

六拍：被叫回来

  • 起点用户离开控制台；某条对话出现待批准。
  • 动作点系统通知，或回到列表点那条对话。
  • 立刻看到对话已打开，批准面板在顶部，焦点在第一个操作；行尾计数在返回列表时消失。
  • 慢 / 空 / 失败 / 断线没有待批准 → 不出现标记；设备断线 → 行仍可打开缓存内容，顶部显示重连，批准按钮禁用并说明原因。
  • 键盘与焦点行是一个 tab 停靠点；标记有可访问名称「2 个待批准」；通知打开后焦点直接进批准面板，Esc 回到对话。
  • 离开再回来返回列表落在同一滚动位置；计数已更新；不回到收件箱，因为收件箱已不存在。

六拍：找一条导入会话

  • 起点用户记得导入过一条外部 agent 会话，但不记得在哪台设备。
  • 动作在列表末尾展开那台设备的「导入的会话」，或直接搜索标题。
  • 立刻看到行与原生会话同高、同排版；打开后详情头也是同一套标题 / 状态 / 溢出。
  • 慢 / 空 / 失败 / 断线没有导入 → 不显示该分组；导入进行中 → 计数 +1 的进度行，失败 → 该行显示重试，不阻塞列表。
  • 键盘与焦点分组头是 disclosure 按钮，Enter / Space 展开；展开后焦点留在分组头，Tab 进入第一行。
  • 离开再回来分组展开状态按设备记住；返回列表时仍在原滚动位置。

其它四条流程

与上面三条同一套六拍；这里只写和合并直接相关的差异。

新建之后回到列表

  • 起点用户从手机 dock 的 FAB 或 Mac 的 ＋ 新建。
  • 动作发出第一条消息。
  • 立刻看到对话页；返回列表时新行已在对应设备和项目下，排在最前。
  • 慢 / 空 / 失败 / 断线设备离线 → 行显示排队状态；发送失败 → 行保留并标记，不消失。
  • 键盘与焦点新建后焦点在输入框；返回列表焦点落到新行。
  • 离开再回来列表滚动位置不变；新行不改变已选筛选。

搜索与筛选

  • 起点用户在列表顶部搜索。
  • 动作输入标题、项目或设备名；筛选运行中 / 待批准 / 已归档。
  • 立刻看到两端同一套结果；项目头保留，匹配的行高亮。
  • 慢 / 空 / 失败 / 断线无结果 → 空状态带清除；远端设备离线 → 该设备结果标灰并说明。
  • 键盘与焦点⌘K / 搜索键进入；↑↓ 走结果；Enter 打开；Esc 清除。
  • 离开再回来返回时搜索词与筛选保留，直到用户清除。

行操作

  • 起点用户在行尾的 ⋯（手机也可长按 / 滑动）。
  • 动作置顶 / 归档 / 删除；两端同一组动作。
  • 立刻看到行就地更新；归档后从当前 scope 消失，可在已归档找回。
  • 慢 / 空 / 失败 / 断线失败 → 行回滚并提示；远端离线 → 动作禁用并说明。
  • 键盘与焦点⋯ 可 Tab 到；菜单 Esc 关闭后焦点回行。
  • 离开再回来操作结果持久；不要求刷新。

项目详情的返回

  • 起点用户点项目头进入 `/projects/:id`。
  • 动作看进展后返回。
  • 立刻看到回到列表同一设备、同一滚动位置，项目仍展开。
  • 慢 / 空 / 失败 / 断线项目页加载失败 → 返回仍可用；冷启动直接打开项目页 → 返回落到列表（Mac 为左栏，手机为 `/sessions`）。
  • 键盘与焦点项目头是链接；返回后焦点回到项目头。
  • 离开再回来折叠状态和滚动位置按设备记住。

这一轮不做什么

把范围钉住，避免一次 diff 又变成整站重写。

不做视觉定稿。只用现有 token 和行排版；新的项目进展图、打卡图属于 `/projects/:id` 的补故事。

不动设置。远程 / 通知的删除是 R0b-3，单独一轮。

不写四条故事的产品代码。`/new`、`/projects/:id`、`/agents`、`/routines` 只写合同和签字页。

不迁 Astryx。R0 只收面和控件；设计系统迁移在 G0.5 之后。

不碰后端契约。待批准计数用现有 approvals 数据；如果缺字段，先加只读查询，不改表。
